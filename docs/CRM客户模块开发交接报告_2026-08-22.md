## 2. 已确认的业务规则

### 2.1 客户与供应商

- 客户就是客户，供应商就是供应商，两者不合并为统一往来单位。
- 当前只开发客户 CRM，不开发订单模块。
- 当前订单、销售、信用和客诉类展示数据由人工维护的临时业务快照提供。
- 临时业务快照必须明确标注 `source_type=MANUAL`、`as_of_at` 和录入人，不能伪装成订单或财务系统实时数据。
- 将来订单模块完成后，可写入新的 ERP 来源快照或替换前端数据源，不需要污染客户主表。

### 2.2 客户阶段与活跃度

客户阶段只表示成交进程：

| Code | 中文 |
| --- | --- |
| LEAD | 线索 |
| VERIFIED | 已验证 |
| OPPORTUNITY | 机会客户 |
| CUSTOMER | 成交客户 |
| LOST | 流失客户 |

客户活跃度独立保存历史：

| Code | 中文 |
| --- | --- |
| INSUFFICIENT_DATA | 数据不足 |
| ACTIVE | 活跃 |
| FOLLOW_UP | 需跟进 |
| HIGH_RISK | 高风险 |
| DORMANT | 沉默 |

旧阶段迁移规则：

| 旧值 | 新阶段 | 初始活跃度 |
| --- | --- | --- |
| PROSPECT | LEAD | INSUFFICIENT_DATA |
| ACTIVE | CUSTOMER | ACTIVE |
| DORMANT | CUSTOMER | DORMANT |
| CLOSED | LOST | DORMANT |

迁移执行前真实数据库客户数为 0，因此本环境没有实际客户记录被转换。

### 2.3 等级、类型、来源和标签

- 客户等级使用可配置字典 A/B/C/D，等级变更保留有效期历史。
- 客户类型使用可配置字典，支持多选和历史记录。
- 客户来源保留首次来源、当前来源及完整来源历史。
- `source_system + external_id` 继续表示外部系统集成来源，不能当作业务获客来源使用。
- 标签为独立实体，客户与标签关联保留历史。
- 已初始化 4 个常用标签：重点客户、欧洲市场、户外用品、年度框架。

## 4. 前端可直接使用的 API

所有路径均以 `/api/v1/` 开头。

### 4.1 客户列表

`GET /customers/`

支持参数：

- `q`
- `lifecycle_stage`
- `country_code`
- `owner_id`
- `organization_id`
- `attention_level`
- `customer_grade`
- `customer_source`
- `customer_type`
- `customer_tag`
- `activity_status`
- `updated_from`
- `updated_to`
- `archived=false|true|all`
- `ordering`
- 分页参数沿用项目公共分页契约。

列表返回新增字段：

- `customer_grade`
- `first_source`
- `latest_source`
- `customer_types[]`
- `customer_tags[]`
- `activity`
- `primary_owner`
- `attention_level`

查询已统一预取当前上下文，不会为每一行单独查询负责人、等级、来源、类型、标签、活跃度和业务快照。

### 4.2 页面选项

`GET /customers/options/`

可选参数：`q`，用于筛选负责人，最多返回 50 名员工。

返回：

- `lifecycle_stages`
- `activity_statuses`
- `customer_grades`
- `customer_types`
- `customer_sources`
- `customer_tags`
- `owner_options`

前端不得自行硬编码这些字典和员工列表。

### 4.3 实时查重

`GET /customers/duplicate-check/`

参数：

- `name`：客户名称，名称和网站至少提交一项。
- `website`：允许完整 URL 或裸域名。
- `country_code`：两位大写国家代码。
- `exclude_customer_id`：编辑页面必须传，用于排除当前客户。

主要返回：

```json
{
  "data": {
    "has_high_risk_match": true,
    "recommended_action": "REVIEW_BEFORE_CREATE",
    "matches": [
      {
        "customer_id": "UUID",
        "account_code": "CUS-000001",
        "account_name": "示例客户",
        "match_score": 100,
        "match_level": "HIGH",
        "matched_fields": ["NAME", "WEBSITE", "COUNTRY"]
      }
    ]
  }
}
```

查重严格应用客户行级权限，不会返回当前用户无权查看的客户。

### 4.4 快捷新建客户

`POST /customers/`

最小请求：

```json
{
  "account_name": "Example Outdoor GmbH",
  "primary_country_code": "DE",
  "customer_source_item_id": "UUID"
}
```

完整可写字段：

```json
{
  "account_name": "Example Outdoor GmbH",
  "english_name": "Example Outdoor GmbH",
  "short_name": "Example Outdoor",
  "lifecycle_stage": "LEAD",
  "primary_country_code": "DE",
  "primary_website_url": "example.invalid",
  "customer_source_item_id": "UUID",
  "customer_grade_item_id": "UUID",
  "customer_type_item_ids": ["UUID"],
  "customer_tag_ids": ["UUID"],
  "primary_owner_employee_id": "UUID",
  "contact_name": "采购联系人",
  "contact_method_type": "EMAIL",
  "contact_method_value": "buyer@example.invalid",
  "source_system": "",
  "external_id": "",
  "notes": ""
}
```

规则：

- `account_name`、`primary_country_code`、`customer_source_item_id` 必填。
- `primary_owner_employee_id` 不传时默认当前登录员工。
- 指定其他负责人需要 `customers.transfer_customer` 权限。
- 网站允许提交裸域名，服务端自动补 `https://`。
- 联系方式类型和值必须同时填写；填写联系方式时必须填写联系人姓名。
- 创建成功后自动创建负责人、首次来源和 `INSUFFICIENT_DATA` 活跃度记录。
- `account_code` 由服务端生成。

### 4.5 编辑基本资料

`PATCH /customers/{id}/`

可修改：

- `account_name`
- `english_name`
- `short_name`
- `lifecycle_stage`
- `primary_country_code`
- `primary_website_url`
- `source_system`
- `external_id`
- `notes`

必须先读取详情响应中的 `ETag`，修改时提交 `If-Match`。缺少时返回 428，版本过期返回 412。

等级、业务来源、活跃度、类型和标签不得通过基础 PATCH 覆盖，必须使用独立历史接口。

### 4.6 详情及客户画像历史

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/customers/{id}/` | 客户详情，包含当前画像和当前业务快照 |
| GET | `/customers/{id}/summary/` | 客户 360 首屏摘要 |
| GET | `/customers/{id}/timeline/` | 客户时间线 |
| GET | `/customers/{id}/grade-history/` | 等级历史 |
| POST | `/customers/{id}/set-grade/` | 调整等级，必须填写原因 |
| GET | `/customers/{id}/source-history/` | 来源历史，正序第一条即首次来源 |
| POST | `/customers/{id}/set-source/` | 调整当前来源 |
| GET | `/customers/{id}/activity-history/` | 活跃度历史 |
| POST | `/customers/{id}/set-activity/` | 人工调整活跃度，必须填写原因 |
| POST | `/customers/{id}/set-classification/` | 整体替换当前类型或标签，必须填写原因 |
| GET | `/customers/{id}/business-snapshot-history/` | 业务快照历史 |
| POST | `/customers/{id}/set-business-snapshot/` | 创建新的当前人工快照 |

等级请求：

```json
{
  "grade_item_id": "UUID",
  "reason": "年度重点客户"
}
```

活跃度请求：

```json
{
  "activity_status": "FOLLOW_UP",
  "reason": "超过约定跟进时间"
}
```

类型和标签请求：

```json
{
  "customer_type_item_ids": ["UUID"],
  "customer_tag_ids": ["UUID"],
  "reason": "客户资料复核"
}
```

传入空数组表示结束该分类下所有当前关联；未提交某个数组表示保持该分类不变。

人工业务快照请求：

```json
{
  "as_of_at": "2026-08-22T08:00:00+08:00",
  "currency_code": "USD",
  "customer_total_value": "150000.00",
  "last_12m_order_amount": "120000.00",
  "last_12m_order_count": 8,
  "quote_conversion_rate": "35.50",
  "credit_limit": "50000.00",
  "credit_used": "12000.00",
  "open_complaint_count": 1,
  "source_reference": "业务员月度复核",
  "notes": "人工维护，待订单模块接入后替换"
}
```

必须至少填写一个业务指标。截止时间不能晚于当前时间，金额不能为负，转化率范围为 0 到 100。
