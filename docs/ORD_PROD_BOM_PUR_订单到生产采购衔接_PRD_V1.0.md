# haiqu ERP 订单到生产采购衔接 PRD V1.0

> 状态：业务规则已逐项确认，核心开发与自动化回归完成；待数据库迁移授权和 1920 实机验收  
> 日期：2026-09-07  
> 适用分辨率：仅 1920×1080 桌面端  
> 关联 Figma：`czPqlJ7fXYn5cq4cbQyTFm`，页面 `03_客户底座`  
> 与旧 PRD 的关系：本文件承接客户 CRM PRD 中原定为“未来模块”的销售订单、生产订单、订单 BOM、采购申请和供应商采购单；旧 CRM 范围描述不作为本模块的实现依据。

## 1. 结论先行

本期主链路确定为：

`客户 → 询盘 → 报价版本 → 销售订单 → 生产订单 → 订单 BOM → 采购申请 → 供应商采购单`

原链路“客户 → 询盘 → 报价 → 订单 → 生产订单 → BOM → 采购”存在三个错误前提：

1. “订单”不能只是一个模糊节点，必须明确为销售订单；生产订单是独立对象。
2. BOM 毛需求量不等于实际采购量，中间必须有采购申请承接库存、在途、MOQ、损耗等差异。由于本期不建设库存净算，实际申请量和原因由采购员填写。
3. 正式采购单必须一张单对应一个供应商；多供应商、多批次拆分发生在采购申请分配阶段。

## 2. 当前系统事实与断点

以下为 2026-09-05 开发前检查到的历史现状，不是当前实现状态或目标方案。销售订单对象现已进入开发，后续断点仍须逐项以代码和测试为准：

1. 当前没有正式销售订单对象；生产订单仅以自由文本订单号关联上游，无法追溯询盘、报价版本和销售订单行。
2. 当前生产对象存在“可投产/生产中”状态，但公开流程缺少确认和开工动作；采购又要求生产对象已到达这些状态，正常流程无法走通。
3. 当前 BOM 创建门禁过松，草稿或待确认生产对象也能建 BOM；采购门禁又过严且依赖无法到达的状态。
4. 当前采购对象一对一绑定生产对象，供应商却放在采购明细行，实际更像跨供应商采购汇总，不是正式供应商采购单。
5. 当前页面同时使用“生产任务单”“生产订单”“销售订单号”指同一字段，业务语义冲突。

因此，开发不能在现有自由文本订单号和一对一采购模型上继续叠加功能，必须先补对象和状态关系。

## 3. 本期范围

### 3.1 本期建设

1. 销售订单列表、新建、自确认、详情、变更、风险、单据、操作记录。
2. 销售订单详情内的订单协同，不单独建设“订单协同”菜单或对象。
3. 生产订单列表、新建、PMC 确认、详情、生产负责人接单开工。
4. 每张生产订单独立的订单 BOM、版本、确认和只读打印。
5. 采购申请创建、提交、按供应商/批次分配、分配余量追踪。
6. 一单一供应商的正式供应商采购单。
7. 部门事实暂缺独立模块时的受控人工事件，包括财务、质量、物流事件。

### 3.2 本期不建设

1. 库存、在途、已分配、损耗、MOQ 的自动净需求计算。
2. PI/合同自动生成、电子签章和法务审批，只保存元数据、版本、状态和附件。
3. 历史订单真实数据导入；后续按真实文件单独审计、备份、迁移和对账。
4. 财务、质量、物流完整业务模块；本期只接收来源事件或受控人工事件。
5. 移动端及其他桌面分辨率适配。

### 3.3 现有数据兼容迁移

1. 本次开发不得删除、覆盖或自动猜测关联现有生产订单、BOM 和采购单。
2. 为新链路增加关联字段时，数据库迁移必须允许既有记录暂时为空；既有记录统一标识为“历史未关联”。
3. 新功能启用后，新建生产订单必须来源于已确认销售订单交付批次，并按新链路建立 BOM、采购申请和供应商采购单关联。
4. 历史数据的正式关联必须等待真实对应关系，另行执行只读预检、备份、映射、迁移和对账，不纳入本次自动迁移。

## 4. 核心对象与关系

### 4.1 对象

| 对象 | 业务含义 | 关键关系 |
|---|---|---|
| 客户账户 | CRM 中的客户经营主体 | 可对应多个买方交易主体 |
| 买方主体 | 本次交易合同/下单主体 | 销售订单确认时冻结快照 |
| 报价版本 | 不可覆盖的对外报价版本 | 销售订单行可追溯到具体报价版本行 |
| 销售订单 | 客户成交和履约主对象 | 最多来源于一份报价版本，或作为无报价直接订单创建 |
| 销售订单行 | 产品、价格、数量、容差与交付要求 | 可拆为多个交付批次 |
| 销售订单交付批次 | 生产订单的创建来源 | 一个批次可生成一个或多个生产订单 |
| 生产订单 | 生产部门执行对象 | 只能属于一个销售订单 |
| 订单 BOM | 当前生产订单的用料版本 | 每张生产订单独立建版、独立确认 |
| 采购申请 | 从已确认 BOM 形成的采购需求 | 记录毛需求、实际申请量和差异原因 |
| 采购申请分配 | 将申请行拆给供应商/批次 | 跟踪已分配量和剩余量 |
| 供应商采购单 | 对供应商的正式采购订单 | 一张单只能对应一个供应商 |

### 4.2 关系约束

1. 一个销售订单最多关联一份来源报价版本，并沿该报价保留询盘追溯关系；不得把多份报价合并进同一销售订单。客户把多份报价合并下单时，系统内仍分别建立销售订单。
2. 一个报价版本行允许部分数量、部分产品转销售订单；同一报价可以分多次生成多张销售订单。系统按报价行累计已转数量并保留剩余数量，累计转单数量不得超过报价数量。
3. 一个销售订单可以生成多个生产订单。
4. 一个生产订单只能属于一个销售订单，不允许合并多个销售订单。
5. 生产订单累计生产数量不得超过销售订单对应交付批次及其数量容差；超出必须先走销售订单变更。
6. 每个生产订单拥有独立订单 BOM；复制历史 BOM 时必须生成新版本并重新确认。
7. 一条采购申请行可拆到多个供应商或多个采购批次，但已分配总量不得超过实际申请量。
8. 一张供应商采购单只能有一个供应商，可包含同一采购申请中分配给该供应商的多条明细。

## 5. 销售订单

### 5.1 创建来源

1. 报价已接受后，由业务员点击“生成销售订单”，选择实际成交的报价行和数量，生成销售订单草稿；不自动生成。
2. 允许无报价、返单或直接下单，但必须填写下单原因、客户确认依据并完整审计；业务员确认订单前必须上传至少一份客户凭证。
3. 从报价进入时只带入当前报价版本，不允许追加其他报价；可以继续从当前报价选择尚未转单的产品和数量。
4. 报价来源的销售订单禁止追加报价外产品。报价中不存在的产品必须单独建立无报价直接销售订单，并按直接订单规则填写原因、客户确认信息和上传客户凭证。

### 5.2 客户确认最低字段

以下字段必须结构化保存：

1. 确认方式：客户 PO、签署 PI/合同、邮件或聊天书面确认。
2. 客户确认人。
3. 确认时间。
4. 确认摘要。
5. 系统记录提交人和提交时间。
6. 本单买方地址。草稿可暂缺，确认时必须选择仍有效且属于当前买方主体的地址。

所有销售订单均必须保存上述结构化客户确认信息。无报价、返单或其他直接下单的销售订单，还必须上传至少一份客户凭证，例如客户采购订单、签署的 PI/合同、邮件或聊天截图；缺少凭证时禁止业务员确认订单。来源于报价的订单可复用报价或询盘中已经归档的客户确认凭证，不要求重复上传。

### 5.3 关键字段

| 区域 | 字段 |
|---|---|
| 标识 | 销售订单号、客户 PO 号、合同号、版本号 |
| 主体 | 客户账户、买方主体、本单买方地址、固定卖方模板及各自冻结快照 |
| 来源 | 询盘、报价版本、报价行、无报价原因 |
| 条款 | 币种、汇率快照、贸易条款、付款条款、税务口径 |
| 产品 | 产品、规格、数量、单位、价格、报价价格差异、差异原因 |
| 交付 | 交付批次、计划交期、包装/质量/唛头要求、数量容差 |
| 人员 | 业务员、业务跟单、团队、协同人员 |
| 审计 | 创建人、确认人、版本、变更原因、操作记录 |

#### 5.3.1 买卖方与地址规则

1. 从报价创建订单时，带入报价签发时的地址快照；对应地址仍有效时同时带入地址 ID，已归档或不存在时保留历史快照供识别，但必须重新选择或新增地址。
2. 客户只有一条有效地址时自动选中；存在多条时必须由业务员人工选择，系统不得默认取第一条。
3. 确认订单时服务端重新校验地址归属和有效性，并冻结独立的 `buyer_address_snapshot`。客户以后修改主数据，不改写已确认订单及历史版本。
4. 缺地址时页面打开共用买方资料弹窗的“地址”页签；保存新地址后刷新并选中，但不自动继续确认，业务员须再次点击“确认订单”。
5. 报价与销售订单共用买方资料弹窗、卖方主体卡片和卖方编辑弹窗。卖方继续使用固定模板 `HAIQU_FIXED_BILINGUAL`；更新模板须提示会影响以后新建的报价和订单，已确认订单只读取自身快照。

#### 5.3.2 交付批次编辑规则

1. 1920×1080 页面每行展示两张交付批次卡片；每张卡按产品展示订单量、本批数量、其他批次已分配量和剩余量。
2. 少分显示黄色提醒，超分显示红色错误，完全分配显示绿色状态；每款产品所有有效批次数量合计必须严格等于订单数量后方可确认。
3. 删除草稿批次前显示将释放的产品与数量，删除后不自动重分；已确认订单不得新增、删除批次或改变产品组成。

### 5.4 状态与动作

`草稿 → 已确认 → 履约中 → 已完成`

旁路状态：`已暂停 / 已取消`

| 当前状态 | 允许动作 | 结果 |
|---|---|---|
| 草稿 | 保存草稿 | 保持可编辑，不回写成交事实 |
| 草稿 | 业务员确认订单 | 校验必填项后进入已确认，并锁定直接编辑 |
| 已确认/履约中 | 编辑并保存订单变更 | 保存即确认新版本，不覆盖原版本；已有生产订单时须先登记 PMC 影响确认 |
| 履约中 | 满足完成条件 | 进入已完成 |

销售订单不经过业务主管审核。创建业务员自行执行“确认订单”；确认前仍可保存和修改草稿，确认后只能通过订单变更流程修改。

### 5.5 报价价格差异记录

1. 报价来源订单允许填写实际成交价，界面必须同时显示来源报价价、实际成交价、差额和差额比例。
2. 业务员可以修改实际成交价并直接确认销售订单；低于来源报价价也不增加主管审批门禁。
3. 系统保存来源报价价、实际成交价和差额比例作为追溯事实，但不引用历史成交价进行限制。
4. 无报价直接订单由业务员自行填写成交价，系统记录录入人、确认人和时间。

### 5.6 销售订单完成条件

1. 所有要求发货的数量已完成发货事实确认。
2. 付款条款要求的余款已完成。
3. 发票、装箱单等单证继续记录和展示，但不作为销售订单完成门禁。
4. 未全部发货或余款未完成时允许例外关闭，但必须记录未发数量、未收金额、关闭原因、影响说明、确认人和时间。流程责任提示为业务主管，当前开发阶段不做账号权限限制。

## 6. 销售订单内协同

“订单协同”不是独立业务对象，也不单独占用一级菜单；它是销售订单详情中的事实聚合与催办界面。

### 6.1 详情页签

`订单信息 | 产品明细 | 协同进度 | 单据 | 变更 | 风险 | 操作记录`

### 6.2 协同里程碑

1. 订金确认。
2. 合同/PI 状态。
3. 生产订单。
4. 产前样确认。
5. 生产与验货。
6. 订舱。
7. 发货。
8. 余款与单证。
9. 返单机会。

协同页采用“整单汇总＋交付批次明细”两层展示：顶部里程碑和金额卡展示整张销售订单的汇总状态；生产、验货、订舱和发货必须按销售订单交付批次展开。每个批次至少显示批次号、计划交期、产品与数量、关联生产订单、负责人、计划时间、实际时间、当前状态及异常。整单状态不得掩盖未完成或延期批次。

交付批次的生产状态不得由业务人员手工修改，必须根据该批次关联的有效生产订单自动汇总：没有有效生产订单时为“未开始”；存在已开工但累计合格完成数量不足时为“进行中”；所有有效生产订单累计合格完成数量达到批次需求量时为“已完成”。已取消生产订单不计入汇总数量，但必须保留取消记录和历史关联。

业务端的交付批次协同需要显示与交期直接相关的采购摘要，包括当前 BOM 是否已确认、采购申请完成进度、关键物料预计到料日期以及缺料/延期风险。业务协同页不得显示供应商采购单价、采购金额、供应商付款条件等采购商业敏感信息；详细采购数据只在采购模块查看。

### 6.3 事实来源原则

1. 订金、余款由财务来源事件确认。
2. 生产进度由生产模块确认。
3. 验货结果由质量模块确认。
4. 订舱、发货由物流模块确认。
5. 业务人员只能查看、催办、评论，不能直接改写上述事实。
6. 所属模块未建设时，允许指定角色登记人工事件，但必须显示“人工登记”、登记人、时间、证据和来源；未来系统事件同步后保留替代关系。

## 7. 销售订单变更

1. 已确认销售订单禁止直接覆盖字段；从“订单变更”进入编辑页，保存即确认新版本并保留旧版本快照，不再增加一层整单主管审批。
2. 产品、数量、价格、交期、质量、包装、唛头等客户约定字段发生变化时，新版本生效前必须保存客户确认方式、确认人、时间和摘要，并上传至少一份客户确认凭证。
3. 仅登记内部协同备注时使用协同时间线，不要求客户凭证，也不建立销售订单新版本；确认后的订单字段变更仍必须生成新版本。
4. 尚未创建生产订单时：业务员创建变更版本后可以自行确认。
5. 已经创建生产订单时：必须先由 PMC确认变更影响后才能生效；当前阶段只提示责任角色，不做账号权限拦截。
6. 销售订单变更不会自动覆盖生产订单、BOM 或供应商采购单；系统生成影响清单和待办。
7. 需要时创建新生产订单版本和新 BOM 版本；已下达供应商采购单必须单独变更或取消。
8. 销售订单取消后，来源报价和询盘标为“转化待复核”，不自动猜测回退状态。
9. 已确认销售订单取消某个交付批次时，不允许直接删除批次，必须通过销售订单变更新版本并保存客户取消凭证。未开工的关联生产订单可在变更生效后取消；已开工生产订单必须保留实际产量和停产记录，不自动删除；已下达供应商采购单不自动取消，只生成采购变更或取消待处理事项。

## 8. 生产订单

### 8.1 创建与锁定

1. 业务跟单从已确认销售订单交付批次创建生产订单草稿。
2. 客户、买方、卖方、销售订单、产品和数量容差从来源锁定。
3. 不允许在生产订单中任意选择其他产品。
4. 业务跟单在来源交付批次可用数量内填写生产数量；PMC确认时不得修改产品、规格、生产数量、数量容差和客户要求。
5. PMC只允许调整计划开始/完工、生产优先级、生产批次和计划人员；无法执行时填写原因退回业务跟单处理。
6. 生产和采购角色默认只看执行字段；销售价格、毛利、付款字段需单独授权。

### 8.2 状态与动作

`草稿 → 待 PMC 确认 → 已确认 → 生产中 → 已完成`

旁路状态：`已暂停 / 已取消`

| 角色 | 动作 | 结果 |
|---|---|---|
| 业务跟单 | 创建、保存、提交 PMC 确认 | 进入待 PMC 确认 |
| PMC | 退回业务并填写原因 | 返回草稿，由业务跟单修改 |
| PMC | 确认生产订单 | 进入已确认 |
| 生产负责人 | 接单并开工 | 进入生产中 |
| PMC | 异常完结确认 | 允许短产或提前关闭 |

生产订单允许单独取消，但取消原因必填。未开工订单取消后不再进入执行；已开工订单取消时必须保留累计合格数量、实际产量、报工和物料记录。取消生产订单不减少来源销售订单交付批次的客户需求量，系统应重新计算该批次的待生产缺口并提示补建生产订单，但不得自动创建替代生产订单。

### 8.3 开工门禁

生产负责人点击“接单并开工”时必须同时满足：

1. 生产订单已确认。
2. 当前订单 BOM 已确认。
3. 生产数量未超过销售订单交付批次及容差。

产前样要求和确认状态继续在销售订单协同及生产订单中展示，但不作为开工门禁。需要产前样而客户尚未确认时，页面只显示非阻断警告，生产负责人仍可开工，也不增加额外审批。

付款条款要求订金时，订金已到账可以直接开工；未到账时必须先登记“允许先生产”放行记录，填写原因并保存操作人和时间，完成登记后方可开工。当前开发阶段不限制由哪个账号登记，后期权限细化时再指定财务或管理放行角色。

### 8.4 完成条件

1. 全部生产批次已完成。
2. 合格完成数量达到计划数量后允许正常完成。实际产量超过计划数量或销售订单容差时，不阻止完成，也不需要审批。
3. 系统必须记录实际完成数量和超出数量，超出部分只展示、不控制。
4. 数量不足或提前关闭必须填写原因并进入异常完结，由 PMC 确认。

## 9. 订单 BOM

### 9.1 建立与版本

1. 每张生产订单独立建立订单 BOM。
2. 生产订单草稿或待 PMC 确认时允许准备 BOM 草稿。
3. 生产订单未确认时，BOM编辑页只能保存草稿；生产订单确认后，才允许执行“确认BOM”。
4. 可从 Excel 导入、复制同产品历史 BOM 或空白建立。
5. 复制历史 BOM 必须创建当前生产订单的新版本，保留来源版本、调整原因、确认人和时间。

### 9.2 状态与动作

`草稿 → 已确认`

1. BOM编辑页同时提供“保存草稿”和“确认BOM”两个按钮。
2. 生产订单为草稿或待 PMC 确认时，“确认BOM”按钮不可用，并提示需先确认生产订单。
3. 生产订单已确认后，编辑人员点击“确认BOM”，当前版本立即生效，不再经过独立审核。
4. 已确认版本锁定；变更必须新建草稿版本并重新确认，旧版本保留追溯。
5. 当前已确认 BOM 同时是生产开工和生成采购申请的门禁。

### 9.3 数量口径

界面统一使用“BOM 毛需求量”，不得使用“建议采购量”或把毛需求直接等同实际采购量。

## 10. 采购申请

### 10.1 创建条件

1. 来源生产订单已确认。
2. 来源订单 BOM 已确认且为当前版本。
3. BOM 物料、单位和毛需求量完整。

### 10.2 申请字段

| 字段 | 规则 |
|---|---|
| BOM 毛需求量 | 从已确认 BOM 只读带入 |
| 实际申请量 | 采购员填写，不能默认直接等于毛需求量 |
| 差异原因 | 实际申请量与毛需求不同必填；相同也可注明“与毛需求一致” |
| 需求日期 | 必填 |
| 建议供应商 | 可选，不自动确定正式供应商 |
| 已分配量 | 系统汇总供应商采购单分配量 |
| 剩余量 | 实际申请量减已分配量，不得小于零 |

### 10.3 非净需求风险

本期不自动扣减库存、在途、已分配，不自动计算损耗和 MOQ。因此：

1. 页面必须持续提示“BOM 仅为毛需求”。
2. 不提供“一键照搬全部毛需求并下单”。
3. 实际申请量和差异原因由采购员承担录入责任。
4. 后续建设库存/采购净算时，再替换人工申请量，不回写覆盖历史采购依据。

## 11. 采购申请分配

1. 采购申请提交后进入供应商和采购批次分配。
2. 同一申请行可拆给多个供应商，也可分多个采购批次。
3. 每次生成供应商采购单后回写已分配量和剩余量。
4. 已分配量不得超过实际申请量；并发提交必须防止重复占用。
5. 取消或减少未下达采购单时释放分配量；已下达采购单必须先完成采购单变更/取消。

## 12. 供应商采购单

1. 一张正式采购单只能对应一个供应商。
2. 供应商放在采购单头，不放在每条明细上作为可变字段。
3. 采购单可来自采购申请的部分行、部分数量和一个采购批次。
4. 必填字段包括供应商、联系人、币种、税务口径、预计到料、采购数量、单位、采购单价和金额。
5. 采购金额由采购数量乘采购单价计算；修改数量或单价必须重算并记录。
6. 正式下单后，修改或取消需形成变更记录，不直接覆盖原下达内容。

## 13. 报价、询盘与客户状态回写

1. 销售订单草稿只在询盘展示关联卡片，不改变询盘主状态。
2. 首张有效销售订单确认后，询盘立即标记为“已创建销售订单”；报价行继续保存累计已转数量和剩余数量，供后续拆单使用。
3. 客户“成交客户”由存在已确认有效销售订单派生，不由业务员手工选择。
4. 报价“接受”不等于成交，只有销售订单确认才构成成交事实。

## 14. 职责提示与暂缓权限

当前为单人开发和内部验收阶段，本期先实现完整业务流程，不新增订单链路的角色权限拦截。下表仅定义流程责任角色，页面通过按钮旁短提示、状态说明或操作确认文案标明“应由谁负责”，不增加占用大面积版面的权限说明区。

| 责任角色 | 负责动作 |
|---|---|
| 业务员 | 创建销售订单、保存草稿、自行确认订单、查看本人/团队授权订单 |
| 业务主管 | 查看风险订单、处理需要管理判断的例外关闭；不审批销售订单成交价 |
| 业务跟单 | 从已确认销售订单创建生产订单草稿、维护协同催办 |
| PMC | 确认生产订单、确认已有生产订单时的销售订单变更影响、确认异常完结 |
| 生产负责人 | 查看执行字段、接单开工、更新生产事实 |
| BOM 编辑人员 | 建立、编辑、保存草稿并确认订单 BOM |
| 采购员 | 创建采购申请、维护实际申请量、供应商分配、维护采购单草稿、正式下单及采购变更/取消；当前业务只有一名采购员，不设置采购主管复核 |
| 管理层 | 查看全部订单及风险；敏感明细仍按字段权限控制 |

本阶段不按上述角色阻止操作，也不实现细粒度数据可见范围。正式上线前必须另立权限开发任务，将后端接口权限、数据范围、敏感字段和前端按钮显示一起实现并测试；不能只靠前端隐藏。未完成权限开发前，本模块只能用于开发和内部验收，不应开放给多人生产使用。

## 15. 编号与快照

1. 销售订单使用唯一系统编号，例如 `SO-202609-000188`。
2. 客户 PO 号和合同号为独立字段，不作为系统主键。
3. 生产订单使用唯一系统编号，例如 `MO-202609-000031`。
4. BOM 编号包含生产订单和版本，例如 `BOM-MO000031-V1`。
5. 采购申请编号例如 `PR-202609-000018`。
6. 供应商采购单使用独立系统编号，不复用采购申请号。
7. 买方、卖方、币种、条款、价格和来源版本在订单确认时保存快照，历史不随主数据修改而变化。

## 17. 开发顺序

1. 建销售订单及订单行、来源关系和状态；页面以紧凑提示标明责任角色，本阶段不做角色权限拦截。
2. 改报价/询盘转单动作与成交状态回写。
3. 将现有生产对象迁移为正式生产订单关系，补 PMC 确认和接单开工动作。
4. 将 BOM 关联从自由文本/产品关联改为生产订单独立版本，补确认门禁。
5. 新增采购申请及分配对象。
6. 将现有采购对象调整为一供应商一采购单，解除生产订单一对一限制。
7. 接入销售订单协同事实事件和受控人工事件。
8. 业务流程稳定后，单独实现角色权限、数据范围和敏感字段控制，作为正式上线门禁。
9. 最后处理历史数据迁移和旧编号映射。

## 18. 验收场景

1. 报价只转部分产品和数量，销售订单草稿能追溯来源版本和剩余量；同一报价再次转单时只能选择剩余数量，累计数量不得超出报价数量。
2. 无报价订单可确认，但直接下单原因和客户确认结构化字段必须完整，且至少有一份客户凭证。
3. 报价来源订单允许修改成交价；低于报价时不触发额外审批，业务员可直接确认，系统保留来源报价价、成交价和价差快照。
4. 无报价直接订单不比较历史价格、不触发价格审批，业务员填写成交价后可自行确认。
5. 销售订单未确认时不能创建正式生产订单。
6. 生产订单不能选择销售订单以外的产品，累计数量不能超过批次容差。
7. 生产订单待 PMC 确认时可准备 BOM 草稿，但“确认BOM”不可用。
8. 当前 BOM 未确认时生产负责人无法开工；产前样未确认只提示，不阻止开工。
9. 未收订金时必须先登记允许先生产的原因、操作人和时间，完成放行记录后才能开工。
10. BOM 已确认后才能生成采购申请。
11. 采购申请必须显示毛需求、实际申请量、差异原因、已分配量和剩余量。
12. 同一采购申请行可拆给两个供应商或两个批次，累计分配不得超量。
13. 供应商采购单头只有一个供应商，不能在行上混入第二供应商。
14. 已确认销售订单变更不会静默覆盖生产订单、BOM 或已下达采购单。
15. 业务人员不能直接把财务、质量、物流事实改为完成。
16. 全部页面在 1920×1080 下无横向溢出、遮挡或关键操作裁切。
17. 关键操作页面以简短文案提示责任角色，但当前开发阶段不因登录角色不同而阻止操作。
18. PMC确认页只能调整生产计划字段；销售订单带入字段锁定，退回时必须填写原因。
19. 含两个及以上交付批次的销售订单，在协同页顶部显示整单汇总，并能分别查看各批次的生产、验货、订舱和发货状态；一个批次完成时不得把其他未完成批次显示为整单完成。
20. 交付批次生产状态随有效生产订单和累计合格完成数量自动变化；取消生产订单后重新汇总，且业务员不能直接把批次改成“已完成”。
21. 取消已确认交付批次时必须通过销售订单变更并上传客户取消凭证；系统保留已开工生产事实，不自动取消已下达采购单，并生成下游影响清单和待处理事项。
22. 单独取消未开工或已开工生产订单时必须填写原因；已开工事实保留，来源交付批次需求量不减少，系统重新显示待生产缺口并提示人工补建，不自动创建替代生产订单。
23. 业务端交付批次协同显示 BOM、采购申请、关键物料预计到料及缺料风险，但不显示供应商采购单价、采购金额和供应商商业条款。
24. 执行数据库迁移后，原有生产订单、BOM 和采购单数量不减少且不被自动关联；新建生产订单必须关联销售订单交付批次，旧记录显示“历史未关联”。

## 19. 已接受但需持续观察的风险

1. 订金未到账仍可通过登记放行后开工，且当前阶段不限制放行账号：可能造成坏账、停产和材料损失。
2. 直接订单虽强制客户凭证，但本期不自动判断附件内容真实性，仍需业务员对证据负责。
3. 无报价直接订单不参考历史价格且不经过价格审批，业务员可自行定价并确认，存在低价、错价和权限滥用风险。
4. 本期无净需求计算：依赖采购员人工判断，存在重复或过量采购风险。
5. 财务、质量、物流先用受控人工事件：存在时效和真实性依赖人工的问题。
6. 历史数据暂不导入：新旧订单统一列表需等后续数据迁移任务完成。
7. 当前暂不做订单链路权限控制，只适合单人开发和内部验收；如未补权限就多人上线，存在越权查看和越权操作风险。
8. BOM由编辑人员直接确认，不经过第二人审核，存在错料、漏料和用量错误未被复核的风险。
9. 需要产前样但客户尚未确认时仍允许开工，存在颜色、材质或工艺与客户预期不一致的质量风险。
10. 实际产量超过计划数量或订单容差时不阻止完工，可能造成额外库存、材料消耗和成本偏差；系统只记录实际量与超出量。
11. 当前仅一名采购员，采购申请、供应商分配、采购单价及正式下单均由同一人完成，不设置采购主管复核，存在错价、错量、错供应商或舞弊无法被第二人及时发现的风险。

以上风险均不得在开发时被悄悄改成不同规则；如需改变，必须作为新的业务决策单独确认。
