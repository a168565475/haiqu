# SAM-10A 样品入库批量选择弹窗开发说明

## 本轮范围

- 只开发 1920 桌面端“样品入库”批量选择弹窗，不开发出库弹窗、借出弹窗或详情页。
- 沿用已确认的样品库页面、黑色主按钮、卡片、表格和 Noto Sans SC 字体。
- Figma 示例只用于字段、尺寸与交互结构；候选样品和提交结果均通过真实接口读取或写入，不使用 Mock 冒充业务功能。

## 入库规则

- 候选明细必须同时满足：样品跟进单流程结束、PMC 审核通过、金工参数完成、裁剪参数完成、打样数量大于 0。
- 支持同一条样品明细分批、多次入库；累计入库达到打样数量后不再出现在候选列表。
- 入库数量必须是正整数，且不能超过当前剩余可入库数量。
- 入库位置必填，前端默认“样品库”，允许操作人修改。
- 提交时同时携带“候选列表加载时的累计入库数量”。后端事务内重新锁定并检查，数据已变化时返回 409，要求刷新后重试。

## 接口与权限

- `GET /api/v1/sample-inventory/eligible/`：返回当前可入库样品明细，单次最多 100 条。
- `POST /api/v1/sample-inventory/receipts/`：在同一事务内生成入库单和多条入库明细。
- 两个接口均要求 `samples.add_sampleinventoryreceipt` 权限；操作人必须绑定有效员工档案。
- 单据提交人和提交时间由后端从当前账号与系统时间写入，前端不允许伪造。

## 编号说明

- Figma 中的 `RK-日期-序号` 只是原型占位，不承诺最终格式。
- 当前系统编号基础设施的兼容格式为 `RK-YYYYMM-六位序号`，由数据库序列保证唯一性。
- 新增迁移 `0018_sample_inventory_receipt_sequence.py` 创建入库编号序列。
