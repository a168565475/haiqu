## 1. 交付结论

本轮已把 `/` 从环境检查页替换为正式工作台，并完成两种视图：

- 超级用户或具备 `customers.view_all_customer`：显示主管工作台。
- 其他具备 `customers.view_customeraccount`：显示业务员工作台。

本轮没有新增或修改数据库表、Migration、后端接口和后端业务代码。工作台复用现有 Dashboard、任务、客户、沟通和询盘接口。

## 2. 已实现功能

### 2.1 数据与权限

- 新增统一的工作台模式、数据来源和加载状态类型。
- 调用：
  - `GET /api/v1/dashboard/me/`
  - `GET /api/v1/dashboard/manager/`
  - `GET /api/v1/tasks/`，分别请求 `PENDING`、`IN_PROGRESS`，前端合并、去重和按截止时间排序。
  - 客户列表与客户统计接口，用于风险客户和风险数量。
- 只解析前五条任务来源；直接客户来源按客户 ID 缓存客户名称。
- 接口失败显示局部错误，不使用演示数据静默替代。
- 缺失准确业务口径的数据统一放在 `workbenchDemoData.ts`，卡片显示“演示数据”。

### 2.2 交互

- “记录沟通”：调用现有沟通创建接口，使用 Element Plus 抽屉完成最小必填表单。
- “新建询盘”：调用现有询盘创建接口；当前账号必须关联有效员工，作为询盘负责人。
- 任务详情：读取 ETag；开始/完成操作携带 `If-Match`，冲突时明确提示刷新。
- 风险客户行：跳转现有客户详情路由。
- “导出日报”“分配询盘”及未接入审批动作：保留原型外观，使用 `aria-disabled="true"`，点击只提示“模块尚未接入”，不伪造成功。
- 页面包含加载、空数据、局部错误和无权限状态。

### 2.3 视觉和响应式

- 字体栈第一优先级改为系统 `Noto Sans SC`。
- 1920×1080：240px 侧栏、56px Header、24px 页面内边距。
- 1440×900：64px 折叠侧栏、56px Header、24px 页面内边距。
- `<1600px` 切换为 64px 图标侧栏；`<=768px` 隐藏侧栏。
- 1920/1440 下，指标卡、主卡、下方卡片的位置和尺寸均与确认值一致，浏览器测量误差为 0px；没有页面级横向溢出。
- 工作台侧栏图标使用从 Figma 节点下载的原始 SVG，没有使用相似图标替代。

## 6. 视觉验收事实与未达项

几何验收已达到确认值：两种工作台在 1920 和 1440 下，侧栏、Header、页面内边距、五张指标卡以及四张主卡的位置和尺寸均为 0px 几何误差。

当前未达到“整张图片原始像素差低于 3%”这一严格数值，不能声称已经像素级 1:1：

- 1920 原始差异像素比例：业务员 7.41%，主管 7.33%。
- 1440 原始差异像素比例：业务员 10.61%，主管 10.71%。

该统计没有排除动态文字、真实任务/客户内容、“演示数据”标记和字体抗锯齿，因此比方案中允许排除后的口径更严格；但即使如此，也不能把它描述成已达 3%。

主要差异有三个明确来源：

1. 产品方案要求所有演示卡片必须显示“演示数据”，Figma 主画面没有这些标记。
2. 为保留已经上线的客户入口，侧栏仍显示“客户管理”；Figma 工作台基准的侧栏没有该独立入口。删除它会造成真实功能回归，因此本轮没有为了截图而删除。
3. 任务、客户、当前用户按真实接口和权限展示，不能把 Figma 示例文案伪装成真实业务数据。

判断：布局结构、密度、颜色体系和卡片尺寸已经基本一致，可以进入业务联调；如果验收必须以未做排除的整图 `<3%` 为硬门槛，需要产品在“保留演示标记/真实导航/真实数据”和“完全复刻静态 Figma 截图”之间重新确认优先级，两者不能同时完全满足。

## 7. 已知限制和后续成本

- 销售漏斗、订单里程碑、团队绩效、团队负载、SLA、日报和询盘分配仍是演示口径；要转为真实数据，需要后端先定义统计周期、币种换算、归属规则、历史快照和权限口径。
- 主管“风险与审批”卡片包含真实风险客户入口与演示审批事项，整卡已标记演示数据；后续接入审批 API 时应拆分来源标记。
- 工作台暂未新增独立路由懒加载，生产包仍有 Vite 的大包体积警告；这是性能优化项，不影响当前功能，但低速网络首屏会承担额外成本。
- 视觉截图使用 Chrome、100% 缩放、设备像素比 1。其他浏览器或未安装 Noto Sans SC 的电脑不能保证相同字形。
- 后端测试使用遗留的空闲 `test_haiqu_erp` 测试库并以 `--keepdb` 运行，没有删除该数据库。
