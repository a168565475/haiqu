## 已确认规则如何落图

| 已确认要求 | 设计处理 |
| --- | --- |
| 从内部装配计划成品入库，仓库操作 | 自动带入来源，入库人跟随当前员工；不增加审核页 |
| 保留订单允许偏差上限 | 示意1000把、2%、上限1020把；2%不是固定系统值。实际公式向下取整 |
| 分次入库不能超量 | 累计600把，剩余420把；填写200把后预览累计800、剩余220 |
| 生产领料已经扣料 | 确认入库只增加成品，不再次扣半成品 |
| 装配不要求上游全部完成才领 | 页面不增加金工/车缝全单完成门槛；实际产出投入校验另见待定规则 |
| 来源详情弹窗，不做右侧固定栏 | 复用已确认AppWindowDialog的独立预览打包件，1180×660 |
| 规格、颜色独立列，单行 | 两页签均按单行独立列；长值提示完整内容，不叠两行 |
| 现有设计规范 | 暖色ERP，230侧栏、64顶栏、14单层外距、32控件、44表头、40数据行、24标签 |

## 现有代码检查结果与设计建议的区别

已核对 `src/frontend/src/views/inventory/FinishedGoodsInventoryView.vue`、`src/frontend/src/types/inventory.ts`、`src/backend/apps/inventory/services.py` 与 `selectors.py`。当前已有生产入库、批量入库、样品来源、颜色/单位、库区/库位、选填每箱数量、装箱及容量校验。当前生产入库按订单偏差向下取整，并核对累计入库变化。

以下为本次设计建议，用户确认后再开发：

- 保留原有生产入库与批量入库能力，收在“其他入库”；样品仍从样品流程办理。库存页新增“装配入库”快捷入口时须先选择装配计划，正式实现不能固定到示例计划。主入口仍为内部装配计划的产品行。
- “入库记录”替代全屏超宽原单弹窗作为页签；点击查看才打开单笔来源详情。历史生产来源不能一概重标为装配，样品来源也不能删除或伪造装配关联。
- “在库记录”对应既有汇总中的在库批次数，表示组成该库存的有效入库记录数，不增加新的批次选择。仅变展示文案，不擅自改变成品出库分配规则。
- 当前库存页统计卡片把当前页合计显示为“当前库存”等，且可能混合把、张等单位。新稿不保留该统计卡片；保留列表总记录数，不新增未经接口支持的全库合计。
- 收货日期与装配计划关联是新入口需要核实/增加的单据字段。收货日期不能用创建时间偷偷代替；旧单没有事实来源时不补造。
- 表单示例沿用当前实际颜色可选、包装选填规则。未填包装标识“未计算”，不等于库位无限；是否收紧有限库位在未填包装时的确认条件，应在业务开发前单独明确，不通过视觉稿暗中改规则。

## 后续已定稿的业务点

以下两项已经分别取得用户确认：

1. 已在设计确认后的逐项问答定稿，用户选择A：装配累计有效入库达到订单净数量后显示完成，继续允许偏差内入库；出库不恢复额度，不自动结清整单。原稿只显示入库累计，实际计划状态按此规则实现。
2. 用户后续选择A：成品按实收入库，不增加逐项领料投入校验；按订单含偏差上限控制，领料端继续保留原有上限，材料与产出差异由人工核对。稿中“剩余可入库”指订单额度，不代表材料一定足够。

跨入口累计、并发、防重复、权限、普通仓管真实操作及历史接续在开发和联调中验收，本稿不将浏览器内演示视作这些业务能力已实现。
