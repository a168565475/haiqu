# 面料后续流程单位核查（2026-09-24）

用户要求：采购按米、入库按米、出库按米，半成品回货按套。本轮核对当前源码、真实单据和库存只读接口，并在独立测试数据库实际跑通非一比一换算；没有修改业务代码、执行迁移或写入主库业务数据。

## 单位主链结论

普通外发路线符合上述规则。面料原料与裁片半成品是独立库存身份；回货确认是从原料米数转为半成品套数的业务节点，不是将原库存记录改个单位。

| 环节 | 当前数量单位 | 检查结果 |
| --- | --- | --- |
| BOM 面料 → 采购 | 米；面料行单耗 × 订单量 | 正常，裁剪明细的套不参与原料采购 |
| 采购到货、质检合格入库 | 米 | 正常，沿用采购单位并核对原料单位 |
| 原料库存 | 米 | 正常，普通数量字段存米数；管材专用米数字段为空不代表面料漏记 |
| 厂内领布或外发发布 | 米 | 正常，按实际米数扣原料余额 |
| 外发实际投入、未用布退回 | 米 | 正常，投入登记不重复扣库；退布恢复原料米数 |
| 外发裁片回货 | 整数套 | 正常，增加独立半成品余额，原料库存不再扣一次 |
| 半成品领取 | 整数套 | 正常，只扣半成品套数，不重新扣布 |

每套耗米沿用创建外发单时冻结的 BOM 换算参数；修改当前 BOM 不会重新改变旧单据。

## 发现的配套问题与范围差异

### 1. 厂内裁剪没有按套完工入库节点

此前本单采用“全部厂内裁剪”。现有厂内领料只按米扣布，车间报工只登记报工和工价，不增加半成品库存。当前半成品入库调用仅有外发回货及管材专用回货。

该范围随后已由用户回复“1 确认”：厂内裁剪完成后也要按套入半成品仓，再按套领给后续车间。确认的链路为“原料按米领出 → 厂内裁剪完工按套入库 → 后续按套领料”；完工入半成品库存时不得再次扣除已领出的布料米数。这里确认了业务规则，完工登记界面、字段及开发步骤仍需形成可审阅方案，不能以修改原领料显示单位替代。

### 2. 半成品页仓库筛选仍使用原料仓

实时 GET 和源码一致：库存页面切换半成品后仍使用只提供 `MATERIAL` 仓的筛选接口，未提供裁剪布面仓、成品布面仓、管材喷塑仓等半成品仓。该问题影响筛选和查找，不代表库存数量已按错单位记账。

用户进一步询问“2 如何修正”，具体方案记录于 `docs/material_inventory_filter_fix_proposal_20260924.md`，尚未实施。

### 3. 退布减产后已完成单仍显示待回套数

已在独立数据库实际复现，非仅公式推测：每套 1.5 米，外发 100 米时计划 66 套；实际投入 90 米、回货 60 套，退回未用布 10 米。原料和产出均平衡，完成接口成功，状态为 `COMPLETED`，但详情接口仍返回待回 `6.0000` 套。

原因：详情使用“计划套数 − 已回套数”，完成校验使用“实际投入可产出套数 − 实回套数”。前后端详情同样存在该显示差异；不会导致重复扣布，但会让已完成单看起来仍欠回货。

证据：`unit_chain_edge_r1.json`、`unit_chain_edge_r1.log`；该审计用例以成功复现问题为通过标准，不表示问题已修复。

## 本轮未改动及后续边界

本轮仅检查，以上配套问题均未实施修复。采购米数仍取面料行自身用量，未自动汇总覆盖裁剪用量。当前主库未发现米与套混账。

半成品库存追溯详情、普通面料结清后补登记的现有能力限制，以及错误上游单位的条件性校验风险，记录在分段报告中；它们不等同于本单已经发生的单位错误，也不在本轮擅自扩展开发。
