## 分步改动和目的

1. **原单及事务接口**：增加装配来源、真实收货日期、请求防重复和来源快照；复用订单上限、有效成品仓/库区/库位、单位和包装检查。确认时重新读取额度，重复请求只返回同一原单；失败全部回滚。目的：不同入口和并发不能多入。
2. **装配成品入库页面**：按已确认图带入计划、订单、产品与额度；填写实收数量、实际颜色、位置、日期和包装；只增加成品库存，不再次扣已领半成品。目的：仓管从计划即可分次办理收货。
3. **成品库存页面**：库存汇总与入库记录两页签、独立单行列、按需加载的来源/库位弹窗；原生产入库、批量入库、样品来源、出库和配置保留。目的：库存数量与来源追溯各自清楚，避免混合单位的误导统计。
4. **装配进度及跨入口回归**：用统一累计有效入库计算装配状态；库存出库不恢复额度；按已确认口径不新增逐项投入核验。目的：完成状态、额度与实际库存不混淆。
5. **隔离环境验收与截图**：订单上限、分次、并发、防重复、库位不足、包装留空、日期、普通仓管权限、旧来源兼容、列表分页，以及实际1920页面截图。只在独立测试库创建试跑单据。
6. **主环境准备**：待整条业务验收后核对整合差异、迁移、备份及恢复，再按已约定门禁处理主环境切换。本次设计确认不代表已上线。

## 已确认规则

第一项已确认，用户选择A：累计有效成品入库达到订单产品净数量即显示装配完成；仍允许订单偏差范围内继续入库。例：订单1000把、偏差2%，达到1000把完成，上限仍为1020把。出库不恢复额度，也不自动结清整单。此规则作为装配进度开发依据。

第二项已确认，用户选择A：仓管按实际收到的成品确认，按订单含偏差上限控制，不新增逐项齐套领料校验；领料端原有数量上限和库存检查继续保留，材料与产出差异由人工核对。成品入库不再次扣原料或半成品，不新增超领审批。

两项规则及两页设计均已确认，进入连续开发与隔离验收。新候选目录：`qa/finished_goods_20260929/backend`、`frontend`；不再重复询问已定范围开发许可。
