## 需求对应

| 用户确认要求 | 本轮实现 |
| --- | --- |
| 仓库操作半成品入库，入口放内部作业计划 | 金工、车缝产品行“更多 → 半成品入库”，登录员工记录为入库人 |
| 裁剪不入库，直接给车缝 | 裁剪无新入口，接口拒绝裁剪类别；车缝读取已批准裁剪/车缝面料投入 |
| BOM 单耗乘订单量按部位封顶 | 后端使用最新已确认且数量一致 BOM；支/套整数，跨库区、跨厂内/外发累计封顶 |
| 同时按实际已领数量控制 | 金工扣除外发已用/占用；车缝多个部位共享面料池合计扣米，不能每个部位各用一份全额 |
| 不选采购批次，同实物半成品公共 | 复用 PublicStockBalance/Movement；厂内及外发车缝同完成阶段共用身份，来源原单独立保留 |
| 金工需喷塑沿用已有外发喷塑 | 有喷塑工艺的金工计划不在厂内最终入库，原喷塑回货进入同一只读记录列表 |
| 部件全部入库才算该工序完成 | 计划列表按全部部位累计入库判断金工/车缝完成；不改变报工或整个生产订单状态 |
| 装配可以随时拿，不能多领 | 厂内入库沿用公共半成品需求匹配；不增加齐套门槛，原订单领用上限及可用余额继续生效 |
| 列表区分厂内/外发来源，详情弹窗 | 全宽16列，点击“查看”才读来源原单；不做固定右侧详情栏 |
| 规格、颜色等独立列，单行显示 | 生产订单、产品、部位、品类、材质、规格、颜色、厚度、阶段分别成列；缺厚度显示“—” |

## 事务与异常处理

- 服务端检查登录、有效员工、入库权限与订单可见范围，前端隐藏入口不作为权限边界。
- 页面携带版本；确认时先锁实际已领来源，再锁订单及计划，重新计算。来源或额度变化返回冲突，禁止继续使用旧数。
- 同一请求号只入账一次；不同内容不得复用。库存写入失败时原单、明细、投入占用及余额一起回滚。
- 首次写入须公共库存已启用；旧库存口径领料不自动转换。
- 已入库数量不因领出恢复；实物属性、投入原料或历史切割参数冲突不自动猜补。
- 查询按业务入库日期，补录日期不使用系统创建时间替代。
- 超时及认证/限流错误保留原请求，手动核对仍使用同一编号，不自动重发新入库。
