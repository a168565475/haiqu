# 厂内半成品入库：S3第一部分开发记录

用户已选择A：厂内金工/车缝入库同时检查订单BOM需求和已审核实际出库投入。本阶段实现数量计算及单据存储基础，不代表完整S3或业务入库功能完成。

## 改了什么、为什么

| 项目 | 本次实现 | 验证范围 |
| --- | --- | --- |
| 数量内核 | 部位净需求减累计有效入库；实际投入减历史耗用及外发占用，两者共同限制本次入库 | 精确十进制计算、完整历史、分次办理、多部位共用投入 |
| 面料单位换算 | 每套用米＝每套片数×每片用米；多个部位使用同一投入池时按整张申请合计 | 避免每行单独允许、合计却超出已领米数 |
| 管材投入 | 输入为实际已领切割支数，每支产出占用一支 | 不直接把根数或米数当作产出支数；根/米换算沿用领料侧 |
| 历史保护 | 已入库不因后续领出而释放；历史来源、单位或单耗改变时拒绝无痕重算 | 不会通过减少当前仓库余额重新获得生产入库额度 |
| 单据存储 | 新增InternalSemiFinishedReceipt及明细，关联来源计划、工序、部位、投入需求和现有PublicStockMovement | 不建立第二套库存余额，不新增待审核状态，不关联采购批次 |
| 基础约束 | 正整数产出、前后累计一致、不得超过需求快照、耗用量一致、请求号唯一、一条明细对应一条公共流水 | 数据库约束是兜底，不能替代完整服务端权限与并发控制 |
| 删除保护 | 实例、常规查询集、关联管理器均拒绝直接删除入库记录 | 属于常规ORM操作保护，不能宣称数据库原始SQL不可删除 |

复用现有框架，不增加第三方依赖。新单据只生成新增/查看两类默认权限，未给真实员工授权。

[改动范围检查](../qa/internal_receipt_backend_20260928/scope_verification.json)核对候选原文件未变、独立副本只有模型注册文件被追加。

按[requesting-code-review](C:/Users/Administrator/.codex/skills/requesting-code-review/SKILL.md)安排独立只读复核。发现并修复：

## 已覆盖的业务算例

- 订单1000、部位4支：需求4000；已领只支持1000支时可入1000，申请1001被拒。
- 已领1000支，外发已用及占用250、此前厂内入200：剩余最多550支。
- 已领面料100米；座布每套0.6米、靠背每套0.4米：各入100套恰好用100米；座布150套加靠背100套合计130米被拒。
- 部件已经累计入足4000支，装配随后领走一部分：累计入库仍为4000，可再入量仍为0。
- 缺少来源、跨订单混算、零/负/非整数产出、无穷数、重复部位、历史数量与新需求冲突均返回受控错误。

## 还未完成及下一步

本阶段没有新增业务API或页面入口，当前不能通过新页面办理厂内实际入库。下一部分仍在已授权方案内：

1. 从真实已审核领料、历史产出和有效外发占用读取服务端事实；不能由前端填写可用投入，不能只提交本次选中的部位历史而漏掉共享材料占用。
2. 在一个完整事务内锁定订单/部位及共享投入，完成额度重算、权限/工序/需求版本校验、公共库存记账和单据写入。支持重复请求返回原结果、相同请求不同内容拒绝及多人并发不超入。
3. 接入厂内金工完成阶段及厂内/外发同实物同阶段识别，核对旧快照兼容；现有喷塑收发流程保持既定路线。确认外发与厂内两边都遵守投入占用，不能仅做单向检查。
4. 增加分页记录与按需来源详情API，再按S4/S5接已确认页面；之后做真实业务、普通仓管权限、性能与浏览器验收。

当前请求号唯一约束不等于幂等接口已完成；测试中的人工事务回滚不等于完整业务事务已实现；单行需求快照约束也不等于跨单累计或跨外发并发校验已上线。主环境迁移、发布及历史处理继续留在S8审阅后执行。
