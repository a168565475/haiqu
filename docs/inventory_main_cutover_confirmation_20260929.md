## 执行顺序与维护影响

1. **最后核对。** 再检查源码摘要、BOM原值、单据状态版本、期初数量及目标数据库身份；变化时暂停处理差异。拟使用现有有效管理员员工`DEMO_SALES_A`（显示名“业务员 A”，当前账号具备管理员权限）执行并记入审计，不冒充用户本人。
2. **暂停主系统写入。** 在维护窗口停止本项目主前后端服务，确认无其他任务对该主库执行写入；网页暂时不能正常操作，报工窗口也应停止提交。数据库及缓存服务保留，不删除容器卷。此前服务直接挂载`src`并自动重载，不能在线逐文件覆盖。
3. **正式备份及恢复验证。** 对停写后的主库、待替换源码和必要配置做成套新备份；只在另一个独立库验证恢复。预检快照不能代替此备份。
4. **部署、迁移和已审数据准备。** 按冻结清单复制文件，只执行`inventory 0019`、`material_issues 0012`、`outsourcing 0008`及其缺少的依赖。保持网页停写，在正式公共库存维护标记建立前，通过正常服务/API完成BOM、旧计划及厂内裁剪调整。这样避免正式维护标记拦截正常业务服务；不关闭校验来强行更新。
5. **建立库存维护状态及期初。** 设置绑定本机主库实例的工具目标，建立持久维护记录；生成与实际维护会话匹配的新备份/恢复证据，再执行正式期初导入及5项旧在途接续。各次写入记录请求号，超时先查实际结果，不换新请求自动重试。
6. **复核并启用。** 保存三张旧领料单保留凭证；制作本次真实维护期间的启用备份并验证恢复；重新生成完整预检。所有业务阻断解除、数量一致后，按本次用户确认及实际目标生成启用凭证。确认授权采用真实记录时间，不编造原消息时间。切换为公共库存后才恢复服务。
7. **主系统验收。** 用真实会话核对采购入库、原料库存、领料、外发、半成品入库、成品入库及库存页面、权限和关键余额，保存1920截图。单纯页面验收不自动创建新的采购、领料或报工测试单；如需业务试跑另按已授权范围执行。

本次确认允许在以上明确范围连续完成执行、核对与截图，不再逐条请求相同开发许可。若出现清单外业务数据变化、未知归属或金额风险，应停在当前阶段报告，而非扩大范围处理。
