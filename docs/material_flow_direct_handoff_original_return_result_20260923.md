# 原单正常合格回货：本步改动与验收结果

日期：2026-09-23。用户已统一确认两张补图，本步按既定顺序完成图1“原单正常合格回货”，以及直接交接后旧入口限制。**本步开发与隔离验收已完成；不代表整个直接交接流程或真实业务应用全部完成。**

依据：[已确认图稿](material_flow_direct_handoff_p4_completion_design_20260923.md)、[本步执行清单](material_flow_direct_handoff_original_return_execution_20260923.md)。

## 1. 改动前后

| 范围 | 改动前 | 改动后 |
| --- | --- | --- |
| 原单正常回货 | 直接交接没有仓库原料发料记录，旧回货路径被拦截；P4工作台无合格回货入口 | 原交接行可打开“登记合格回货”，填写支数、半成品库区、接收人、日期及选填备注 |
| 回货上限 | 单次交接和累计回货容易混用，原料分配量不能代表实际交接量 | 同任务、产品、部位、工厂累计实交−合格回货−未喷塑退回，多个交接共同使用这个上限 |
| 库存 | 不能通过再次发原料绕过回货限制 | 复用现有回货单和合格半成品库存账；新增合格支数，原料根米和流水保持不变 |
| 原单状态 | 直接交接后仍可能显示待外发 | 新交接转为加工中，合格回货转为部分回货；历史已有交接但仍待外发的原单可以凭真实交接回货 |
| 旧操作 | 旧发料、取消等路径尚未明确识别直接交接 | 后端限制旧原料发料、通用回货、退料、对账、完成、取消及删除；前端读取能力并说明限制。原单编辑接口原本不存在，没有新增旧页面原本没有的按钮 |
| 历史与身份 | 需要避免后改BOM漂移或相同部位重复回货 | 使用领料／交接冻结的任务、部位、颜色、单位与工艺；回货记录可查；重复请求只入一次 |

来源已备注结清不影响已经交接管件的正常回货。不同冻结颜色／单位混在同一分配、或整单同时存在仓库原料发料与直接交接时，阻止合并并提示核对。

本步没有新增表、迁移文件或依赖。没有扩展原单人工结清、自动完成、报废或不良品规则；即使已交接数量全部回齐，也不会擅自套用重加工新单的自动完成规则。

## 2. 实际网页结果

专用库 `p4original_acceptance_20260923`，独立 PostgreSQL 实例 `7688204325370306594`。后端本机18044，前端18045；普通业务账号，真实 Session、CSRF、真实接口，没有模拟响应。

种子通过真实后端视图准备实际交接60支、未喷塑退回12支、已合格回货24支。该24支属于验收前提，不冒充网页操作。随后从网页输入10支并确认回货，实际结果如下：

| 项目 | 网页确认前 | 网页确认后 |
| --- | --- | --- |
| 累计实际交接 | 60支 | 60支 |
| 未喷塑退回 | 12支 | 12支 |
| 合格回货／合格半成品 | 24支 | **34支** |
| 尚可回货 | 24支 | **14支** |
| 本次新增半成品流水 | 无 | **入库10支，24→34** |
| 原料余额及流水 | 原料领用后基线 | **全部字段逐条不变** |
| 仓库原料发料记录 | 无 | **仍为无，没有补造发料** |

网页只发出一次业务写请求，实际请求 `good_pieces:10`、备注为空，没有原料投入或不良品字段。零、负数、小数及25支超量输入均在网页拦截；取消不保存。重复同一请求不再次入库；同请求不同内容、缺CSRF、旧版本及超量在真实HTTP校验中被拒绝。

最终只读审计不只核对数量，还逐项比对任务、产品、BOM部位、工艺、颜色、单位、库区、品质及回货单—流水—余额的关联，确认两笔合格流水分别为0→24、24→34。
