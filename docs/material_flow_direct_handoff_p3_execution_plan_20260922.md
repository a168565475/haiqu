## 1. 本步交付与边界

实现后端的金工管材来源查询、实际合格完成登记、备注结清预览和确认，在独立测试数据库验证。正式页面接入属于 P4；P3 完成时不能宣称用户已能在正式页面操作整条路线。

加工来源仅来自具体已出库管材原料领料明细，并核对所属金工车间、生产任务、产品和部位。取已实际出库的支数与冻结批次快照，不拿申请量、采购量或最新 BOM 重算来源。旧记录缺少必要快照时提示不可登记，不补猜、不转换旧管材。

本步不接入外发占用、交接、回货或退回；不更改原料库存、共享领料额度、半成品库存、工资、采购状态、排产和任务日期。不新增报废流程。

## 2. 数据结构及约束

新增内容放在现有 `material_issues` 模块，沿用 UUID 主键、时间戳和人员引用。以下为拟实施名称，迁移编号在开发时再次核对，避免覆盖其他改动。

| 结构 | 字段与约束 | 用途 |
| --- | --- | --- |
| `MetalProcessingSource` 加工来源 | `issue_line` 唯一受保护关联；来源快照保存任务、产品、部位、管材、实际已领支数 L、批次及根米；`completed_pieces` C；`reserved_pieces` P；`dispatched_pieces` D；状态 OPEN/CLOSED；正整数版本 | 一条领料明细只有一份加工额度；原领料和批次仍为追溯依据 |
| `MetalProcessingCompletion` 完成记录 | 来源受保护关联、正整数合格支数、完成日期、操作者、服务端登记时间；唯一请求 UUID、规范化请求摘要、操作后版本和结果快照 | 保留每次登记和重试结果，累计完成可与明细核对；不开放编辑删除接口 |
| `MetalProcessingClosure` 结清记录 | 来源唯一受保护关联；去首尾空格后 1～1000 字备注；L/C/D/P/U/F 快照；操作者、服务端结清时间；唯一请求 UUID、请求摘要、操作后版本和结果快照 | 保留结清差额和审计，不提供重开或删除接口 |

数据库约束：L 为正整数；C、D、P 非负整数；C ≤ L；D + P ≤ C；来源唯一、结清唯一、版本大于零。完成登记必须为正整数。数量转换前检查整数性和字段范围，不截断小数、不产生整数溢出。

P3 的 P、D 固定由服务初始化为 0，不接受客户端提交修改，不生成模拟交接数据。字段为 P4 的同源并发控制预留；P4 必须同时建立真实外发关联明细并在同一事务内维护、核对汇总，不能只有计数没有来源单据。P3 测试可用隔离夹具检验 P > 0 时拒绝结清，但不把该测试说成外发链路已完成。

来源列表读取不创建记录。首次登记或结清时，在事务中锁住原领料及明细，校验实际出库状态与快照后建立唯一来源。来源未建账时也可展示 L 和零累计量；写入必须携带基于该领料明细及冻结快照的初始版本标识，避免首次并发登记绕过版本检查。

## 3. 接口清单

沿用项目现有接口前缀，在 `material_issues/api/urls.py` 注册 `metal-processing-sources`；不增加公开免登录入口。

| 接口 | 内容 |
| --- | --- |
| GET `metal-processing-sources/` | 分页查询有权限查看的已出库金工管材来源；按任务、产品、部位、领料单、来源状态筛选；包括尚未建立加工来源的有效领料明细 |
| GET `metal-processing-sources/{issue_line_id}/` | 来源详情、冻结根米与批次追溯、完成明细、结清快照、当前数量和版本标识；统一用领料明细 ID 定位，避免来源未建账时无法查询 |
| POST `metal-processing-sources/{issue_line_id}/completions/` | 请求 UUID、合格支数、完成日期；带 `If-Match`；校验未结清及累计不超 L，登记后返回最新数量及版本 |
| GET `metal-processing-sources/{issue_line_id}/closure-preview/` | 返回 L/C/D/P/U/F、是否可结清及阻止原因；只读，不生成结清记录 |
| POST `metal-processing-sources/{issue_line_id}/close/` | 请求 UUID、必填备注；带 `If-Match`；再次校验未结清、P=0，保存差额和审计后关闭来源 |

完成日期必须是有效日期；服务端登记时间另行保存，不将图中演示日期当成真实日期。额外的计划日期限制不在本步擅自增加。

权限沿用 `HasActiveEmployee`、`BusinessActionPermission`、会话登录及 CSRF 校验。新增来源查看、登记完成、备注结清的独立权限，分别映射接口动作；来源可见范围复用 `accessible_material_issues`，写入同样限定可见来源并核对动作权限，不接受客户端任意指定操作人。无权限请求不得通过详情、预览或错误信息泄露其他订单来源。

P3 只在隔离测试账号上验证权限，不自动给正式账号或角色授权；正式角色配置在后续应用步骤列出并确认。

## 4. 数量、事务与重试规则

1. 来源开放时，U=L−C，F=C−D−P；结清后可外发 F 显示 0，结清前两类差额仍保留。不得为归零而修改 L/C/D。
2. 首次写入按“领料单 → 领料明细 → 加工来源”锁序校验和落账；同来源全部写操作使用同一锁序。后续 P4 的分配与交接必须遵守此来源锁定约定，并在接入外发单锁时统一全链路锁序。
3. 一次完成登记、汇总增加、版本更新必须同事务成功；结清记录、来源状态、版本更新同事务成功。任何异常完整回滚。
4. 新请求校验 `If-Match`，过期版本或缺失版本按现有项目约定拒绝。相同请求 UUID 和相同内容重试返回原成功结果，不重复登记；同 UUID 内容改变拒绝。权限仍需重新校验，不因幂等重试放开访问。
5. 结清前再次校验 P=0。P4 接入真实分配后返回关联单号及数量；P3 不伪造关联单号。有已确认交接 D 不阻止来源结清，但不结束外发单。
6. 不通过完成记录自动登记报工，不触发库存或工资服务。已结清来源拒绝继续登记；结清与登记并发时最多只有符合当前版本的一方成功。
