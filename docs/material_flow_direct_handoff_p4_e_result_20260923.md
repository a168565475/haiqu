# P4-E 隔离数据库与真实浏览器验收记录

日期：2026-09-23。结论：**本轮已验证重加工新单分支，P4 整体尚未通过验收，不能标记全部完成或上线。**

## 1. 执行范围

本轮承接 P4-D4 后的确认，执行隔离数据验收及其必要修复。使用真实 Django 接口、Session 与 CSRF，以及普通业务权限账号；浏览器没有模拟接口响应。主数据库未执行迁移、业务写入或旧管材转换。本轮没有新增业务表或迁移文件。

隔离数据库为 `p4e_acceptance_20260923`；后端回归库为 `test_p4e_20260923_012134`，均位于专用 PostgreSQL 容器。隔离网页使用 `http://127.0.0.1:18041`，接口使用 `http://127.0.0.1:18040`。数据库脚本执行前校验数据库名、主机及 PostgreSQL 实例标识，防止误连主库。

## 2. 本轮修改及结果

| 修改 | 解决的问题 | 结果 |
| --- | --- | --- |
| 原来源交接按钮按可外发数量判断 | 加工全部登记完成后，仍有可交接数量却不能点击 | 完成 210 支的来源可实际交接 60 支 |
| 独立 P4 选项接口及前后端权限核对 | 读取选项依赖旧委外查看权限；创建新单误要求另一权限 | 普通 P4 账号可读取工厂、库区、接收人并创建新单 |
| 退回请求携带版本；采用服务端可退上限和阻止原因 | 缺少版本、旧回货与未喷塑退回重复占用数量 | 过期请求被阻止，前后端使用相同可退数量 |
| 原单、任务、产品、BOM 部位、加工厂唯一校验 | 错绑原单或部位、超分配交接 | 不匹配、已完成原单、已结清来源的新交接被拒绝 |
| 旧回货与未喷塑退回共用实交上限 | 同一批实物被两条回货路径重复使用 | 超量请求回滚，不产生半成品库存或原料变动 |
| 请求标识复用、失败重试和刷新处理 | 网络结果不明时重新生成请求可能重复写入；保存成功后刷新失败被误报为保存失败 | 重试保留原请求和版本，成功与刷新错误分开提示 |
| 查询并发和日期处理 | 慢响应覆盖当前选择；日期受 UTC 换算影响 | 当前选择与页面数据一致，默认日期按本地日期 |
| 新单库存预览使用来源冻结资料 | 修改当前 BOM 后，历史新单预览换算依据跟着改变 | 新单库存预览保持原换算依据；领料端相关缺口见下文 |
| P3 详情与旧回货检查 P4 迁移状态 | 尚未应用 P4 迁移时，旧入口查询新表导致报错 | 两条真实缺表测试先失败后通过；已迁移时仍执行实交上限校验，不给 P4 写入绕过规则 |
| 合格回货统一按任务、库区、库存余额加锁 | 回货与领料锁定顺序相反，同时操作可能死锁 | 真实数据库线程复现后修复；回货等待任务时不再提前占用库区 |

## 3. 真实数据走通的分支

1. 金工来源已完成 210 支，关联原外发单实际交接 60 支。
2. 登记未喷塑退回 24 支，登记重新加工完成 24 支。
3. 拆成两张新外发单，每张 12 支，分别完成实际交接。
4. 每张先回合格品 6 支，备注结清，再填写原因补回 6 支；原结清快照不变，回齐后自动完成。
5. 两张单累计形成合格半成品 24 支；领料 6 支后剩余 18 支。
6. 与测试基线核对：原料根数、米数余额逐条一致，原料流水记录数未增加；原来源完成量仍为 210 支、已交接仍为 60 支。流水检查比较的是记录数，未声称对原有流水字段做了逐条比对。

外发各项写入由真实网页按钮触发，共捕获 13 次成功写请求。半成品领料页使用真实需求数据完成选择和填数；领料单的创建、提交、确认出库通过同一登录会话的真实 HTTP 接口完成。因此本轮证明了半成品实际扣库，但**没有将领料页全部按钮操作声明为完整浏览器验收通过**。

首次浏览器运行在领料人控件处遇到测试脚本定位重复，外发写入已经成功；修正定位后从已有单据继续验收，没有重做外发写入。第一次写入记录保存在 `browser_run01.json`，最终结果保存在 `browser_acceptance.json`。最终报告的 `writes: []` 是续跑期间网页没有新增外发写入，不能理解为本轮没有真实写入。
