## 6. 失败轮次与修正边界

本轮没有为使测试通过修改业务代码。保留的失败轮次及原因如下：

- 首次浏览器环境缺少同源 API 配置；端口保护拦截了请求。仅修正 S10 前端环境并重启隔离前端，业务服务未停止。
- 初始补测夹具按每套 1.5 米固定赋值，与新增 100/80 套场景不符；完整链路夹具有供应商编码、车间员工必填值、排产快照缺项。修正测试前置数据后通过。
- 整根断言先使用“整根”文字，而接口返回“必须是 6 的整数倍”；改为校验明确的 `PIPE_WHOLE_BAR_REQUIRED` 错误代码，未放宽业务判断。
- 历史样品浏览器脚本引用未创建的采购来源；新增隔离来源后通过。外发状态脚本读取了早期失败结果，改为本轮有效单据。
- 历史领料状态脚本假设已出库单据仍有足够库存；本轮已将裁片领完。先验证确认弹窗的受控冲突，再验证来源耗尽时阻止编辑和保存；真实退回编辑流程另有主流程证据。
- 初始 BOM 账号缺少六项字典查看权限；仅对隔离账号补授权，最终复验六项读取均成功。没有改动业务用户权限。
- PDF 初次检查选择了本机未安装的库，改用已有 PDF 库；恢复快照首次读取使用系统默认编码失败，改为 UTF-8 后继续比较已成功恢复的副本。

早期日志、失败截图和最终通过结果分别保存。`browser_suite_results.json` 是中间轮次记录，最终以 `browser_final_results.json` 和 `result.json` 为准。
