## 1. 本步修改与实际结果

| 范围 | 改动 | 现在的结果 |
| --- | --- | --- |
| 管材 BOM | 整数切割长度、单耗、每根切割支数；共用 S3 十进制公式；后端生成根数、单根米数及采购米数 | 派生结果不能被客户端伪造；采购数量逐部位独立取整 |
| 管材字段 | 长度改切割长度（mm），采购长度改原材料长度（m），支数改采购根数；补建议采购米数 | 编辑、保存、复制、同步订单、预览和打印使用一致结果 |
| 面料与裁片 | 面料单耗乘订单量；裁片明确关联同一 BOM 已保存的面料行及每套耗米 | 拒绝跨 BOM、自关联、被删除来源及无效米制面料；不按名称推断来源 |
| 来源原料 | 新增管材、面料真实原料选择接口，分别限定根制管材、米制面料 | 绑定后材质及规格显示来源快照，换来源才能换这些字段；历史未绑定行保留原编辑字段 |
| 数量预览 | 新增只读 POST `boms/material-flow-preview/`，支持 PIPE/FABRIC | 弹窗应用前由后端核算；失败保留草稿；取消后重新打开，旧请求不能应用到新弹窗 |
| 七类编辑 | 移除下方“物料明细／当前编辑”区，行右侧按钮打开统一 1000px 弹窗 | 型材、五金、塑料、裁剪明细、面料、辅料、包材均保留对应字段、取消、下一行和图片入口 |
| 版本与历史 | 同产品行复制继承部位身份；其他产品行复制生成新身份；二次映射面料关联 | 复制不指回旧 BOM；已发管材部位不得删除、换原料/切割参数或减少到已领额度以下；确认不提前生成领料账 |
| Excel 导入 | 支持切割长度、每根切割支数、采购根数表头；识别旧面料清单标题 | 导入后也重算耗米；缺少每根切割支数不猜测，缺有效来源不能确认 |

例如订单 1000 件、单耗 2 支、每根切 6 支：切割长度 500 mm → 单根 3.05 米 → 337 根／1027.85 米。浏览器将切割长度改为 501 mm 后，保存、刷新、打印预览均为单根 3.06 米、337 根／1031.22 米。

面料单耗 2.5 米、订单 1000 件，需求为 2500 米；裁片每套耗米独立记录为 1.5000 米。外发米转套及半成品实际入库、领用仍由 S6/S7 实施。

## 5. 环境、异常与边界

- 沿用 Vue、Django、PostgreSQL 17 技术栈，无新增运行依赖。隔离前端用现有锁文件离线安装依赖；可用既有 `npm run build`、Vitest 和 Django 测试命令复核。
- PostgreSQL 容器为 `haiqu-material-flow-s3-pg`；浏览器后端为 `haiqu-material-flow-s4-web`，只挂载隔离副本。隔离库建立测试表时执行了 S3 迁移，**未对业务数据库执行迁移**。
- 预览前端 `http://127.0.0.1:15175`，后端仅绑定 `127.0.0.1:18004`。前端必须配置 `VITE_API_BASE_URL=same-origin` 和 `VITE_PROXY_TARGET=http://127.0.0.1:18004`；数据库不对宿主机发布端口。临时测试库不能作为正式业务数据保存位置。
- 初期浏览器轮次因内网端口映射、代理未就绪，以及 API 基地址未设置而失败；其中一次浏览器尝试默认 `localhost:8000`，被跨域限制阻止，未取得有效业务验收结果。最终脚本明确拦截隔离源之外的请求，所有最终写入均指向隔离测试数据。
- 已处理非整数、零、负数、越界、超小数精度、缺参、错误单位、无效来源、关联删除、过期版本、核算失败及旧请求回写。导入缺资料保留待完善，不伪造旧管材换算。
- 本步未修改业务采购、仓库执行、外发、领料流程，未做库存清零或采购状态重置。S3—S4 新口径尚未向业务环境启用。
