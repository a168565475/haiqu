## 3. 管材补齐规则与允许变化

逐部位计算，不合并不同部位：

| 内容 | 补齐依据 |
| --- | --- |
| 切割长度，整数 mm | 旧 `length_value` |
| 单耗，支/件 | 旧 `unit_consumption` |
| 每根切割支数，支/根 | 旧 `raw_values.tube_cut_piece_count` |
| 原材料长度，米/根 | `(切割长度 × 每根切割支数 + 50) / 1000`，按已实现规则向上保留两位 |
| 建议采购根数 | `订单量 × 单耗 × 1.01 / 每根切割支数` 向上取整数 |
| 建议采购米数 | 建议采购根数 × 原材料长度 |

预先核对结果：323 条原材料长度均不变；157 条建议根数不变，166 条各增加 1 根。实际执行前重新核对目标 ID、版本和原值，数据变化即停止，重新生成差异。

允许变化包括六项新类型字段、与这些计算对应的旧显示字段和衍生重量，以及正常保存/确认产生的状态、操作人、时间和审计记录。不得只补六项字段而留下新旧显示值互相矛盾。隔离演练时列出完整字段差异，任何超出确认清单的变化均须停止核查。

每米单价继续空白，不沿用旧按根价格，不自动填写实际采购根数。涉及金额汇总必须按现有空值规则重新计算，不能保留已经失效的旧金额。

## 4. 非管材依赖：范围及以下四项规则已确认

已按用户选择 A，将上述 99 条面料、297 条裁片及 3 条塑料件/辅料缺项纳入同一批模拟数据补齐范围，以便恢复完整流程。

取值确认进度：

- 面料旧 `purchase_consumption` 映射为每个成品耗米：用户已选择 A，确认沿用有效旧值作为本批模拟单耗。
- 裁片来源面料与每套耗米：用户均已选择 A，确认按行号轮流关联同一 BOM 的面料，并按对应裁片总套数分摊面料耗米，仅用于流程模拟。
- 4 条异常明细采用下文列出的有效原料替换，同步 BOM 与采购物料信息、清空替换行旧单价及派生金额，不修改基础物料主数据：用户已选择 A 确认。

第一项已确认规则：把面料旧 `purchase_consumption` 作为每个成品耗米的模拟值，执行前逐行检查现值有效性，再映射到 `unit_consumption`，以订单量计算采购米数。历史生成脚本按面料行号生成 0.75、0.90、1.05；这些仅说明旧模拟值的生成依据，不代表真实生产耗米，也不能直接重新生成覆盖现值。示例：旧值 0.75、订单 1,000 件，按此规则得到单耗 0.75 米/件、采购 750 米。用户已选择 A 确认此规则；无效或缺失旧值须列为异常，不自动补默认值。

本规则仅针对面料原料行，不直接作为裁片每套耗米。裁片来源及耗米采用下文已确认的第二、三项规则，并检查其合计需求与对应面料需求是否一致。

第二项已确认规则，仅用于本批流程模拟：在同一份 BOM 内，按明细行号排列裁片和面料，裁片轮流关联面料；例如有两条面料，则裁片依次关联面料 1、2、1、2。只允许关联本 BOM 内原料身份及米单位均有效的面料行；发现无效面料先处理已纳入的缺项，不静默跳过，不跨 BOM 配对。行号重复或排序不明确时先列入异常。此为人为设定的模拟关联，不宣称符合实际材质、颜色或生产工艺。用户已选择 A 确认此规则；每套耗米按第三项已确认规则处理。

第三项已确认规则，仅用于本批流程模拟：保留旧裁片用量，按关联面料的每成品耗米分配每套耗米。同一面料行关联的裁片，每套采用相同模拟耗米，其公式为“该面料每成品耗米 ÷ 这些裁片每成品用量之和”。现有加工需求函数 `processing_required_quantity` 使用 `cut_piece_quantity`（缺失时才使用 `unit_consumption`）乘订单量；执行前逐行核对用量为有效正数，不修改旧裁片用量以凑数。

示例：面料每个成品耗 0.90 米，关联三条裁片，每条旧用量均为每成品 2 套，则合计每成品 6 套，每套模拟耗米为 0.15 米。订单 1,000 件时，各裁片需求 2,000 套，各需 300 米，总计 900 米，与面料采购需求一致。

精度处理已随第三项规则确认：每套耗米最多四位小数；除不尽时向下保留四位，避免总模拟发料需求超出已确认的面料采购需求。差额留作未发出的库存，在试算清单单列，不记为已耗用或损耗，不声称发料必然耗尽全部采购米数。若结果小于 0.0001、用量无效、关联缺失或数量单位不符合预期，则列为异常，禁止自动填默认值。该分配仅用于流程模拟，不推断真实裁片大小和工艺；用户已选择 A 确认。

## 6. 执行约束与回退

1. 保留 BOM、分区和明细 ID，保留订单、产品及附件关系；物料关系除逐项确认的来源关联或原料替换外保持不变。现有保存接口按完整明细处理，漏传行可能被当作删除；不得只提交 323 条管材而遗漏其余行。演练须比较保存前后完整 ID 集合。
2. 采购刷新必须在 BOM 完整通过确认后进行，维持待确认状态。采购保存需要完整行集合，未批准变更的供应商、日期、数量、价格等均须保留并核对；若面料规则改变使原采购需求失效，先展示差异再确认处理。
3. 不运行历史全量模拟重建、补全或清空命令，不扩大到其余模拟 BOM，不转换旧库存，不删除入库记录。
4. 多份 BOM 与采购的现有操作可能分属不同事务，不能宣称全批天然原子回滚。隔离演练须验证中途失败、重跑和补偿方式，记录每笔完成状态。
5. 业务库执行期间应避免目标记录被同时修改，并使用现有版本校验。失败时优先停止后续操作，依据执行前快照制定定向回退；数据库整库恢复可能覆盖同期其他操作，不自动执行。
6. P2 需要验证完整业务校验、来源快照一致性、明细不增不减、重复执行无重复记录以及并发修改时拒绝继续。此前 S10 通过不能替代本批旧模拟数据验收。
