# 材料库存筛选修正方案（2026-09-24）

## 用户本轮确认与范围

用户回复“1 确认，2 如何修正”。第 1 项确定厂内裁剪也采用“领布米 → 完工入半成品库套 → 后续领料套”，完工入库不得重复扣布。第 2 项本轮解释具体修正方案；尚未修改业务源码或库存数据。第 3 项退布减产后的待回数量显示问题仍是独立待处理项。

## 当前原因

`MaterialInventoryView.vue` 查询库存列表时带了 RAW／SEMI 库存性质，但仓库筛选 `fetchMaterialFilterOptions()` 没有带此参数。后端 `MaterialInventoryViewSet.options` 固定返回原料仓及库区；页面切换仅刷新列表，也保留旧仓库、库区、分类条件。

结果是半成品列表已经切换，筛选器仍选择原料仓，且旧原料筛选条件可能继续把半成品结果筛空。

## 修正后的页面行为

| 当前页签 | 仓库下拉 | 库区下拉 | 分类选项 |
| --- | --- | --- | --- |
| 原材料 | 有效原料仓 | 对应原料仓下的有效库区 | 原料分类 |
| 半成品 | 有效半成品仓，如裁剪布面仓、成品布面仓、管材喷塑仓 | 对应半成品仓下的有效库区 | 可见半成品记录对应的分类 |

1. 切换原材料／半成品时清空原仓库、库区和分类，页码回到第一页，重新加载对应选项和库存。搜索文字可以保留。
2. 仓库变更时清空旧库区，只提供该仓库的库区；仍支持全部仓库、全部库区查询。
3. 半成品库存为空时，启用的半成品仓仍可选，列表准确显示空库存；不生成演示库存。
4. 因用户已确认厂内裁剪也入半成品库，当前“外发半成品”页签统一命名为“半成品”，覆盖厂内和外发来源。
5. 快速切换时，旧请求不得覆盖新页签的选项、数据、错误提示或加载状态；加载失败要提示并可重试，不能继续显示另一类仓库的旧选项。

## 实现位置与约束

- 后端 `/api/v1/material-inventory/options/?scope=filters` 增加 `stock_kind=RAW|SEMI`，未传默认 RAW，兼容原有入库和其他选项调用。
- `scope=filters` 时按库存性质返回匹配仓库、库区、分类；保持已有权限和可见范围。
- `scope=receiving/full` 维持原材料选项语义，不因新增参数改变现有调用。
- 库存列表请求同时校验库存性质、仓库类型及所选库区归属。仓库或库区编号无效、不存在、类型不匹配时明确报错；同时传仓库和库区时校验归属，只传库区时也校验其所属仓库类型。
- 下拉选项仅列启用的仓库与库区；列表查询不增加启用状态限制，保留历史停用仓的查询能力。
- 前端 `src/frontend/src/api/inventory.ts` 为筛选选项传库存性质；`MaterialInventoryView.vue` 增加明确切换处理和选项请求版本校验。
- 原材料与半成品余额继续沿用现有独立库存账；该修正只影响筛选选项、查询校验和页签文案，不需要数据转换或数据库迁移。

## 开发与验收步骤

1. 修正后端筛选选项及参数校验，测试默认 RAW 兼容、SEMI 选项、非法类型、仓库与库区不匹配、权限和空库存。
2. 修正前端传参、切换重置、联动及过期请求保护，更新半成品页签名称。
3. 验收“原料布面仓已选 → 切半成品 → 旧条件清空 → 可选择裁剪布面仓”和切回原材料的完整往返；检查 1920 及窄视口，确认库存记录和单位未改变。
