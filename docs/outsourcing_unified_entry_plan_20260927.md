## 1. 已确认目标与当前事实

用户要求所有外发从一个“委外加工”入口进入、在同一个列表查看，进入单据后按实际来源显示操作。管材和其他材料继续采用各自单位、数量上限和库存规则。

当前代码及真实页面核查：

- 侧栏存在“委外加工”和“管材外发闭环”两个入口，委外列表右上还有后一入口。
- 普通外发单和金工首次外发原单已共用 `OutsourcingOrder`，当前普通列表已经包含两者，不能把金工原单再次添加而产生重复行。
- 退回重加工后的新外发单使用 `MetalProcessingExternalOrder`，在另一页面及接口中展示，需纳入统一列表。
- 金工工作台还有未成单来源、加工完成登记、来源备注结清、退回和重加工记录；只删除菜单会使这些操作无法找到。
- 尚未首笔发料或交接的原单不一定有持久化来源标记。不得依据“喷塑”工艺或管材名称推断其已从金工领过原料。
- 本轮实际1920×1080页面只读截图已保存，页面无错误、业务写入0；真实单据数量只作为本次观察，不写死在设计或正式页面。

## 2. 用户看到的变化

### 图1：一个入口、统一列表

- 侧栏仅保留“委外加工”，移除独立“管材外发闭环”菜单及列表右上同名跳转。
- 委外加工页内有“外发单”和“待外发材料”两个页签。前者统一看所有已建单据；后者处理未成单加工来源，也可查已交接完或已结清来源的历史。
- 外发单列表按单据显示。普通原单、金工首次原单及重加工新单分别只出现一次；保留多产品、多部位和多加工厂信息。
- 增加“材料来源”展示：仓库原料、金工加工件、重加工件、待选择。来源筛选允许只看某类，但默认看全部。
- 发出数量与合格回货各自携带单位，米、支、套不能相加或直接计算进度；多单位单据分项展示。
- 统一“新建外发单”入口，选择具体材料来源后进入相应录入操作；材料来源来自选择的真实记录，不增加手工“是否扣库”开关。

### 图2：统一详情，按单据来源显示操作

- 所有列表行从“查看详情”进入委外模块内的详情；标题和面包屑使用“外发单详情”，不出现“闭环”或开发阶段编号。
- 金工首次外发原单：登记交接、合格回货、未喷塑退回、待交取消、原单备注结清、结清后补登记都保留在单据内。
- 重加工新单：查看原退回和重加工来源，调整交接前分配、保留分配修改前后数量/操作人/时间，登记交接、合格回货、备注结清与结清后补登记，并保留查看半成品库存。
- 普通仓库原料外发：沿用原发料、回货及按现有状态可用的操作，不显示不适用的金工按钮。此处“现有操作”不代表新增报废或不良品功能。
- 退回与重加工通过详情中的记录区进入；重新创建的外发单回到同一列表，同时保留前后单关联。
- 加工完成登记、来源备注结清在“待外发材料”来源详情内办理；历史加工与来源结清记录仍可查询。
- 按现有权限、状态和数量上限显示可用操作，权限不足不能因为菜单合并而获得额外数据或动作。

设计图中的编号、日期和数量均为明确标记的示例，不是当前数据库记录，不创建真实单据。

## 3. 数量和库存规则保持不变

| 场景 | 继续沿用的处理 |
| --- | --- |
| 管材原料直接外发 | 按BOM换算整根及米数，实际发料时扣原料；不足或不满足整根规则时阻止 |
| 金工已领料的加工件外发 | 按支登记交接，原料已在领料时扣减，交接不重复扣根数和米数 |
| 重加工件再次外发 | 按新加工记录的可用支数分配与交接，不恢复原料或原来源额度 |
| 管材合格回货 | 按支增加对应部位合格半成品库存 |
| 面料外发与裁片回货 | 发出与扣料按米，裁片半成品回货按套；不把米与套作为同单位对比 |
| 其他材料 | 沿用各自现行单位和加工产出规则 |
| 备注结清 | 保留差额与备注，不虚增库存；结清后补登记沿用现有原因和数量校验 |
| 半成品领料 | 按既定部位和可用总量办理，用户不选择回货批次 |

本轮不做旧管材转换，不新增报废或不良品处理，不改已入库数量，不重建既有外发单或修改历史编号。

## 4. 最小实现边界

### 列表读取

新增统一只读查询，将普通外发与重加工新外发投影为同一列表结构。保留两种原业务模型与写接口，避免迁移历史数据。

- 每行使用“单据类型＋原始ID”作为稳定键；原单按原始ID去重。
- 按原有可见通道及组织/任务范围筛选后合并，再统一排序、搜索、筛选、分页与计数。普通原单与金工原单共表，不能简单地给每个模型只配一种权限：有普通查看权限时沿用普通原单范围；只有金工查看权限时，仍应通过可见金工来源获取其原单投影，字段与数量不得超出原来源接口已可见范围；两条通道命中同一原单时去重。不得先各取一页后在浏览器拼接并伪造总数。
- 列表统一展示现有状态含义，具体动作仍由原业务接口校验；不强行把自动完成和人工结清规则改成一种。
- 单据数量摘要按真实单位分组，发出量取实际发料/交接，计划量单独标识。待交接没有实际量时显示0或未发出，不以计划数量冒充实交。
- 多产品、多部位、多加工厂不拆成重复单据；缺失信息显示未记录，不伪造价格、工艺或来源。
- 重加工新单没有独立交货日期时显示“—”，原单日期只可作为明确标识的来源参考，不能冒充新单交期。
- 加工厂详情的“关联外发单”复用同一按加工厂筛选的聚合结果，避免主列表包含新单而加工厂关联列表遗漏。
- 列表只取摘要并批量加载关联资料；详情打开后再读取历史和库存上下文，避免逐行重复查询。

### 来源识别与创建

- 已原料发料：从实际发料关联识别仓库原料。
- 已金工交接：从实际交接关联识别金工加工件。
- 重加工新单：从原退回和重加工关联识别重加工件。
- 未首发原单：没有足够关联时显示“待选择”，进入实际发料/交接时选择真实来源。新建时预选来源只作为录入上下文，刷新后不得谎称已持久化锁定。
- 服务端继续禁止同一单混用原料发料和金工交接；以实际状态和关系复核，不信任前端类型标记。
- 本方案预计不新增表或迁移；若实施发现必须增加持久化业务字段，应先给出具体缺口及影响，再调整方案，不能暗中扩大范围。

### 路由与旧链接

- 统一主入口保留 `/workshop/outsourcing`。
- 普通单及金工原单保留既有ID与详情链接；重加工详情有类型明确的路由，避免ID误用。
- 原 `/workshop/outsourcing/metal-processing` 及其 `issue_id`、`production_task_id`、`product_line_id` 参数兼容跳转到统一入口的来源区域，并保留来源定位。
- 更新金工计划、生产领料等现有快捷入口；打开旧收藏链接仍能找到原单或来源。
- 侧栏权限取两类可见能力的并集，各页签和每笔数据再用各自原权限过滤。
- 金工原单收尾继续核对原单所有交接来源的可见范围；任一来源无权访问时，不放宽整单收尾权限。仅有普通查看权限者仍能看原有基础详情，不因额外金工接口拒绝而导致整页失败。

## 6. 验收清单

- 普通原单、金工原单、重加工新单各至少一个样例；金工原单不重复出现。
- 原单和新单交叉排序、跨页筛选、总数一致，零记录与接口失败有正确展示。
- 仅普通外发权限、仅金工来源/重加工权限、无权限和跨组织/任务访问均按原规则限制。
- 仅金工权限者既能找到合法的首次原单，也能找到重加工新单；跨范围来源不得借原单汇总泄露，原单整单收尾保留更严格的全来源门禁。
- 未首发原单显示待选择；真实首笔原料发料或交接后识别正确，混合路径被拒绝。
- 金工加工件与重加工件的交接不再扣原料，管材支/根/米与面料米/套显示和提交口径不变。
- 退回、重加工、备注结清、结清后补登记、取消待交等现有路径均能找到并正确刷新。
- 旧计划/领料链接和直接收藏链接仍可定位；有源记录但尚未成单时不会从页面消失。
- 正式代码变更后运行相关后端测试、前端类型检查/相关单测/构建；1920×1080及较窄视口浏览器验收，检查少量和超量数据、滚动、弹窗、加载、错误和权限状态。
- 涉及写操作的验证只在隔离数据库进行；真实页面以只读验收，未经本轮明确指定不操作现有业务单据。
