# 权限第三阶段：账号、角色与销售团队管理

日期：2026-09-28。依据[已确认的分阶段方案](erp_permissions_plan_20260928.md)与阶段 1 已确认页面、ERP `DESIGN.md` 实现。阶段 2 已获用户确认，本阶段待验收；阶段 4 尚未开始。

## 交付范围

- 权限管理四个分区：角色与权限、员工与账号、销售团队、授权记录。页面直接调用真实 Django API，未使用模拟业务接口。
- 423 项操作按业务模块展示。查看、新增、编辑、删除、提交、审批与专项操作分别配置；只有实际存在的操作才可配置。每项操作独立选择本人、所管团队、本人及团队或全部；非销售模块使用模块范围。
- 角色默认无权限，支持新建、修改、复制、停用和恢复。保存前展示变更前后范围和影响人数；恢复角色的影响人数包含保留的有效期内分配。
- 员工沿用现有档案，可关联独立账号、分配多个角色、重置密码、启停账号，查看有效角色授权及历史直接/分组授权来源。管理账号受保护；不批量修改旧账号。
- 销售团队由管理员创建，可跨部门添加成员；数据库约束保证一名员工只属于一个团队。团队客户经理创建后不可改，成员换团队不在本轮范围内。团队身份不自动提供业务操作权限。
- 授权记录展示操作人、时间、对象、变更前后内容。密码正文不进入响应或审计。
- 移除前端固定管理员自动登录。旧开发自动登录接口始终返回 404，旧开发开关不能恢复免密登录。正常账号密码登录继续沿用 Session 与 CSRF。

## 一致性与账号安全

已有对象的写操作使用 `If-Match` 防止覆盖他人修改；冲突会提示重新加载。角色草稿未保存时阻止切换角色、管理分区和离开路由，刷新前提示。写请求不自动重试。

停用普通账号时，在事务内撤销其现有数据库 Session；重新启用不会恢复旧会话。正常登录与停用使用同一个 User 行锁，锁内重新核验账号和密码、保存 Session，避免并发登录绕过撤销。密码重置使用 Django 密码校验与散列，旧密码和旧 Session 失效。审计与业务变更处于同一事务。

员工账号、团队、角色管理 API 仍仅允许有效的 `admin` 超级管理员及其有效员工档案。普通账号直接访问页面显示无权限，直接调用 API 被拒绝。

## 设计落实

沿用现有 ERP 外壳与 `PageContainer`，单层 14px 内边距；页面标题 Noto Serif SC 34/44，正文沿用项目字体。输入框与按钮高 32px，复选框 14px，表头 44px、数据行 40px；颜色、强标签使用现有 CRM SCSS tokens。窗口复用 `AppWindowDialog` 的拖动、缩放、最小化与最大化能力。

浏览器验收使用 Chrome、1920×1080，证据位于 [QA 目录](../qa/permissions_stage3_20260928/)。界面中的“验收”账号、角色与团队只存在于独立测试数据库。

## 数据库与启用边界

新增迁移 `access_control.0003_sales_teams`，仅创建 `access_sales_team` 与 `access_sales_team_membership` 两张表；员工成员字段为 OneToOne，客户经理和成员引用现有 Employee。本阶段没有在正式业务数据库执行该迁移或角色初始化。

独立 QA 使用 `config.access_preview_settings`，固定数据库名 `test_haiqu_access_stage2_20260928`，独立 Cookie 和媒体目录，绑定本机 QA 端口。测试账号密码仅写入被忽略的 `.tmp` 文件。不得把该配置用于正式启动；测试数据库运行浏览器验收期间不得同时运行会清空它的 Django 测试。

正式数据库只读检查结果：仍为 10 个账号、44 名员工、0 个角色、0 个授权组、0 条角色分配；新权限表不存在、迁移未执行，`ACCESS_MANAGEMENT_ENABLED=false`，admin 保持有效超级管理员。证据：[只读核对结果](../qa/permissions_stage3_20260928/main_readonly_evidence.json)。

**本阶段完成管理能力，不代表销售和生产业务接口已执行新范围。** 销售业务入口在阶段 4 接入，其他业务模块与自审限制在阶段 5 接入，整体验证与主库启用在阶段 6。当前不能把普通员工投入使用作为权限已隔离的正式环境。

企业微信绑定、通讯录接入、客户及单据转移、字段级权限继续不在本阶段范围；独立财务项目没有改动或关联。
