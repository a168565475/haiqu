# ERP 权限使用说明

适用范围：已实现的 ERP 权限管理与业务授权。企业微信实际登录、通讯录同步和客户转移功能不在本轮交付范围。

当前启用状态（2026-09-28）：权限管理已开放，20 个空角色已创建；销售及其他业务范围限制仍关闭。下面的数据范围和禁止自审说明用于整体权限启用后的操作。配置准备期间，给员工分配角色可能经旧授权机制增加操作能力，不能把“本人/团队”当作已经生效的隔离边界。实际启用范围见 [记录](permissions_management_activation_20260928.md)。

## 管理入口与账号

用网页端 `admin` 登录，在“系统配置 → 权限管理”中维护。权限管理仅开放给有效的 admin 超级管理员，并要求关联在职员工档案。其他账号是否为超级管理员，不代表可以管理授权。

员工使用独立登录账号；管理员可在“员工与账号”中为已有员工创建账号、重置密码、启停账号及分配角色。不会根据名字自动合并员工，也不会自动删除历史账号。账号停用会使原会话失效，重新启用后需要重新登录。

以后接企业微信时应绑定已有员工主键，继续复用本套角色和数据范围；本轮没有接入企业微信。

## 配置角色

20 个目标角色仅补建为空角色，名称不自动带来任何权限。一个员工可以有多个角色；权限按同一种操作取并集。例如“团队查看”加“本人编辑”，只会获得团队查看及本人编辑，不会获得团队编辑。

1. 选择角色，勾选该模块需要的查看、新增、编辑、删除、提交、审批或专项操作。
2. 销售操作分别选择本人、所管团队或全部；生产等模块使用按模块授权。样品允许选择销售范围或生产模块范围。
3. 保存前核对实际变化和影响人员；若提示版本已变化，刷新后重新审阅，避免覆盖另一位操作者的配置。
4. 在员工页分配角色，并查看有效权限及授权来源。未授权操作在后端会被拒绝，隐藏按钮只是界面提示。

“查看”不等于“编辑”，“编辑”不等于“审批”或“完成”。例如采购合同模板、供应商采购单、生产订单完成、任务完成/改期、字典启停/归档、样品费用审批和报工均有对应操作。

“个人保存视图”另有查看、新增和编辑权限，只允许“本人”范围。保存的是个人列表筛选与列配置，不会扩大业务数据权限；即使 admin，也不能读取其他员工保存的个人视图。没有此权限时，任务中心仍可按任务权限正常使用。

## 数据范围

- 客户、询盘、报价、订单统一按客户当前主负责人判断归属；不按单据历史业务员字段另算一个归属。
- “本人”只含当前员工；“所管团队”依据 ERP 手工销售团队的成员，经理自身数据需同时勾选本人。“全部”必须显式授权。
- 销售团队独立于企业微信部门。一个员工只能加入一个销售团队，本轮没有换团队入口。
- 生产按所分管模块授权。必要的客户或单据来源摘要用于完成业务，并不代表可以打开跨模块的完整记录。
- 样品仅报工人员可填写报工数量、完成情况及允许的说明，产品、客户和打样数量仍受原有编辑状态限制。

历史单据缺少客户当前主负责人时，本人/团队范围不会猜测归属；由有权管理员核实，本轮不自动回填。

## 审批与撤权

提交人不能审批自己本次提交的记录，admin 也遵守这条业务规则。指定审批人、数据范围和单据状态仍同时生效；拥有审批权限不保证能审批任意记录。无法核实提交人的旧记录需要重新提交。

角色权限变更、移除角色、停用角色或团队，会在后续后端请求重新检查。旧页面可能仍暂时显示按钮，但不能绕过服务端检查；刷新页面可看到新状态。

系统保留历史独立直授、分组及旧角色授权。因此移除新角色后，如果员工仍能操作，应先查看“有效权限”的历史来源。含历史权限或原生组成员的旧角色会拒绝直接覆盖，需要先审阅旧授权，不能靠改角色名字或重复保存清除。

## 常见提示

| 提示 | 处理 |
| --- | --- |
| 没有权限 / 记录不可见 | 核对对应操作、该操作的数据范围、客户当前主负责人及员工状态 |
| 缺少版本或版本已变化 | 重新加载最新记录，不重复提交旧页面内容 |
| 不能自审 | 换由具备权限且符合指定处理人及范围要求的其他员工审批 |
| 权限管理尚未启用 | 需要先完成正式库迁移及开关启用；测试截图不代表正式库已经启用 |
| 权限已撤销但仍可操作 | 检查是否仍有其他角色或历史独立授权；后端按多来源并集判断 |

页面样式沿用已确认的 `DESIGN.md` 和权限管理原型；本说明不替代原有业务操作流程。
