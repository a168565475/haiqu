## 1. 交付目标及范围

按用户确认的 `2026-09-15-r2` 原型实现 P01–P08：主排产列表、选择生产任务单弹窗、新增排产、计划详情、金工/裁剪/车缝/装配四个计划。交付必须同时通过真实业务校验和逐页视觉验收，不能以编译成功、原型截图或 Mock 演示代替。

数据库使用[主订单排产数据库设计 V1](database/production_scheduling_database_design_v1_20260915.md)的三张表，与[委外数据库设计](database/outsourcing_database_design_v1_20260915.md)共用 S01–S03。一张任务单最多一张有效计划、多产品一次提交、每产品独立数量/日期/工艺、不分批排产。数量沿用来源任务产品单位；保存计划不改变库存、采购、BOM、生产执行批次或自动开工。

本方案已按确认规则落地。下文的接口、组件、迁移与测试文件均已实现；完成状态以第 10 节的本地验证证据和明确未执行项为准。

## 5. 后端实施方案

技术栈保持 Python 3.13、Django 5.2、DRF、PostgreSQL 17，登录使用 Session + CSRF。

### 5.1 拟新增/修改文件

拟新增 `src/backend/apps/production_scheduling/`：

- `models.py`、`migrations/`：数据库稿的 S01–S03、条件唯一、外键、行内检查及必要跨表保护。
- `services.py`：建单、合法维护动作、任务锁、数量/来源检查、幂等与审计。
- `selectors.py`：带数据范围的列表、候选、详情及四计划查询，避免关联工艺造成重复行。
- `api/serializers.py`、`views.py`、`urls.py`：请求/响应契约、权限、状态码、分页及 OpenAPI。
- `tests/`：规则、接口、并发、迁移及权限验证。

最小接入点：应用设置、主 API 路由、Craft.plan_category、任务单产品编辑服务、权限配置。保留所有已有未提交改动，不重写项目原路由或全局样式文件。

### 5.2 拟定接口契约

以下路径均为开发建议，当前尚不存在；沿用项目 `/api/v1/` 前缀及现有分页结构。

| 方法与路径 | 用途及关键字段 |
| --- | --- |
| GET `/production-schedules/` | 主计划分页；关键词、客户、创建日期；返回单号、任务/销售号、客户、产品概览、四类日期范围、创建人/时间 |
| GET `/production-schedules/task-candidates/` | 当前已确认且在数据范围内的任务；返回产品摘要、按单位数量汇总、selectable、不可选原因、existing_schedule_id |
| GET `/production-schedules/task-candidates/{task_id}/` | 读取任务基本信息、产品详情及来源摘要；不是前端凭搜索结果拼出详情 |
| GET `/production-schedules/options/` | 可选工艺、分类、允许的筛选参数等；工艺使用真实 ID、类型和状态 |
| POST `/production-schedules/` | 请求 UUID、来源任务及摘要、每产品数量/四日期/厂内外工艺；整单原子保存 |
| GET `/production-schedules/{id}/` | 历史快照、产品及工艺、实时来源状态、版本/ETag、关联四计划链接条件 |
| GET `/production-schedule-items/` | category=METAL/CUTTING/SEWING/ASSEMBLY；计划/产品/日期等筛选，分页产品明细 |
| PATCH `/production-schedules/{id}/` | 仅 Q5 确认允许编辑时开放；If-Match 必须，不能换源任务 |
| POST `/production-schedules/{id}/void/` | 仅 Q5 确认允许作废时开放；原因、版本及委外引用保护 |

单头日期范围按产品的同一日期字段分别取最早/最晚；缺失不造日期，同一天只显示一个日期。产品单位各自返回，不能把整单数量强行统一为套。P01 显示全部产品摘要所需的信息；超出原型示例容量的展示须按节点交互核对，不能裁掉数据或擅自堆高行。

尺寸响应建议 `dimensions.expanded`、`dimensions.folded`、`dimensions.source`，仅在明确来源后填写，否则为空；不从价格、BOM 或名称猜测。候选中“已有计划”可看不可选，并不放宽 POST 的一单一计划规则。

参数错误返回字段/产品行定位；冲突返回可读原因及已有计划 ID（有访问权限时）；428/412 沿用项目 If-Match 语义。所有下拉候选、详情、导向链接都检查员工和任务数据范围，不能只在列表筛选。

### 5.3 核心服务校验

1. 当前 READY、未归档，产品确实属于所选任务；保存阶段重新检查。
2. 锁任务及相关产品，用条件唯一保证一任务一有效计划。先处理已成功的同请求重试，再判断是否可新建。
3. 正整数且不超过对应产品当前数量；无旧容差扩展，不允许产品之间相互抵扣。
4. 日期/工艺必填按 Q4/Q6 最终答复；新选工艺必须有效，分类映射不能按名称模糊猜测。
5. 任一产品失败整单回滚；子表变化更新单头版本和 updated_at，旧 ETag 不能覆盖。
6. 主计划保存不调用实际开工、库存、采购服务。委外只引用计划，不重复创建来源表。
7. 任务减量/替换/删除须检查排产和委外历史；未发料/已发料引用按数据库稿保护，不级联取消或改写。

## 7. 真实业务验证方案

沿用数据库稿 P-T01–P-T28，覆盖建单、单任务唯一、并发、幂等、数量/来源、工艺分流、单位、源单变更及无额外库存副作用。

接口/前端额外覆盖：

- 候选中有计划行禁选但可打开原计划；其他员工不可借 ID 越权读取或保存。
- 保存成功刷新仍可见；详情与四个计划数据一致，列表分页总数不因多工艺/多产品重复。
- 批量填写后可逐产品改日期/工艺，未选行不变。
- 创建/编辑失败定位到具体产品和字段，保留输入；网络重试不产生新计划。
- 无图片/销售关联/尺寸时按缺失显示，不硬编码图纸示例。
- Q5 未确认或未开放时，不出现可执行的编辑/作废入口；不存在的功能不得显示成功提示。

并发测试使用独立连接和事务测试，不能只在一个事务里顺序调用两次假装模拟竞争。数据库直接写入保护单独测试；API 权限测试独立于 UI 按钮是否隐藏。

视觉比对使用独立测试环境、经 API 建立的确定性测试数据，保持与参考画面同样的产品数/文本长度/图片；正式页面代码不写死这些样例。另用真实格式、长文字、多产品和缺失资料的数据覆盖边界。不得直接向正式业务库导入演示工厂、订单或任意执行迁移。

## 8. 视觉验收执行方法

### 8.1 基准准备

1. 读取对应技能及真实 Figma 节点，提取位置、宽高、字体、填充、描边、圆角和组件状态；导出缺失的交互截图。
2. 参考截图及节点属性只读冻结，记录 SHA-256、节点 ID、版本。改实现后不能覆盖基准来让差异消失。
3. 登录正式应用的测试环境，在真实业务路由进入页面。固定浏览器版本、1920×1080、DPR=1、100% 缩放、字体和参考数据。等待字体/图片/请求稳定，关闭动画与光标闪烁后采图。

### 8.2 每个画面的证据

每个主画面及交互状态都生成以下材料，写入本次验收输出目录：

- `actual/{case_id}.png`：真实应用截图。
- `diff/{case_id}.png`、`overlay/{case_id}.png`：与冻结基准同坐标对照及半透明叠图。
- `metrics/{case_id}.json`：元素边界、行高、列宽、字号/行高/字重、颜色、边框、标签、弹层位置和溢出测量。
- `results.json`：通过/失败、差异定位、整改及复测信息；版本与真实入口记录齐全。

图片像素差异用于定位，不单靠全图相似度判定通过。建议几何偏差不超过 1 CSS px，关键高度必须匹配 32/24px 及页面例外；颜色、字体、字重按计算样式和节点匹配。文字抗锯齿的小差异单独注明，不能掩盖字号、列宽、布局或对齐错误。

截图中业务数据不同产生的差异必须有明确范围；优先对齐测试数据，禁止遮罩整个产品区、表格或表单来绕过验收。单据动态 ID/时间的有限遮罩需要在报告列出，功能测试仍核对真实值。

### 8.3 必查项目

| 项目 | 判定要求 |
| --- | --- |
| 壳层和空间 | 侧栏、顶栏、标题、内容宽度、背景、筛选与表格间距对应基准 |
| 表格 | P01 60/112px 例外；其他按各自节点；列序/列宽、图片、边框、对齐、分页一致 |
| 文字 | 主次颜色、字号、行高、字重完整核对；缺失样式不能用相似灰色顶替 |
| 标签 | 普通 24px，P04 28px，P01 日期标识 20px；颜色、宽度、圆角和反白文字按对应基准 |
| 表单 | 输入框背景、内外高度、间距、只读态；P03 工艺摘要不变 Tag 堆叠 |
| 弹层 | P02 左侧汇总紧凑、按钮不被裁；各工艺/日期/批量面板位置、尺寸、内容及滚动正确 |
| 详情 | P04 边框/分隔线齐全、13/16px 信息层级、相关计划蓝色及箭头 |
| 滚动 | 页面无横向滚动；表格横向滚动在容器内；纵向滚动后按钮和最后一行可到达 |
| 交互 | 筛选、选择、取消、保存、刷新、分页、返回及相关计划跳转可实际操作 |

视觉不是只看首屏截图。每页还覆盖加载、空数据、筛选无结果、接口错误/重试、无权限、长文字、缺图、悬停、焦点、选中和禁用；不适用的功能明确标记原因，不能伪造通过。没有对应参考的通用异常状态使用最新设计系统组件；若必须改布局或加业务操作，先出具体差异再确认。

1920×1080 为正式基准。1440×900 仅在兼容范围需要时检查折叠侧栏与表格内滚动，不另造一套设计；短窗口检查可访问性，不强行把布局缩放到一屏。

### 8.4 缺陷整改与通过门槛

发现差异 → 记录页面/控件/实际值/基准值 → 修复 → 重拍本页及受同组件影响状态 → 更新结果。不得为了达标修改基准、放宽整个表格尺寸或跳过失败画面。

全部适用视觉项通过、业务用例通过、无页面错误、无按钮不可达/文字遮挡/数据裁切，才报告“开发完成并通过视觉验收”。原型的 70 画面历史审计、当前 13 张参考哈希一致、前端 build 成功，都不能单独满足这个条件。
