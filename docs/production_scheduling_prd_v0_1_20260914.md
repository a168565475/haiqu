## 1. 目标与范围

基于已经确认的生产任务单，建立生产排产主计划；同一计划支持一次安排多个产品，并按产品选中的厂内工艺，在金工、裁剪、车缝、装配四个计划中查看相应数据。

本期做到“能排产、能查看排产”。这是人工填写数量和计划节点的排产台账，不计算设备或员工产能，也不保证填写的交期一定可实现。

| 本期包含 | 本期不包含 |
| --- | --- |
| 从已确认生产任务单发起排产 | 自动排程、设备负荷、人员班次、工时计算 |
| 每张生产任务单仅一张有效主计划，可一次安排多个产品 | 跨生产任务单合并排产、分批／分次排产 |
| 填写数量、四个计划日期、厂内／厂外工艺 | 工序拆解、派工到员工、扫码报工、计件工资 |
| 保存、查看主计划 | 生产进度、完工申报、质量检验 |
| 按指定工艺查看四个计划 | 委外发料、委外订单、供应商交接和结算 |
| 数量、来源、工艺有效性校验 | 自动采购、库存占用、领料、实际入库 |

本期不做分批／分次排产。编辑、作废仍属于待确认的维护规则，见第 3 节；对应建议不能当作已确认开发范围。

## 2. 已明确需求与当前项目事实

### 2.1 本轮明确需求

1. 已确认的生产任务单可以生成排产计划。
2. 一张排产计划对应一张生产任务单；本期每张生产任务单只允许一张有效计划，同单多个产品可以一次排产，不做分批／分次排产。
3. 排产时显示订单与产品基础信息。
4. 填写材料入库时间、金工回货时间、车缝回货时间、成品入库时间。
5. 厂内、厂外工艺分别从工艺资料中多选。“外内”按上下文理解为“厂外”。
6. 每个产品的排产数量不能超过来源生产任务单对应产品行数量，不以销售订单整单数量作为上限。
7. 厂内工艺决定四个计划的可见数据；具体映射见第 8 节。
8. 裁剪计划和车缝计划均显示车缝回货时间，保留原需求，不新增裁剪完成日期。
9. 四个计划日期、厂内工艺、厂外工艺按每个产品分别填写，支持批量填入相同值。

### 2.2 只读核对得到的事实

| 当前事实 | 对本次方案的影响 |
| --- | --- |
| 生产任务单有草稿、待校验、已确认、生产中、暂停、完成、取消等状态；已确认为 `READY` | 新建排产使用明确的状态条件，不能用“曾确认过”替代当前状态 |
| 一张生产任务单有多条产品明细；数量为正整数 | 排产必须关联具体明细行，避免同款不同颜色或规格串量 |
| 产品行已有编号、货号、名称、规格、图片、颜色、数量和单位等数据 | 优先带入任务单保存的信息，不要求重复填写 |
| 已有生产任务单号、合同编号、来源销售订单号等不同字段 | 页面明确区分生产任务单号与销售订单号，不能混用 |
| 工艺已有厂内／厂外、启用／停用分类；厂内工艺关联车间 | 工艺选择可以复用现有资料结构 |
| 当前固定车间包含金工、车缝、装配、敲布孔；没有独立裁剪车间 | 裁剪计划根据“裁剪”工艺筛选，不能要求先新增裁剪车间 |
| 五个现有排产路由均指向占位页 | 本期需要新建排产数据与查询能力，入口存在不等于业务已实现 |
| 现有 PMC 确认维护计划开始、计划完工等字段；现有开工动作另有 BOM 和订金条件 | 新增四个日期需明确用途；保存排产不得直接触发开工 |
| 现有生产批次对象包含实际数量、合格数量等执行字段 | 本期主计划不自动创建或修改这些执行记录 |

验证边界：上述为当前源码与现有 PRD 的核对结果。本次未查询真实数据库，未核实当前工艺记录的具体 ID、实际订单数量及在用状态，未执行真实业务验收。用户所述订单、采购、材料仓库已有功能作为业务背景，不据此宣称整条链路已通过验收。

### 2.3 与既有规则的衔接

- 旧生产／采购 PRD 中的“数量容差”不自动扩大本期排产额度。本轮明确要求不超过来源产品数量。
- 排产时间表示计划日期，不表示材料已经入库、金工已经回货或产品已经完成。
- 推荐排产只要求来源任务单已确认，不增加 BOM、订金、材料齐套条件；实际开工继续遵守现有开工规则。此项作为待确认的衔接建议。
- 旧项目协作文件中“生产不在当前阶段”的范围描述，由本轮明确提出的生产排产 PRD 请求限定扩展；不据此扩展到执行管理。

## 4. 业务对象和责任

已确认关系：生产任务单 → 至多一张有效排产主计划 → 多条产品排产明细 → 按工艺查询的四个计划。

| 对象 | 定义 |
| --- | --- |
| 生产任务单 | 本次排产的来源，带入生产要求、产品和数量 |
| 排产主计划 | 一次提交形成的计划单，只能关联一张生产任务单 |
| 产品排产明细 | 关联来源任务单的一条产品行，保存本次数量、日期和工艺 |
| 四个计划 | 主计划产品明细的不同查询视图，共用同一数据来源，无需再次排产 |

建议 PMC／计划人员负责录入和维护，车间负责人负责查看，业务跟单查看自己被允许访问的订单计划。此处为责任建议：沿用项目现有登录和数据访问规则，不自动增加新的角色审批或绕过原有访问限制。新增操作权限如何配置，应在开发方案中核对现行规则后确认。

员工和工序资料本期不参与排产计算，也不生成员工任务；已有资料不意味着需要在本期强行使用。

## 5. 业务流程

1. 从“生产车间 → 计划排产”点击“新增排产”，选择当前已确认、未归档且没有有效排产计划的生产任务单；已有计划时提供查看原计划入口，禁止重复新建。
2. 读取任务单基础信息与全部产品行，展示各行订单数量和排产数量上限。
3. 选择一个或多个产品，填写本次排产数量、四个计划日期以及厂内／厂外工艺。
4. 同单多个产品日期或工艺一致时，可以批量填入，再逐个调整。
5. 点击“保存排产”；服务端重新检查是否已有有效计划、来源状态、产品归属、数量上限、日期和工艺。
6. 全部明细校验成功后，整张计划一次保存，生成唯一排产单号。
7. 主计划列表显示该计划；四个计划立即按工艺显示相应产品明细，刷新后仍可查询。
8. 点击排产单号查看详情；符合 Q5 的已确认维护方案时，允许编辑或作废。

推荐不增加独立审核、发布、接单或完工动作。“保存排产”即成为可查看的有效计划。若需要草稿或审批，应另行定义，避免把未确定内容混入本期。

## 7. 数量、日期与保存规则

### 7.1 数量规则

按已确认的 Q1、Q2 执行：

> 每张生产任务单最多一张有效排产计划；每条产品明细满足：0 ＜ 排产数量 ≤ 来源生产任务单对应产品行数量。

新建时，来源任务单已存在有效计划则拒绝创建，不能通过改选另一产品绕过限制。同一来源产品行在同一计划中只能出现一次。若 Q5 确认允许编辑，应更新原计划，并校验修改后的数量，不生成第二张有效计划。

示例：来源 A 产品 1000 件，本计划填写 600 件符合数量上限，但不能另建计划补排其余 400 件。若 Q5 允许编辑，可在原计划中调整数量；若选择保存后锁定，则本期无法补足。暂不做分批排产不等于必须排满，仍保留用户明确的“不超过”上限规则。

- 订单数量等于本次数量时可以保存；0、负数、小数、空值、非数字均不可保存。
- 多产品逐行校验上限，不允许用 A 产品未排数量抵扣 B 产品超排。
- 若 Q5 确认允许作废重建，应先作废整张旧计划并保留记录，再新建唯一有效计划；这是替换原计划，不是叠加生产批次，也不代表返库或冲销产量。该维护方式尚未确认。
- 一个产品被四个计划同时显示，仍只占用一次排产额度；四个列表数量不能相加作为总产量。
- 单位不同的产品不做无单位合计，主计划列表优先展示产品行数，数量按单位分别汇总。
- 同时提交、重复点击或网络重试不能形成两张有效计划。必须在服务端锁定来源任务单、事务校验，并通过数据库唯一性约束保证一单一张有效计划，不能只靠前端限制。

### 7.2 日期规则

- 日期必须可解析且真实存在；必填规则由 Q4 决定。
- 推荐金工和车缝不强制先后，实际可能并行；不要硬编码为四个日期严格顺排。
- 成品入库早于材料入库、金工回货或车缝回货，或晚于订单交货／PMC 计划完工时，给出明确风险提示；推荐本期不自动改日期、不新增审批。
- 推荐允许历史日期以支持补录，并提示“计划日期早于今天”；不将历史计划自动认定为逾期未完成，因为本期没有实际完成数据。
- 选择 Q4-B 时，不适用日期显示“—”；被某个计划引用的日期必须填写，例如进入裁剪计划必须填写车缝回货时间。

### 7.3 来源和工艺规则

- 以当前状态 `READY` 作为本期新建排产入口；保存时再次核对。草稿、待确认、生产中、暂停、完成、取消、归档均不新增排产，例外需另外确认。
- 不能加入来源任务单之外的产品，也不能把两个任务单拼成一个主计划。
- 工艺按真实记录 ID 保存，并保存当时的名称、类型和计划分类，避免后续改名导致历史列表突然消失。
- 分类映射必须绑定明确的工艺记录，不能用名称包含“车缝”等模糊匹配，也不能从工序名称猜测。
- 正式启用前只读核对“管材加工、裁剪、车缝、装配/包装”对应的厂内工艺记录。缺失或名称不一致时列出缺口，不能擅自新建或修改基础资料。
- 工艺停用后不可新选；已保存计划继续展示历史选择并标注停用。提交时新选工艺若已经停用，阻止保存并提示重新选择。
- 未映射到四个计划的其他工艺仍可保存在主计划中；不擅自归入某个列表。仅选厂外工艺时不进入四个厂内计划。

### 7.4 保存与异常恢复

多产品保存必须全部成功或全部失败。失败时定位错误产品和字段，保留表单输入；不得出现主计划已保存但部分产品丢失。保存中阻止重复点击，网络结果不明时通过本次请求标识核对是否已生成单据。

编辑使用项目现有版本冲突机制：他人已修改时提示重新加载，不能直接覆盖。离开未保存表单时提示保存或放弃。来源任务单在录入期间发生状态或产品变更时，阻止旧表单提交并要求重新核对。

## 8. 四个计划的查询规则

这是本期已经明确的分流规则；“装配/包装”为待核对的工艺名称整体，不擅自拆成两个工艺。

| 列表 | 纳入条件：该产品明细的厂内工艺包含 | 必须显示的日期 |
| --- | --- | --- |
| 金工计划 | 管材加工 | 金工回货时间 |
| 裁剪计划 | 裁剪 | 车缝回货时间 |
| 车缝计划 | 车缝 | 车缝回货时间 |
| 装配计划 | 装配/包装 | 成品入库时间 |

共同列：生产任务单号、来源销售订单号、排产单号、产品图片、编号／货号、名称、规格、颜色、排产数量、单位，以及本列表指定日期。

推荐一个列表行对应一条主计划产品明细。同一产品选择多个厂内工艺，可出现在多个列表；同一明细在同一列表只显示一次。本期不产生同一任务单的分批计划；不同任务单中的同款产品分别展示，并用生产任务单号和排产单号区分。

四个列表仅查看；不独立编辑数量、日期和工艺。Q5-A 生效时，统一回主计划编辑，所有列表按保存后的数据同步更新。移除厂内工艺后，该明细退出对应列表；作废后退出默认有效计划列表，历史仍可追溯。

## 9. 查询与页面状态

| 页面 | 最小查询能力 | 默认展示建议 |
| --- | --- | --- |
| 主计划列表 | 排产单号、生产任务单号、销售订单号、客户／产品关键词 | 创建时间倒序，一行一张主计划，可展开产品明细 |
| 四个计划 | 订单号、排产单号、产品关键词、本列表日期范围 | 对应日期升序，再按排产单号、产品行号稳定排序 |

列表需要分页；查询和数量汇总以服务端完整数据为准，不能只筛选当前页。主计划日期不强行合并成单一日期，展开产品行展示；必要时可显示最早至最晚范围。

页面应区分：加载中、暂无计划、筛选无结果、工艺资料加载失败、无可排产品、来源已变更、无访问权限、保存失败。日期无值的展示仅在 Q4-B 允许；空数据不能显示为已完成。

推荐主计划只显示“有效／已作废”等计划记录状态（作废取决于 Q5），同时展示来源生产任务状态。不要把“排产中”作为实际生产进度状态；本期没有足够数据证明已开工、进行百分比或已完成。

## 10. 已保存计划与上游变更

以下为维护建议，需要随 Q5 一并确认：

- 基础资料改名时保留计划当时快照，不静默改变历史要求。
- 来源任务单产品、数量或关键要求变更时，计划显示“来源已变更，待核对”，保留原数据，阻止继续编辑保存直至使用当前版本核对。
- 来源产品数量减少到低于有效计划中该行排产数量时提示超排冲突，不能自动截断数量、删除明细或认为已完成。
- 来源任务单取消、归档、暂停或完成时，保留计划与记录；四个列表显示当前来源状态。取消／归档默认从有效执行查看范围排除，历史查询可见；暂停显示明显标记。完成表示来源任务完成，不代表本系统核实了各计划实际完成时间。
- 保存计划不改变来源任务单状态、BOM、采购单、库存或已存在的生产执行批次。

## 11. 最小数据设计建议

本节用于后续设计评审，不是已经存在的接口或数据库结构。

| 数据对象 | 必需信息 |
| --- | --- |
| 主计划 | 唯一 ID、排产单号、来源生产任务单 ID、来源版本、计划记录状态、创建／更新人员与时间、版本号；若允许作废，增加作废原因和时间 |
| 产品明细 | 主计划 ID、来源任务单产品行 ID、产品基础信息快照、本次数量、单位、四个日期 |
| 明细工艺关联 | 产品明细 ID、真实工艺 ID、厂内／厂外类型快照、名称快照、对应计划分类 |
| 操作记录 | 创建、修改、作废的操作者、时间及变更前后内容 |

四个计划从上述同一组数据查询，不复制成四套可独立修改的计划单。数据库必须限制同一生产任务单最多一张有效计划，并限制同一计划内来源产品行不重复；整单保存失败时不留孤立明细。

沿用现有 Vue／Django 技术栈、登录方式和事务／版本校验方式；不为本期引入排程引擎、新消息系统或新的生产执行模块。

## 13. 验收清单

以下是开发后的验收要求，本次仅制定清单，未执行系统测试。涉及待确认方案的项目在业务选项锁定后同步修订。

| 编号 | 场景 | 预期结果 |

| AC24 | 刷新、翻页、按号和日期筛选 | 数据持久保存，筛选结果和总条数一致 |
| AC25 | 无图、无工艺、网络失败、无权限 | 显示对应状态，不伪造数据或成功提示 |
| AC26 | 多产品不同单位 | 不展示混合单位的无意义数量总计 |
