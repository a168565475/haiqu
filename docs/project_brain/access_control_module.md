本卡记录角色、员工账号、权限、数据范围和基础资料设置的当前技术边界。权限配置能否在页面上看到，不等于后端业务接口已经按同样范围执行；最终判断必须回到 API 权限类、服务端数据筛选和运行测试。

## 1. 负责范围

- 角色、角色授权、员工角色分配和员工账号状态。
- 模块/操作权限、本人/团队/全部数据范围。
- 指定车间、指定外协工艺等资源范围。
- 销售团队及成员关系。
- 系统偏好和国家、币种、单位、产品、生产等基础资料入口。
- 权限变更、角色复制、账号操作和授权历史审计。

## 2. 当前代码事实

- `RoleActionGrant` 以角色、权限和范围保存授权；范围包括 `OWN`、`TEAM`、`ALL`、`MODULE`、`WORKSHOP`、`CRAFT`。
- 车间和外协工艺资源通过 `RoleGrantResource` 单独绑定；空资源选择代表没有该资源访问，不应被解释成全部资源。
- 权限目录使用明确的业务权限白名单和隐含权限关系，不直接把所有 Django 权限暴露给管理员。
- 角色授权保存前会校验权限、范围、资源类型和重复项；修改角色与授权使用 ETag，并记录审计。
- 系统避免覆盖历史直接授权或原生用户组成员；检测到投影差异或原生成员时，会要求先审阅。
- 员工可分配多个有效角色，但不能重复分配或分配停用角色；角色有效期和历史分配有数据库约束。
- 权限管理 API 的管理者限制为启用的 `admin` 超级管理员；功能开关未启用时返回“权限管理尚未启用”，不是静默放行。
- 前端权限管理页包含角色与权限、员工与账号、销售团队、授权记录；页面隐藏只改善体验，不替代后端校验。
- `resource_scopes` 和模块权限有分阶段开关；开关关闭时不能把资源范围选择写成已经生效。

## 3. 基础配置边界

- `reference_data` 维护国家、币种、产品/生产资料、单位、客户等级等可复用字典和快照来源。
- `preferences` 维护系统偏好设置；询盘处理时限、主题等页面设置有独立 API 和权限。
- 基础资料停用、发布或快照与业务单据引用是不同动作；停用不能直接删除已经被业务记录引用的事实。
- 汇率、信用、成本、毛利、销售 SLA 等业务政策不能因为存在字典或设置页面就视为已经制定，仍按 D-030、D-031、D-053、D-054、D-055 执行。

## 4. 与业务模块的关系

- 业务模块通过 `BusinessActionPermission`、`HasActiveEmployee`、模块策略和资源范围过滤访问；前端菜单隐藏不能替代这些后端门禁。
- 客户、询盘、报价、样品、采购、库存、生产和委外可以定义自己的操作权限与数据范围，但不能在页面上自行绕过统一权限服务。
- 销售团队和负责人影响客户/询盘/销售订单的可见范围；技术上的负责人筛选口径必须和业务模块实际查询一致。
- 指定车间和外协工艺范围只适用于对应模块；不能把 `WORKSHOP` 或 `CRAFT` 作用域扩大到不支持该资源类型的权限。
- 根据 D-084，询盘查看者可以看到关联样品摘要和样品是否存在；这不授予样品编辑权限，也不等同于完整样品详情权限。当前关联样品摘要未复用样品对象范围筛选，因此应保留摘要，但继续核对详情跳转和写入动作的样品权限门禁。
- 询盘列表的“是否存在进行中样品”布尔字段属于 D-084 明确允许的摘要信息；完整样品字段、详情页和样品操作仍不能因该决定自动放开。
- 根据 D-085，样品库存、出库和借出记录按模块权限全员共享，不按客户或负责人范围筛选；但查看权限不自动包含创建、确认、归还或编辑等写入动作权限。

## 5. 当前缺口与风险

- 权限管理开关、资源范围开关和历史迁移状态可能影响实际行为；页面显示的授权不等于生产环境已启用。
- 角色权限投影、旧权限来源和新资源范围并存时，不能直接覆盖或批量清理，必须先审阅来源和影响。
- 不同业务模块可能同时存在旧权限别名、模块权限和资源范围；需要按实际 API、查询筛选和角色矩阵验收，不能只看权限目录。
- 基础资料停用、版本快照和已引用数据之间的影响需要按模块验证；当前不做批量删除或权限重构。
- 角色/账号/数据范围属于高风险配置；任何修改都应保留 ETag、审计和回滚前的只读证据。
- 前端菜单/路由隐藏不是授权边界：当前路由守卫不逐路由校验权限，直接打开页面仍可能加载，必须以 API 权限和查询范围为准。
