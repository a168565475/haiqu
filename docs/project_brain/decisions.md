## D-001：正式设计规范的唯一维护入口

- **日期**：2026-09-30
- **状态**：`active`
- **决定**：`DESIGN.md` 第10章维护当前正式设计规则；项目 README 和审核页面只提供导航或来源说明。

- **来源**：[`DESIGN.md`](../../DESIGN.md)、[`README.md`](../../README.md)、设计确认记录。

- **状态**：`active`
- **决定**：CRM 负责客户核心数据和相关汇总；询盘、报价、样品分别建立独立模块知识卡，CRM 只保存关联并展示摘要。历史 CRM PRD 保留为评审稿和目标参考，当前代码事实、用户确认规则和 PRD 差异分开记录。

- **被替代的决定**：无。
- **来源**：用户 2026-10-01 确认、[`crm_customer_module.md`](crm_customer_module.md)、[`crm_prd_alignment.md`](crm_prd_alignment.md)。

## D-012：销售订单对客户删除的保护

- **日期**：2026-10-01
- **状态**：`active`
- **决定**：在没有生成销售订单之前，客户及其相关数据可以删除；只要存在销售订单，客户就不能删除。
- **原因**：销售订单产生后，客户已经成为订单事实来源，继续物理删除会破坏订单追溯和关联完整性。
- **影响**：删除接口必须在后端检查有效销售订单状态；前端按钮隐藏不能替代接口拒绝。当前代码尚未证明满足此规则，后续开发前必须补检查和测试。草稿和已取消订单的例外规则见 D-014；客户不可删除后的归档/停用规则见 D-013。
- **被替代的决定**：无。
- **来源**：用户 2026-10-01 确认、`src/backend/apps/customers/api/views.py`、`src/backend/apps/customers/hard_delete.py`、`src/backend/apps/sales_orders/models.py`、[`crm_customer_module.md`](crm_customer_module.md)、[`crm_prd_alignment.md`](crm_prd_alignment.md)。

## D-013：订单后的客户归档

- **日期**：2026-10-01
- **状态**：`active`
- **决定**：客户存在销售订单后禁止物理删除，但允许归档/停用；订单和客户历史保留，授权用户可以恢复。
- **原因**：保留订单追溯和历史，同时允许不再经营的客户退出正常工作列表。
- **影响**：归档/停用与删除必须使用不同操作和权限；归档不能删除客户关联数据。当前代码的客户归档/恢复能力可作为实现事实，但订单删除门禁仍需补充。
- **被替代的决定**：无。
- **来源**：用户 2026-10-01 确认、客户归档/恢复服务、[`crm_customer_module.md`](crm_customer_module.md)、[`crm_prd_alignment.md`](crm_prd_alignment.md)。

## D-014：删除保护的销售订单状态范围

- **日期**：2026-10-01
- **状态**：`active`
- **决定**：草稿销售订单和已取消销售订单不算有效销售订单，可以删除客户；其他销售订单状态按已有有效订单处理，阻止客户删除。
- **原因**：用户明确确认“这种订单可以删除”，即草稿和已取消订单不应锁定客户。
- **影响**：后端删除检查必须按销售订单状态判断，不能只判断是否存在任意 `SalesOrder` 记录；草稿和已取消订单仍需随客户删除规则处理其关联数据。
