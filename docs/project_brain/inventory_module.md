本卡记录仓库基础资料、材料/半成品/成品入库、库存余额和库存移动的当前边界。库存模型、公共库存切换和样品库存是不同层次，不能只看到“库存”目录就当作一条统一流程。

## 1. 模块目的与范围

库存模块负责仓库、库区、库位、材料入库、品质确认、库存余额、库存移动、成品入库/出库以及部分半成品和管材库存流程。库存数量以库存服务和库存移动为事实来源。

主要对象包括 `Warehouse`、`WarehouseZone`、`WarehouseLocation`、`MaterialInbound`、材料库存余额/移动、成品入库和成品出库，以及公共库存与管材/半成品专用服务。

## 2. 已验证的代码事实

- 仓库、库区和库位支持启用/停用，基础资料不允许物理删除。
- 材料入库有“待品质确认”和“已入库”状态；入库可以关联采购订单，品质确认是库存可用性判断的一部分。
- 采购材料入库先建为 `PENDING_QUALITY`，待检到货量会占用采购剩余；只有品质确认后的合格量才通过库存移动进入 `AVAILABLE` 余额。明细 `accepted_quantity` 的待检初始值不能单独证明库存已入账。
- 材料入库服务区分采购入库、手工入库和其他来源；库存余额与库存移动需要在事务内更新和校验。
- 成品入库可来自生产订单或样品库存，成品出库从具体入库批次扣减可用数量，并保留前后数量快照。
- 当前代码同时存在旧库存模式、公共库存模式、管材、半成品和成品专用流程；公共库存切换有预览、授权和并发测试入口。
- 库存 API 使用权限、ETag/并发校验和数量边界校验；已有测试覆盖部分入库、库存余额、公共库存和并发场景，但普通采购收货的提交幂等、来源身份冲突和真实并发仍没有充分运行证据。D-112 已将收货重试幂等议题暂缓。

## 3. 与采购、样品、生产的边界

- 采购模块负责采购订单和供应履约；库存模块负责实际入库、品质确认和可用数量，采购完成不能直接等同库存已入库。
- 样品模块负责样品材料需求、样品专用领料和样品库存业务边界；通用库存模块提供真实入库/库存事实，不能由样品页面直接改公共库存。
- 按 D-085，样品库存、出库和借出记录按模块权限全员共享，不按客户或负责人再次隔离；具体写入动作仍按独立权限控制。
- 生产/BOM/车间负责需求、报工和生产任务；库存扣减、入库和移动按实际仓库动作记录，不能用生产完成数量代替库存数量。
- 销售订单只提供下游来源或需求快照；销售订单确认不自动增加库存，发货/出库必须有库存事实。

## 4. 已确认决定

- D-072：样品库存沿用分批、多次入库；一次入库的旧细化方向被替代。
- D-076：样品实际领料按仓库能发多少记录多少，不自动补料；缺口保留，允许继续参数和生产。样品专用领料仍需与通用库存数量分开验收。
- D-080：样品入库数量上限按样品申请数量，参数图片、报工完成和入库数量分开记录。
- D-081：样品部分到料后可以按实际可发数量继续，采购剩余由采购模块管理。
- D-082：材料需求版本和采购后锁定改造暂缓，不因库存模块直接修改样品材料需求。

## 5. 当前缺口与风险

- 采购到货、品质确认、库存可用量、样品到料和样品专用领料之间存在多条链路，必须按具体来源和库存移动核对，不能只看页面状态。
- 旧库存模式与公共库存模式并存；任何切换、迁移、重置或清理动作都属于高风险操作，当前不执行清理。
- 入库数量、报工数量、样品申请数量和库存可用数量属于不同事实，不能用一个“完成”字段互相替代。
- 采购完成是采购履约状态，`purchase_inbound_workflow_status` 是列表派生状态；二者都不能替代 `MaterialStockMovement` 和 `MaterialStockBalance` 的库存事实。
- 历史库存专项测试和浏览器证据只覆盖报告范围；当前专项测试还存在旧管材采购夹具与新增 `stock_mode` 返回字段的断言漂移，真实数据库、普通采购收货幂等、并发和跨模块写入仍需独立验收。

## 6. 当前状态与下一步

当前状态：库存基础资料、入库、库存余额/移动、成品和公共库存入口已记录；不同来源和模式的完整业务边界仍需专项拆分。

下一步：继续按 Q-010 的证据规则核对采购到货到库存入库、品质确认、样品入库/领料和生产入库的数量流；任何涉及库存修正、重置、迁移或删除的操作，必须先单独确认范围并保留数据证据。
