本卡记录采购单、供应商、采购来源、到货和采购表的当前事实。采购代码工作区存在既有修改和未跟踪文件，本卡不把工作区状态当成已提交或生产验收状态。

## 1. 模块目的与范围

采购模块负责供应商、采购申请/分配、采购订单、采购退货、采购完成、采购表和采购来源追踪。采购订单可以来自生产任务或样品缺料，但订单创建后供应履约事实由采购模块维护。

当前可定位的业务对象包括：供应商、`PurchaseOrder`、采购订单明细、采购申请、分配记录、退货、采购合同模板和供应商采购表。

## 2. 不负责范围

- 样品材料需求的最终业务规则；样品模块维护申请，采购模块接收采购来源和履约结果。
- 销售订单产品和客户要求；销售订单只提供来源快照或生产连接。
- 库存数量、品质确认和库存移动；由库存模块维护。
- 生产任务、BOM 需求计算和生产报工；由生产/BOM/车间模块维护。
- 付款、成本、毛利和信用政策；采购金额字段不等于财务核算制度。

## 3. 已验证的代码事实

- 采购订单状态包括草稿、已确认、采购中和已完成采购；数据库保留 `SUBMITTED` 值，界面统一称为“已确认”。
- 采购订单来源包括生产订单和打样单；模型约束要求二者只能选其一，并保留来源快照。
- 样品采购已有 `sample_purchase_services.py`、采购来源预览、建单和 `SampleMaterialPurchaseSource` 绑定；旧报告中“样品采购未接入”属于历史状态。
- 采购接口包含供应商、采购订单、采购来源、确认、完成、退货、采购表和模板相关动作；关键写入使用权限和 ETag/并发校验。
- 供应商编号有格式校验，供应商不允许物理删除，应使用禁用状态。
- 采购表发布后进入只读或受限状态，图片和正式 PDF/Excel 生成有独立服务。

## 4. 与样品、订单和库存的边界

- 样品材料需求产生缺料采购来源；采购单建立后，样品模块不应直接覆盖采购来源和已到料事实。D-073—D-075 的材料编辑改造按 D-082 暂缓。
- 样品部分到料后可以继续生产；样品进入生产后不继续跟踪采购剩余，剩余收货或关闭由采购模块负责，见 D-081。
- 销售订单/生产任务可以作为采购来源，但采购数量、供应商履约和到货由采购模块维护。
- 采购到货必须通过库存入库或对应到货链路产生库存事实，不能只修改采购单状态表示已入库。
- 采购完成允许在部分到货的前提下完成，但前提是已经发起的到货批次全部完成品质确认、退货已完成或已核对；这只关闭采购履约状态，不代表采购数量全部到齐或库存已经可用。当前代码还允许已完成采购单针对已完成退货行补收，但 D-110 已将该议题暂缓，不能把代码现状当作用户确认的制度。

## 5. 当前缺口与风险

- 采购单建立后的样品材料变更、取消、退回重提和来源重算尚未形成完整闭环；按 D-082 暂不开发。
- 采购状态、到货状态和库存入库状态是不同事实，不能用采购单“已完成”替代库存品质确认或可用库存。
- 待检数量按到货量占采购余额，品质确认后的合格量才进入可用库存；退货、补收和未到货数量必须分别追踪。
- 工作区存在大量采购/库存相关改动；历史报告、当前源码和实际数据库证据必须分开。
- 采购剩余量、部分到货、退货和关闭之间的数量口径需要跨采购、库存和生产专项验收。

## 6. 已确认决定与下一步

- D-071：样品采购和库存属于当前 ERP 扩展，不受旧 CRM PRD 第一阶段限制。
- D-075、D-082：样品采购单建立后的材料锁定改造暂缓，不能把现有绑定代码写成完整变更流程。
- D-081：样品进入生产后，采购继续管理剩余未到货数量。
- D-110：采购完成后的退货补收议题暂缓，未来单独确认补收或更正/追加流程。
- D-111：退货处理中同一采购单其他明细是否可收货暂缓，当前整单冻结只作为代码事实记录。

当前状态：采购入口、样品采购来源和主要状态已记录；供应商、生产采购、样品采购、退货和到货的全链路仍需按实际 API/数据库证据核对。

下一步：继续按 Q-010 的证据规则核对采购来源、采购完成、退货和库存入库之间的数量闭环；如需改采购状态或样品采购变更，先单独确认范围。
