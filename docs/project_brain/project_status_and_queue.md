### Q-007 只读证据核对（2026-10-07）

- “标记无效”使用专用动作、`If-Match` 和无效原因，当前代码将询盘状态改为 `CANCELLED` 并保留原因；前端提示也明确不会删除沟通、报价和附件。
- “永久删除”是独立的 `delete_inquiry` 权限和 `destroy` API，服务会沿询盘、报价版本、样品、沟通和任务关系递归计算删除范围，并在单事务内执行物理删除。
- `deletion-preview` 目前只返回报价数、样品数、任务数和询盘文件关联数；它没有单独展示报价版本、沟通、订单或所有外键后代的数量。代码注释也明确不宣称穷尽递归删除数量。
- D-090 已确认：即使已有报价、样品或销售订单，也允许永久删除；但仍必须使用独立删除权限、`If-Match`、删除前预览和事务保护。当前只读核对没有执行删除，也没有修改删除门禁。
- 删除预览没有穷举所有报价版本、沟通、订单或其他外键后代；这仍是预览完整性和审计可追溯性缺口，不能因为允许删除就跳过提示或扩大递归范围。

### Q-008 报价接受到销售订单转单（2026-10-07，静态证据）

- 报价接受和销售订单确认是两个阶段。`transition_quotation` 会锁定报价，只接受当前报价下状态为 `SENT` 的版本；接受价格口径必须属于该版本，确认联系人（如果填写）必须属于报价客户。成功后写入 `QuotationAcceptance`，记录接受版本、价格口径、联系人、时间、来源枚举和备注，并把报价结果改为 `WON`、设置 `accepted_version`；来源询盘会回写为 `QUOTE_ACCEPTED`。
- `quotation-options` 接口只返回结果为 `WON` 且当前 `accepted_version` 的报价版本。创建和确认销售订单时，服务端会再次检查接受版本、报价客户与订单客户一致、报价来源行存在，并禁止在报价来源订单中添加报价外产品。
- 转单数量在报价行级别用数据库行锁校验。已取消订单不计入占用；草稿、已确认、履行中和已完结订单都会计入预留/已转数量。允许部分转单和拆成多张订单，但累计数量超过报价数量会被拒绝。创建草稿和确认订单都会执行这项校验。
- 订单确认前需要买方主体、卖方快照中的公司名称、有效买方地址、客户确认方式/人/时间/摘要，以及交付批次数量与订单数量一致。确认成功后创建订单版本；如果来源报价有询盘，当前代码把询盘主状态更新为 `CONVERTED`，并结束对应时限事件。
- 当前“客户接受凭证”不是附件凭证：`QuotationAcceptance` 只有来源枚举、备注、联系人和时间等结构化字段，没有 `BusinessFile` 关联；因此不能把“已记录接受”解释成已经留存客户邮件、PO 或会议附件。无报价/返单订单的客户确认文件要求属于订单确认规则，不能反推到报价接受。
- 销售订单只保存 `source_quotation_version`，没有直接关联 `QuotationAcceptance`；`quotation-options` 也不返回接受来源、接受时间、联系人或附件。订单可以回查“哪一个报价版本已接受”，但不能从订单单据直接看到接受依据。

#### 已发现的实现边界

- 订单草稿创建时，`create_sales_order` 已调用 `handle_time_event(..., 'ORDER_CREATED')`；询盘主状态此时通常仍未改成 `CONVERTED`，但该事件会结束询盘时限，且 `has_sales_order` 把任一未取消草稿视为已有订单，后续阶段登记也会被阻止。
- D-091 已确认这就是当前业务规则：销售订单草稿已经产生时即可影响询盘计时和后续阶段；“首张确认订单后才推进”的旧 PRD 语义不再作为当前规则。主状态仍可等订单确认后再改为 `CONVERTED`，因为“影响询盘阶段”和“确认成交”是两件事。

#### 证据状态

### Q-010 采购到货、品质确认、库存入账数量链（2026-10-07，静态证据）

- 采购完成、实际到货、品质确认和可用库存是四个不同事实。采购完成服务会汇总采购行的到货、待检、合格和退货；只有采购单处于已确认/采购中、至少发起过一批到货、没有待品质确认和未完成退货时，才允许把采购单改为 `COMPLETED`。当前测试明确证明“部分到货且已发起批次全部质检”也可以完成采购，不要求采购数量全部到齐。
- 采购入库会锁定采购单和采购明细，要求同一采购单、采购中状态（已完成单仅允许补收已完成退货）、预期剩余数量未变化，并禁止超过实际采购数量。新建 `MaterialInbound` 状态为 `PENDING_QUALITY`；待检数量按到货量占用采购剩余。
- 品质确认必须完整提交该批次的全部待检明细，并再次校验到货数量没有变化；系统按到货量减退货量计算合格量，写入退货数量和品质备注，将批次改为 `CONFIRMED`，合格量大于零时才调用库存入账服务。
- 可用材料库存以 `MaterialStockMovement` 和 `MaterialStockBalance(quality=AVAILABLE)` 为事实。库存入账在事务内锁原料、库区和余额，做幂等检查并写入 IN 流水；待检批次不能因为明细上的 `accepted_quantity` 初始值而被解释成已经进入可用库存。管材、公共库存和手工入库有专用链路，不能与普通采购入库混算。
- 权限上，收货、品质确认和库存查看是不同动作；API 分别使用 `inventory.receive_material`、`inventory.quality_confirm_material` 和库存查看权限。手工材料入库可以直接创建 `CONFIRMED` 批次并即时入账，这是另一条来源链，不代表采购入库跳过品质确认。

### Q-005 样品参数图片、报工和入库数量分离（2026-10-07，静态证据）

- 当前报工服务分别保存 `metalwork_reported_quantity`、`cutting_reported_quantity`、`metalwork_completed` 和 `cutting_completed`。服务端要求完成时数量大于 0，数量不能超过该明细的样品数量；可以少于申请数量，未完成时允许 0。报工完成后再次提交仍可修改数量和完成状态，并通过样品审计保留前后值。
- 当前样品入库候选按样品申请数量计算剩余量：要求样品状态为 `FINISHED`、两道工序完成、参数/材料就绪条件满足，累计入库量小于申请数量；创建入库单时再次锁定明细并校验剩余量，实际入库数量可以小于申请数量，支持分批入库。入库创建同时写样品库存行和成品库存来源记录，入库量不是报工字段的改写。
- 现有测试覆盖参数先后顺序、删除最后一张参数图后回退、报工数量上限和完成条件、参数与报工均满足后进入入库候选、累计入库和分批剩余量校验；本轮没有在真实业务数据上执行接口或浏览器验收。

#### 已发现的实现边界

- 代码已经实现了“图片、报工、入库数量分开保存”的主要结构，但 D-080 的全量规则仍需验收：新版与历史样品共用兼容条件，入库候选还同时检查材料就绪/无需用料和工作流记录，不能只看参数图和报工字段判断可入库。
- 前端可以把报工输入默认显示为申请数量，但服务端报工序列化器允许部分字段缺省并由当前值承接；“默认带入申请数量”是页面行为，不能仅凭接口定义认定所有入口都满足该默认值。
- 入库服务按申请数量限制累计入库，因此在业务上允许出现入库数量高于某一道工序报工数量的情况；这是 D-080 已知口径，当前没有额外的跨工序数量限制。若要改变该口径，需要新增决定，不能由验收人员自行收紧。

### Q-006 样品部分到料后停止跟踪剩余采购（2026-10-07，静态证据）

- D-081 要求样品缺料只到一部分时，可以按当前实际可发数量领料并继续进入参数/生产，不等待采购全部到齐；样品进入生产后，样品流程不再继续跟踪采购剩余，剩余采购由采购模块继续收货或关闭。
- 当前到货衔接只接受已完成品质确认且合格数量大于 0 的真实采购入库行，并强制校验采购行与样品缺料行的来源绑定、名称/规格/材质/单位快照和幂等关联。到货不会直接扣样品库存或跳过领料确认；有合格到货后，样品通常进入 `MATERIAL_ISSUE_PENDING`，材料进度会分别显示可供、已到货和剩余缺口。
- 当前样品领料确认允许实际发出数量小于需求量，记录 `shortage_quantity`，随后直接进入参数阶段；采购单、采购来源、入库批次和样品到货记录仍然保留，采购完成服务允许采购人员在有到货且无待质检/未完成退货时结束采购，未到货数量可以由采购侧手动关闭。
- 专项测试已覆盖第一次部分到货、退货后按合格量回写、重复到货幂等、第二批到货补齐、部分领料后进入生产，以及采购单后续收货/退货/完成不改写样品较晚的生产状态。

#### 已发现的实现边界

- 当前“部分到料后继续领料和生产”已经有代码路径；但“进入生产后停止跟踪采购剩余”还没有完全隔离。`inventory.services.confirm_material_quality` 对每一条样品采购来源入库行都会继续调用 `receive_material_arrival`；该服务只有在样品生产状态下已经满足全部材料剩余为零，或存在材料流重置审计时才允许回写，否则会拒绝“当前样品不在等待采购到货阶段”。
- 这意味着样品已按不足数量领料并进入生产后，采购模块再收剩余材料时，跨模块品质确认可能仍尝试回写样品并被拒绝，而不是安静地只更新采购/库存。当前测试覆盖了部分到货后继续和采购完成，但没有覆盖“样品已进入生产、剩余采购随后到货”的完整真实链路。
- 因此 Q-006 保持 `code_partial`，不能把现有“部分入库”标签或采购单完成接口解释成 D-081 已全部实现。后续应先明确剩余到货的回写策略（跳过样品、只留采购/库存事实，或保留只读历史），再补事务和 API 验收；本轮不改服务逻辑。
