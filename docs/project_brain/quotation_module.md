## 1. 模块目的

报价模块负责把询盘或其他业务机会形成可版本化的价格、产品、包装、条款和客户要求记录，并支持锁定、签发、发送、客户接受和后续转销售订单。报价接受是客户对报价版本的接受事实，销售订单确认才是成交事实。

## 2. 负责范围

- 报价主单、报价版本、报价明细和版本继承关系。
- 报价产品、价格、数量、包装、容器配置、联系人、地址、交易主体和客户要求快照。
- 报价模板、模板审批开关、版本锁定、签发、作废和替代版本。
- 从询盘创建报价、回写询盘报价状态、客户接受报价版本。
- 报价预览、价格历史、版本差异、产品图片和发送记录。

## 3. 不负责范围

- 客户核心资料、负责人、客户标签和客户信用政策；由客户与 CRM 模块维护。
- 询盘的来源、行项目、技术计时和丢单事实；由询盘模块维护。
- 销售订单确认、履约、生产、采购、库存和财务核算；由对应模块维护。
- 按金额、折扣、毛利率或客户等级统一制定的报价审批制度。用户已确认暂不制定统一阈值，当前沿用报价模板的 `requires_approval` 配置，见 D-057。
- 正式成本、毛利、汇率和财务核算。报价可以保存币种和金额，但技术字段不等于财务制度，见 D-031、D-055。

## 4. 已验证的代码事实

- `Quotation` 结果状态包括 `OPEN`、`WON`、`LOST`、`CANCELLED`，可关联客户、交易主体、来源询盘、负责人和接受版本。
- `QuotationVersion` 支持 `DRAFT`、`LOCKED`、`ISSUED`、`SENT`，并支持 `SUPERSEDED`、`VOID`；版本可通过父版本复制，明细保留 `lineage_id`。
- 草稿可以编辑；锁定后通过新版本复制，不直接覆盖已锁定版本。
- 锁定前会校验明细、价格、模板和快照；模板要求审批时，审批满足后才允许签发。
- 客户接受只允许已发送版本，并记录接受版本、价格口径、联系人、时间、来源枚举和备注；接受后回写来源询盘状态。当前 `QuotationAcceptance` 没有 `BusinessFile` 附件关联，结构化接受记录不能等同于客户邮件、PO 或会议附件已经留存。
- 外部邮件、正式文档、卖方主体和 SMTP 配置存在运行条件；配置不足时不能把“发送按钮可见”解释成邮件已送达。

## 5. 业务流程（当前代码主链）

1. 从询盘事务创建报价草稿，或在允许的入口创建独立报价。
2. 导入询盘产品/需求，编辑报价版本和明细。
3. 锁定版本，校验价格、明细、模板和客户快照。
4. 如果模板要求审批，先完成审批；然后签发并发送。
5. 客户接受已发送版本，记录接受证据并回写询盘。
6. 由销售订单模块从已接受的报价版本选择可转数量，创建销售订单。

流程中的按钮顺序不能替代业务制度；发送、接受和转单仍需以服务端校验和真实运行证据为准。

## 7. 与其他模块的关系

- **客户与 CRM**：读取客户、联系人和交易主体；CRM 不维护报价版本和价格事实。
- **询盘**：报价可以来源于询盘；创建报价进入 `QUOTING`，客户接受后回写询盘，首张有效销售订单确认后由订单模块推进成交状态。
- **样品**：样品可以关联询盘或报价版本；产前样提醒属于样品/订单协同事实，不自动形成统一订单阻塞，见 D-061。
- **销售订单**：只能从客户已接受的报价版本转单，按报价行剩余可转数量校验；报价接受不等于订单确认。转单数量会把未取消的草稿订单也计入预留，允许部分转单和拆单。
- **财务**：报价金额、币种和折扣是单据数据，不自动形成成本、毛利、汇率快照或财务核算。

## 8. 当前缺口与风险

- 旧 CRM PRD 中的统一审批阈值、销售 SLA 和成本毛利要求不能直接当作当前制度；它们与 D-029、D-031、D-055、D-057 的当前边界不同。
- 历史 `QUO-01~QUO-06` 报告只证明当时专项测试和浏览器证据，不能证明现在所有发送、订单和外部配置已经验收。
- 报价版本和销售订单之间存在数量转化、接受版本、客户一致性和价格快照约束；不能只做前端下拉选项而跳过后端校验。
- 正式卖方主体、邮件、模板文件和外部 SMTP 运行条件需要独立验收。

## 9. 已确认决定与下一步

- D-005：报价独立于 CRM 客户核心资料维护。
- D-057：报价审批暂不制定统一金额、折扣、毛利或客户等级阈值，沿用模板 `requires_approval`。
- D-061：产前样未确认不自动阻塞销售订单。
- D-062：订单里程碑责任人、时限和升级规则暂缓，不能从报价页面补出制度。
