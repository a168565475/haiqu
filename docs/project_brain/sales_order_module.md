本卡记录销售订单的当前代码、用户已确认的订单边界和专项证据。订单模型存在字段或状态，不代表对应流程已经有完整 API、权限和运行验收。

## 1. 模块目的

销售订单模块把已接受报价、直接下单或返单形成可确认、可变更、可交付和可完结的订单事实，并把确认后的订单与生产、采购、交付和协同事件连接起来。

## 2. 负责范围

- 销售订单主单、订单明细、产品和客户要求快照。
- 报价来源、直接下单、返单三类来源及其证据要求。
- 草稿编辑、订单确认、确认后变更、版本快照和变更审计。
- 多批次交付、批次取消、交付数量校验和订单完结。
- 客户确认凭证、价格例外、协同事件和产前样提醒。
- 向生产任务、BOM 和采购流程提供订单来源连接；下游事实由各自模块维护。

## 3. 不负责范围

- 客户主档、客户信用审批、统一账期和销售 SLA；由客户/CRM或后续制度维护。
- 报价版本本身的价格、审批和客户接受；由报价模块维护。
- 生产任务、BOM、采购和库存的执行数量；订单变化不自动覆盖下游执行事实。
- 正式财务汇率、成本、毛利和应收核销。`payment_terms`、`exchange_rate`、`total_amount` 是订单技术字段，不等于财务政策。
- 统一订单里程碑负责人、时限和升级规则；当前仅记录协同事件，见 D-062。

## 4. 已验证的代码事实

- `SalesOrderSource` 包括 `QUOTATION`、`DIRECT`、`REPEAT`；状态包括 `DRAFT`、`CONFIRMED`、`FULFILLING`、`COMPLETED`、`PAUSED`、`CANCELLED`。
- 报价来源订单必须选择客户已接受的报价版本，并校验客户一致、报价行来源和剩余可转数量；允许部分转单和拆成多张订单，但不能超过报价数量。报价行数量校验会把未取消的草稿订单也计入预留。
- 草稿订单可以直接编辑；确认前必须补齐买方主体、卖方公司、有效买方地址快照、客户确认方式/人/时间/摘要，以及有效交付批次数量。
- 无报价或返单订单必须填写直接下单原因和客户确认凭证。
- 订单确认后写入 `SalesOrderVersion`，并可能回写来源询盘；产前样未确认只产生提醒，不自动阻塞确认，见 D-061。
- 确认后变更必须填写原因；涉及客户面的变更需要客户凭证；已有生产订单时需要 PMC 确认计划影响。变更写新版本，不直接覆盖生产、BOM 或采购记录。
- 确认后不能新增、删除订单产品或交付批次；允许在既有行/批次边界内调整数量、价格和要求，批次取消走单独动作。
- 正常完结要求有效交付批次、已完成发货数量和余额协同事件满足；异常完结必须填写原因并记录风险事件。

## 5. 业务流程（当前代码主链）

1. 创建报价转单、直接订单或返单草稿。
2. 编辑订单客户、产品、数量、价格、交付批次和要求。
3. 服务端校验客户、报价接受状态、报价剩余数量和订单确认资料。
4. 确认订单，生成订单版本并写入客户确认和来源快照。
5. 在允许范围内发起确认后变更，记录原因、证据和下游计划影响。
6. 维护交付批次、取消批次或记录协同事件。
7. 完成全量履约后正常完结；无法全量履约时走带原因的异常完结。

页面顺序不能替代订单制度；订单确认、变更和完结都以服务端门禁为准。

## 7. 与其他模块的关系

- **客户与 CRM**：读取客户、交易主体、地址和权限范围；客户删除保护按 D-012—D-014，草稿/取消订单不能阻止删除，有有效销售订单后禁止删除。
- **询盘**：报价转单和首张确认订单会推进询盘状态；询盘技术计时不等于统一销售 SLA，见 D-053。
- **报价**：订单可从已接受报价版本创建，转单数量受报价剩余量限制；订单确认是成交事实。
- **样品**：订单可读取产前样提醒，但产前样未确认不自动阻塞订单，见 D-061；样品业务事实仍由样品模块维护。
- **生产/BOM/采购**：订单提供来源和快照连接；订单变更不会自动覆盖已经产生的生产、BOM、采购和库存事实，需各模块分别处理。
- **交付/财务**：交付批次和余额协同事件支持完结门禁；正式发货、收款和财务核销仍需对应模块事实。

## 8. 当前缺口与风险

- 模型有 `PAUSED`、`CANCELLED` 状态，但当前 API 未发现完整的订单级暂停/取消动作；不能把枚举值写成已经可用的流程。
- D-092 已确认暂停是可恢复的临时状态：已确认或履约中订单可暂停并填写原因，已完成/已取消订单不可暂停或恢复；具体数量和下游影响仍待确认。
- D-093 已确认暂停订单继续占用来源报价数量，不释放给其他订单；恢复时沿用原订单数量。当前报价预留只排除 `CANCELLED` 的代码方向与此一致。
- D-094 已确认暂停不联动已开始的生产任务；暂停期间不能新建生产任务，恢复后才允许新建。已经建立但尚未开始的生产任务处理方式仍待确认。
- D-095 已确认已经建立但尚未开始的生产任务在订单暂停期间仍可启动、排产和报工；暂停只阻止新建生产任务，不冻结已有任务。
- D-096 已确认已经建立的采购申请、供应商采购单、到货确认和退货流程继续执行；销售订单暂停不自动冻结、取消或回滚采购事实。
- D-097 已确认已有有效交付批次在订单暂停期间仍可继续发货和登记协同，已完成发货保留；暂停不回滚交付事实。
- D-098 已确认已确认、履约中或已暂停订单允许整体取消，取消后进入终态并保留历史；整体取消与交付批次取消分开，草稿和已完成订单的整体取消规则仍未确定。
- D-099 已确认整体取消释放未履行报价数量，已发货数量不回溯；当前按整张 `CANCELLED` 订单排除预留，部分发货后取消需要按行精确计算，现有代码不足以证明已经实现。
- D-100 已确认整体取消后不再新建生产；已开始生产继续完成，已建立但未开始生产暂停，已完成生产历史保留。该规则覆盖取消场景，不等同于暂停时已有生产任务继续执行。
- D-101 已确认整体取消后已下达采购继续执行，不自动取消；到货、退货和结算按采购模块处理，只停止后续新增采购。
- D-102 已确认整体取消后已有有效交付批次仍可继续发货和登记协同；已发货数量保留，取消只停止新增生产和新增采购。当前取消批次服务的状态门禁尚未适配该规则。
- D-103 已确认订单级整体取消不强制客户确认凭证；必须填写取消原因并记录操作者、时间、取消前状态和状态变化。交付批次取消的客户凭证要求仍独立有效。
- D-104 已确认订单级整体取消复用 `sales_orders.change_salesorder` 修改权限，不新增独立取消权限；仍需订单范围、并发校验、原因和审计。
- D-105 已确认草稿不使用订单级整体取消状态；草稿后续编辑还是另设删除/清理动作、以及草稿报价数量占用，仍待确认。
- D-106 已确认草稿允许单独删除/放弃，删除前释放报价数量并保留删除审计；已确认及后续状态订单不能按草稿删除。当前 API 尚无草稿删除动作。
- D-107 已确认草稿删除/放弃复用 `sales_orders.change_salesorder` 修改权限，不新增独立删除权限；仍需动作门禁、并发校验、数量释放和审计。
- D-108 已确认草稿删除不单独预览；填写删除原因并在确认弹窗中直接删除，仍需并发校验、数量释放和审计。询盘永久删除的预览规则独立保留。
- D-109 已确认已完成订单不允许整体取消；完成后的纠正另走调整/冲销流程，已发货、收款和结算历史不通过取消回滚。
- 当前报价剩余量计算只排除 `CANCELLED` 订单，客户有效订单汇总包含 `PAUSED`；这只是现有代码行为，不等于暂停/取消后的业务规则已经确认。
- 前端对 `PAUSED` 显示异常关闭入口，但后端完结服务不接受暂停订单，属于待处理的前后端状态门禁差异。
- 生产任务创建会拒绝暂停或取消状态的销售订单，但已有生产任务不会自动随父订单暂停/取消；交付批次取消只保留风险提醒，不自动回滚生产、采购或库存。后续实现不能只补一个状态按钮。
- 确认后变更不是任意编辑：当前禁止增删订单行和交付批次，只能在既有边界内调整；知识库和页面不能误导为自由修改。
- 订单字段中的付款条款、汇率和金额是单据记录，不代表信用审批、正式汇率快照、成本或毛利制度，见 D-030、D-031、D-054、D-055。
- 订单变更对生产、BOM、采购和库存的影响目前主要通过连接、快照和提示表达，跨模块实际回退/重算/审批需要单独验收。
- 历史订单专项测试和浏览器证据只覆盖报告列出的范围，不能替代当前代码、API 和真实环境复核。
- 创建报价来源订单草稿时，当前代码已经发送 `ORDER_CREATED` 时限事件；询盘主状态通常仍保持原值，但草稿会被 `has_sales_order` 视为已有订单并影响后续阶段。D-091 已确认沿用这一规则；订单确认后再把来源询盘推进为 `CONVERTED`，不与草稿已经产生的计时/阶段影响混同。

## 9. 已确认决定与下一步

- D-012—D-014：有有效销售订单后客户不能删除；草稿和已取消订单不构成删除阻止。
- D-053：询盘技术计时与统一销售 SLA 分开记录。
- D-054：信用快照展示与信用审批规则分开记录。
- D-057：报价审批不制定统一阈值，订单不能自行补出报价政策。
- D-061：产前样未确认不自动阻塞订单。
- D-062：订单里程碑责任人、时限和升级规则暂缓。

当前状态：销售订单知识卡已建立；订单创建、确认、变更、交付和完结的代码边界已记录。针对性测试已覆盖预构造已接受报价的草稿、数量预留和确认，但未证明报价接受 API 后的完整转单链路，不能宣称全流程完成。

下一步：业务规则已由 D-091 确认；继续核对报价接受 API→订单草稿→订单确认、生产任务创建和订单完结的 API/测试/浏览器证据。如果发现代码与 D-091 不一致，再单独提出范围确认。
