# 公共库存第 5 步：采购、委外及回货接入

日期：2026-09-28。状态：已按用户本轮“确认”完成第 5 步独立开发、迁移、专项测试及真实浏览器验证。新增专项全部通过，整套回归保留已由修改前副本复现的旧测试问题，详见第 4 节。**主环境尚未切换。** 第 6 步接续及正式切换未取得授权。

## 1. 范围与环境

本步承接 `public_stock_step4_result_20260928.md` 第 6 节。独立代码位于 `qa/public_stock_step5_20260928/isolated_backend` 和 `isolated_frontend`，网页端口 8083，接口端口 8003，固定隔离库 `public_stock_s5_base`；自动化测试仅重建固定的 `test_public_stock_s5`。数据库主机、库名及 PostgreSQL 实例身份均设校验。

没有修改主系统挂载的库存、采购、委外和领料源码，没有在主库执行迁移、库存合并、业务单据操作或自动补 BOM。普通面料、五金、塑料、辅料继续使用既有按物料与库区汇总的公共余额；原料管材和半成品使用新公共余额。

## 2. 改前、改后与原因

| 入口 | 原有处理 | 独立副本本步结果 |
| --- | --- | --- |
| 采购收货及质检 | 分批收货、质检，管材按入库行保存根米余额 | 保留采购、分批收货和质检流程；新单合格管材直接累计公共根数及米数，采购入库记录仍可追溯 |
| 质检拒收及采购退货 | 拒收不计可用，按来源处理退货和补货 | 保留该规则；拒收既未入可用库，完成退货不会再次扣公共库存；补货重新收货、质检后入可用库 |
| 普通委外原料发出 | 管材来源可能绑定采购批次 | 新单只按物料、库区、公共可用量发料；与厂内领料共用订单原料额度和待审占用，管材填支并扣整根及米，面料填米并扣米 |
| 普通委外合格回货 | 按订单来源形成半成品余额 | 按发出时冻结的 BOM 实物属性、实际完成工艺和单位入公共半成品；管材为支、裁片为套，五金保持原单位 |
| 金工已领来源交接 | 原材料已经在领料出库时扣除 | 延续原来源凭证，新交接只记录在制交接数量，不第二次扣原料；合格回货才增加公共半成品 |
| 未喷塑退回、厂内返工及再外发 | 记录原来源的在制数量与加工责任 | 保留在制流转；返工再外发的合格回货入公共半成品，不重新领原材料 |
| 未用原料退回、撤销发料 | 沿原发料来源恢复库存与额度 | 只按原公共扣库凭证恢复原库区、根米或普通数量，额度同步恢复；重复请求不重复恢复 |
| 备注结清、结清后补登记 | 保存结清当时差额，实际追加登记另记 | 保留原语义和备注要求；补回货增加实际公共半成品，不覆盖原结清快照 |
| 材料仓库页面 | 旧管材和按订单半成品展示 | 原料、半成品分别显示公共数量；半成品显示冻结实物属性及已完成工艺，仓库筛选对应原料仓或半成品仓 |

仍保留订单需求、已耗用、待审核占用和剩余额度；公共数量足够不代表订单可以超领。原料按现有最终备料额度控制，半成品按接收 BOM 的净支数或净套数控制。相同物品跨订单共用，不混合不同颜色、尺寸、厚度、实际工艺或单位。

界面只改现有提示、库存列和筛选行为，没有新建档案或人工匹配页面，没有重新绘制整页。原料收货记录仍含采购来源；这与后续领用不选择采购批次并不冲突。

## 3. 正反向记账及异常边界

- 新入库、委外单、金工返工外发单明确记录库存口径。完整新流程开关默认关闭；试跑仅在独立服务开启。完整新流程开启时，未接续的旧单不能再向旧账写库存；关闭时，新单也不能悄悄退回旧账。已经成功的相同请求可核验后返回原结果。
- 管材采购长度在收货时冻结；生产领料在扣库前冻结 BOM 实物属性；委外产物冻结实际工艺与单位。后续修改 BOM 不会更改已发生入出库、回货的实物身份。缺旧证据则明确阻止，不能按今天的 BOM 猜历史。
- 后端统一校验正数量、整数支/套、整根换算、根米一致、公共库存不足、订单上限、其他待审占用、来源及权限、有效库区、版本冲突和重复请求；库存与单据在同一事务成功或回滚。
- 独立审查发现并修正任务、原料、父仓、库区和余额的取锁顺序，以及排产与任务的反序，防止同时领料/回货/停用仓区出现相互等待或绕过校验。并发验证使用真实独立数据库连接。
- 未新增报废、不良品及旧米制管材转换功能。原有品质隔离继续保留，不合格采购材料不能被当作可用原料领走。

## 5. 旧未结单与正式切换限制

本步提供只读 `preview_public_stock_transition` 命令及新旧写入口互斥门禁，**没有自动把旧单改成新单，也没有实施历史在途接续**。这部分必须在第 6 步按真实未结单逐项核验，不能只打开开关上线。

| 旧记录 | 正式切换前的处理要求 |
| --- | --- |
| 已收货、未质检 | 先完成原质检并计入期初对账，或另行核对原收货冻结证据后制定接续 |
| 未实际出库的旧领料、未发出的旧委外 | 按权限退回或取消原计划，再按当前有效 BOM 和剩余额度重建；继承已发生耗用，不凭空重置订单额度 |
| 已领但未结清的金工来源 | 核对已领、已完成、已交接及在制数量；接续原来源，不重新扣一次原料 |
| 已发出、未全部回货的旧委外 | 核对未回数量、当时实物属性、实际工艺及退料凭证；已有旧资料不足时需可核实凭证，不能猜值 |
| 已备注结清的委外 | 仍可能发生补回货，不能仅因状态为结清就忽略接续；原结清差额与后补实绩分开保留 |
| 返工再外发 | 沿原退回、返工和交接证据接续，维持在制数量守恒，不再扣原材料 |

旧单历史阅读保留。正式环境仍走原流程，所以本步隔离门禁没有阻断用户当前的真实业务。

## 6. 第 6 步拟提交范围

1. 重新只读核对真实 BOM 缺值、库存余额、旧未结/在途和结清后可补登记单据，形成逐条可审阅接续清单；不沿用已过期的试跑快照。
2. 为可核实的历史记录制定接续和数量对账，完成完整采购→入库→领料/委外→公共半成品→跨订单领用的联合验证；任何需补的真实属性或差额单独列明。
3. 提交具体代码文件、迁移、备份验证、切换时点、短暂停写范围、期初/在途/订单额度对账以及恢复步骤。新旧库存只能有一套正式写账入口。
4. 用户确认具体正式切换清单之后，才操作主源码、主库结构或真实业务数据；切换后的新增流水不能用简单关闭开关抹去，恢复也必须有数量对账。

当前的“第 5 步确认”只覆盖本报告的独立开发、迁移与测试资料写入，不代表已经确认第 6 步正式切换。
