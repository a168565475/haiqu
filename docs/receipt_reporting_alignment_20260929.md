## 用户最终确认的规则

1. 报工完成代表工序/计划完成，不代表仓库已经收到实物。金工、车缝和装配计划继续按现有报工规则完成。
2. 金工、车缝半成品由仓库填写实际入库数量，按订单数量乘BOM部件用量限制，不增加报工数量限制。例如某部件单耗4支、订单1000，则累计最多入库4000支。裁剪仍不入库。
3. 成品也由仓库确认实际入库，不因报工自动增加库存。累计入库上限取以下两者较小值：全部必需装配工序的最低累计报工数量；订单数量加允许偏差后的整数上限。
4. 同工序跨人员、日期及产线的有效报工累计计算；未报工工序按0。可再入库=累计上限−原始累计入库数量，出库不恢复额度。
5. 报工修改后如导致最低累计报工低于已入库数量，拒绝修改并保留原记录。删除同样执行保护，不能通过删除绕过。

## 4步具体改动

| 步骤 | 改前问题 | 改动及结果 |
| --- | --- | --- |
| 1. 对齐完成状态 | 历史入库候选会按累计入库覆盖内部计划状态，与最新报工功能冲突 | 移除入库对计划状态的覆盖；保留最新报工的计划进度、权限及入库入口 |
| 2. 统一成品额度 | 旧成品入口仅检查订单偏差，新旧入口可能口径不同 | 共用装配报工额度计算；单笔、批量和装配计划入口均受相同上限限制；半成品原有订单/BOM额度不变 |
| 3. 保护已入库数量 | 报工调低或删除可能令已入库超过报工 | 编辑、删除在同一事务内校验，失败全部回滚；新入库与报工采用一致的订单锁顺序，防止同时操作越限 |
| 4. 页面及验收 | 仓库看不到报工限制原因 | 现有额度区显示订单数量、装配工序最低报工、累计入库上限、累计已入库、本次可入库；保留现有视觉规范 |

累计上限示例：订单1000，偏差2%，三道必需工序分别报工800、700、600，则上限=min(1020,600)=600。已经入库450，最多再入150。若必需工序缺报或缺少有效批准工价依据，当前额度为0，并提示核对依据。
