# 全局上传病毒扫描策略设计

## 目标

当前 ERP 由内部员工在可信内网使用。用户确认所有上传文件暂时不需要 ClamAV 检测，但仍必须保留文件格式、签名、大小、路径、权限、Session/CSRF、ETag、事务和失败清理校验。未扫描文件必须真实标记为 `SKIPPED`，不能伪装成 `CLEAN`。

## 已确认事实

- 通用图片和文档入口位于 `apps.files.uploads`。
- 联系人导入在 `apps.imports.security` 中有独立的文件保存和扫描链路。
- 询盘附件、报价正式文件、样品文件存在各自的自定义保存链路。
- BOM 文件源已使用 `SKIPPED`，数据库状态和约束已经支持该值，无需新增迁移。
- 多个业务读取、下载和跨模块复用入口目前只接受 `CLEAN`，需要统一接受 `CLEAN` 或 `SKIPPED`，同时继续拒绝 `PENDING`、`FAILED`、`INFECTED`。
- 当前询盘产品图保存失败提示来自 `ScannerUnavailable`；前端还会重复追加句号。

## 范围

### 包含

1. 增加全局配置 `FILE_VIRUS_SCAN_ENABLED`。
2. 增加统一扫描策略适配器：开关开启时调用现有 ClamAV；关闭时返回 `SKIPPED` 和明确的审计说明。
3. 将所有真实用户上传入口接入该适配器，包括通用图片/文档、联系人导入、询盘附件与沟通图片、报价图片与正式文件、样品文件、客诉图片、生产任务图片、采购表图片、基础数据图片等当前源码中的上传入口。
4. 将业务文件可用状态统一为 `CLEAN` 或 `SKIPPED`，更新对应查询、下载、预览、继承和跨模块复用条件。
5. 保留原有格式、签名、大小、路径安全、权限、并发和事务边界；扫描关闭时不等待或调用 ClamAV。
6. 当前本地 `.env` 关闭扫描；`.env.example`、README 或运维说明记录开关含义和重新开启方式。
7. 修正询盘前端 `SKIPPED` 状态文案及重复句号。

### 不包含

- 不删除 ClamAV 镜像、数据卷或扫描实现。
- 不修改数据库结构、历史迁移、业务权限模型、上传格式限制或数据范围规则。
- 不把 `FAILED`、`INFECTED`、`PENDING` 文件放行。
- 不改变系统生成文件当前的 `CLEAN` 记录方式。
- 不清理或重写已有业务文件状态；历史文件保持原状态。

## 配置与默认值

`config/settings.py` 新增：

```python
FILE_VIRUS_SCAN_ENABLED = env_bool("FILE_VIRUS_SCAN_ENABLED", True)
```

默认值为 `True`，避免未配置的其他环境意外关闭安全检查。当前内部开发环境的 `.env` 显式设置为 `FILE_VIRUS_SCAN_ENABLED=false`。重新开启扫描时只需改为 `true` 并重启后端；ClamAV 必须恢复健康。

后端不再把 ClamAV 健康状态作为启动前置依赖。ClamAV 服务定义保留，便于以后重新开启扫描；启动脚本可继续启动该服务，但扫描关闭时后端不因其不可用而阻断。

## 数据流

统一适配器接收临时文件路径和当前扫描函数：

1. `FILE_VIRUS_SCAN_ENABLED=false`：不建立网络连接，返回 `(FileScanStatus.SKIPPED, "病毒扫描已关闭，按内部上传策略保存。")`。
2. 开关为 `true`：调用 `_clamav_scan`；返回成功时为 `(CLEAN, 扫描返回消息)`。
3. ClamAV 报告感染或不可用时，沿用现有 `INFECTED`/`FAILED` 错误语义和清理行为，不把失败转换成成功。
4. 保存器移动临时文件并创建 `BusinessFile` 时使用适配器返回的状态；`SKIPPED` 的 `scanned_at` 保持为空，`CLEAN` 才记录扫描时间。

各自定义上传器通过该适配器传入本模块的扫描函数，保留现有测试的可替换边界，避免把真实扫描调用藏到无法隔离的全局状态中。

## 可用状态规则

在 `apps.files` 提供统一的可用状态集合或判断函数：

- 可预览、下载、复用：`CLEAN`、`SKIPPED`。
- 禁止访问或复用：`PENDING`、`FAILED`、`INFECTED`。

所有查询条件、视图判断、序列化器 queryset、来源图片继承、任务附件读取和导出前校验都使用该规则。访问仍必须先通过现有的员工、权限、客户数据范围、关联关系和路径安全检查。

## 前端行为

- 询盘附件和其他文件状态为 `SKIPPED` 时显示“内部上传，未扫描”，不显示“待处理”。
- `SKIPPED` 文件按照后端返回的可用状态正常预览、下载或复用。
- 询盘产品图片上传失败提示不再出现重复句号。
- 浏览器仍保留失败时的待上传文件，成功绑定后才清除本地待上传状态。

## 验证计划

后端测试至少覆盖：

1. 开关关闭时通用图片、文档、联系人导入、询盘附件/沟通图、报价文件、样品文件等入口不调用扫描，文件落盘并标记 `SKIPPED`。
2. 开关开启时现有扫描成功、感染和扫描不可用路径保持原语义。
3. 非法扩展名、错误签名、空文件、超限文件、越权、缺少 ETag、非草稿状态和事务失败仍拒绝并清理临时文件。
4. `SKIPPED` 文件可在原有权限范围内预览、下载和跨模块复用；其他状态继续被拒绝。
5. 现有 BOM `SKIPPED` 行为不回归。

执行项目规定的 Django check、迁移漂移检查、相关后端测试和 OpenAPI 校验；前端执行类型检查、测试和构建。

## 风险与边界

关闭扫描会让内部账号上传的文件进入业务文件库而不经过恶意内容检测。`SKIPPED` 状态和配置开关会保留这一事实，便于审计和重新开启。该策略依赖“仅可信内部人员和网络”的业务前提；如果以后开放外部上传、客户自助上传或公网访问，必须先把开关改为 `true` 并恢复 ClamAV 健康检查。
