## 按哪条要求改了什么

| 已确认要求 | 修改前 | 本页修改后 |
|---|---|---|
| 无勾选，填数办理 | 旧外发多来源与分配方式 | 正整数纳入；空白/0跳过；全空、负数、小数、超量用ERP气泡拦截 |
| 任务→一个产品→对应BOM | 旧表单以排产进入 | 先选任务与单产品，自动关联唯一有效排产及喷塑工艺；不增加整模块读取权限 |
| 每部位一家加工厂 | 旧结构可把同部位分给多个厂 | 每行一家厂，不同部位可选不同厂；服务端拒绝同部位重复 |
| 原管材同表换算 | 旧原料发出路径 | 同一行显示支数、每根切割支数、原材料长度、扣根和扣米；必须整除，不能向上凑根 |
| 加工件、公共未喷塑按支 | 原发料结构偏向原料 | 两种来源只按支申请，无根米换算，无采购/原入库批次选择 |
| 最低报工约束 | 手工加工来源数量不能作为新依据 | 厂内来源采用当前必做工序最低累计报工，同时受净需求和实际投入约束；首次入库与直发共用数量 |
| 保存预留，发出扣库 | 旧外发创建不建立本次所需真实预留 | 保存独立待发单及预留；不生成出库流水，其他领料及外发扣除可用预留，低层扣库也保护 |
| 页面按确认图 | 设计原型示例数据 | 真实ERP外框、真实API与保存结果；成功留本页显示真实单号、刷新额度 |

三种来源按同部位共同外发额度校验，换一种来源或另开单不能重复占用。多个部位使用相同公共库存时，提交合计校验实物量。原料仍保留既有备料额度；未喷塑半成品与加工件用净需求上限。

## 设计规范与实际截图

- 1920×1080；表头44px，数据行40px，按钮/单行输入/日期/下拉32px；单层表格边框、5px圆角。
- 聚焦实际测得 `rgb(200, 78, 40)`，即主题色 `#c84e28`。
- 日期与下拉复用计划排产使用的Element Plus，保存复核复用 `AppWindowDialog`。
- 规格、厚度、切割长度、原料颜色、喷塑颜色独立列；原料换算不另起表。
- 1920视口无横向溢出。超量等填写问题只显示气泡；无权限、来源失效、保存结果不明确等阻断问题保留明确说明。

## 实际验证

前端27项测试、类型检查、生产构建通过；构建仅有现有项目的大包体提示。后端211项通过：数量/报工/删除相关107项、公共库存/既有领料外发78项、新管材API20项、低层入库预留3项、旧厂内入库互斥3项。迁移检查未发现遗漏。旧入库实测覆盖：无预留时行为正常；预留60支后跨计划最多入40支，超额拒绝，40支确认成功；连续直接记账不能重复使用同一报工额度。

浏览器实际选任务、产品、工厂并保存三来源各20支测试单。原料20支按每根10支换成2根、10.10米；半成品20支；厂内件20支。三单均为待发，数据库回查仅3张单，公共库存流水仍为测试准备时的4条；匹配原料仍90根/454.50米，未喷塑库存仍300支。保存未扣库存，重复检查未重复创建。

另验证空白、负数、小数、超量及非整根的气泡、来源切换、确认窗、主色聚焦和ERP日期。网络恢复通过同一请求编号回查；重复请求返回原单，来源改变则要求刷新后复核，避免重复预留。

证据：`qa/tube_revision_s3_20260929/browser-verification.json`、`demo_saved_orders.json`、`source_scope_after.json`，以及对应测试文件。独立复核已覆盖权限、幂等、共享库存锁、跨来源额度与入库预留；发现项已修正后重验。
