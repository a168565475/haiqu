## 页面细节与业务展示变化

### 已结束详情

顶部关联生产信息为两行、六列对齐，保留任务单、订单、排产、产品、颜色、计划日期、建单人。订单量标为“当前订单量”，避免误以为所有顶部关联资料都是历史冻结值。

回货资料为两行、四列对齐，保留实际发出日期、经办人、发出来源位置、入库状态、收货日期、入库经办人、入库仓库和凭证号。

原单全部部位保留，在同一个表内显示实发（支）、实收（支）、差额（支）、差额原因、入库库区。来源分别为原材料、未喷塑半成品、未入库半成品。每个部位显示本单对应的一个加工厂，材料属性和颜色各占一列。

原材料为 17 列，基础列宽合计 1550px；另两来源为 13 列。原材料额外显示切割支数（支/根）、原材料长度（米/根）、发出扣根、发出扣米。扣根与扣米是发出时的历史记录，不在已结束页根据当前 BOM 再换算，不另起换算表。另两来源直接按支显示。

底部显示实发、实收、差额，以及“查看入库凭证”。表格下仅保留原单备注、入库备注，没有恢复之前取消的规则说明或统计区块。

### 入库凭证窗口

只读窗口展示凭证号、原外发单、任务单、材料来源、收货日期、确认时间、经办人、入库仓库，以及全部部位的最终结果。使用相同的明细列，所有 0 行仍保留。

窗口没有确认入库、补登记、退回、重新加工、结清或修改数量按钮。关闭窗口返回原详情，不办理库存操作。

### 全回、少回与整单 0

“已结束”表示本单一次回货登记已经结束，不表示全部收齐。少回行显示差额和既有原因；实收 0 的部位显示“未入库”，不显示不存在的存放位置。整单实收 0 显示“未新增库存／无实收，无需仓库”，仍保留凭证与所有部位。

这只是正确显示已经确认的 D3 结果，不新增少回处理流程，也不恢复额度。后续是否另建金工计划由用户自行安排。

### 读取异常

包括加载中、凭证缺失、原单历史明细缺失、读取失败、无权限和单据不存在。没有读到原单时不提前显示固定单号、来源和已结束状态；数量显示“—”，不会把未知数据填成 0。原单历史字段缺失显示“—”，不从当前 BOM 补算。

凭证不完整或读取失败时不允许打开伪造的完整凭证。正式实现须按稳定原单明细 ID 对应凭证，而不是按材料名称或数组顺序对应。

## 确认后开发边界

确认本页后，仅在现有隔离 S3 代码中接入新管材已结束详情及只读凭证，按本稿开发，再提供实际页面截图与验证报告。

1. 读取已经存在的最终回货凭证。优先复用已存在的只读回货预览接口及字段，在前端按 `order_line_id` 对应原单明细。若现有字段不能满足已确认展示，只能补充必要的只读字段，不修改库存服务。
2. 已结束页使用最终凭证及原单历史记录，不查询动态最低报工、不重新套用当前 BOM 或公共库存余额来解释历史。
3. 保留现有查看、回货和加工范围权限；检查实际路由与接口是否一致，不借本页增加角色授权。
4. 不修改发出、回货数量规则，不修改公共库存、采购批次、报工额度、工序、加工厂分配或库存流水。
5. 不接入统一列表，不转换旧历史，不删除旧补登记代码，不启用主 ERP；这些仍按各自后续批准步骤处理。

事实限制：现有完成后的只读预览不会再逐行执行发出时的库存凭证核对，因此本页不能声称“查看时重新核对了扣根扣米”。这里显示既有历史记录。部分顶部任务、订单与经办人资料来自当前关联记录；回货数量与差额依最终凭证，不宣称整张页所有字段都已冻结。
