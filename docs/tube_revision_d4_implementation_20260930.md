## 真实库存与单据试跑

全部写入均在独立数据库 `tube_s3_base`，前向迁移前保存了独立数据库备份。三个已有待发单各发20支，随后另建待发20支单取消，再创建一张新的待发20支单。

| 场景 | 修改前 | 试跑后的真实结果 |
| --- | --- | --- |
| 原材料20支 | 90根／454.50米 | 88根／444.40米，实际扣2根／10.10米 |
| 公共未喷塑半成品20支 | 320支 | 300支，实际扣20支 |
| 未入库半成品20支 | 首次已入20、直发0、预留20、还可首次处理60 | 首次已入20、直发20、预留0、还可首次处理60，不再扣原料，不增加入库流水 |
| 待发取消 | 待发单预留20支 | 原单变已取消且明细保留，库存没有增加／扣减 |
| 取消后重建 | 已取消原单 | 带来源打开新建页，填数／选厂／填新日期后保存，直接进入新待发详情 |

新增库存流水恰好2条：原材料一次、公共半成品一次；原单明细与换算快照未被编辑，既有金工入库笔数保持1笔，另一实物身份的原材料余额完全不变。审计新增6条，对应三次发出、测试单创建、取消、重建。

公共半成品场景实际由服务完成发出后，中断浏览器回包并临时阻断结果查询；刷新后保留原请求，恢复查询成功后显示加工中。三来源又按相同请求编号重试，仍只有原两条库存流水，库存数不重复扣。新重建的20支单最终保留待发，后续验收可继续使用，没有删记录或反向恢复库存。
