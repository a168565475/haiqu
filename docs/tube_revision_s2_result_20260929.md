## 修改前后

| 对应要求 | 修改前 | S2隔离实现 |
| --- | --- | --- |
| 同一部位取各工序最低完成量 | 旧金工来源依赖手工完成数，厂内入库可抬高该数 | 新统一核算按当前适用已批准工价方案，用稳定工序身份累计有效报工，再取最低支数；不修改旧手工字段 |
| 订单产品多个计划不能重复使用额度 | 库存入库、来源交接与报工缺少共同依据 | 库存额度跨同一订单产品及稳定BOM部位汇总，首次入库、直接交接、有效预留共同占用；原有工资和逐计划进度口径保留 |
| 报工少于已处理数量不能保存 | 报工改删主要保护装配成品 | 增加金工累计数量保护；降低报工或变更必需工序造成不足时，报工/工资/方案日期/审批事件同事务回滚 |
| 只变价格不改变既有产量 | WorkItem已有稳定身份 | 沿用该身份跨价格版本累计；新增工序从零开始，不重算历史工资、单价和金额 |
| 新工序不能被旧“计划已完成”锁住 | 完成状态可使新增工序无法报工 | 当前适用方案新增未完成工序时复核并重开相应计划；未来版生效后读取入口允许继续报工，GET不写状态，实际报工事务再更新 |
| 实领投入真实且不选批次 | 已有公共出库流水 | 核对当前BOM关联原料、支/根/米转换和真实公共出库凭证；不查采购批次，不以公共库存当前余额恢复额度 |
| 同时操作不能超额 | 各入口锁范围不统一 | 提供同产品来源、排产、订单的统一事务锁与提交前版本复核；S3新入库/直发写入必须同事务使用该入口 |

示例：工序100/200支，已入40、已直发20、待发预留10，剩余30支。预留转实交后总占用不再加一次；取消未发预留才释放对应额度。已经领走的半成品不恢复首次加工额度。

历史豁免仅识别已经存在的`OriginalHandoffPublicTransition`真实接续凭证：该部分不要求补造新报工，仍占原订单/投入边界，不增加新处理额度。此步没有转换旧单。

## 后续接入约定

S3的入库/新预留应在同一事务中调用`assert_tube_quantity_available`，传入预览revision，并实际记录首次入库或有效预留；不能校验后脱离事务再写。预留转交接、取消也须先取得同产品锁。已批准未来方案也会复核本次拟占用，防止审批时零占用、生效前新增占用后失去工序依据。

旧`MetalProcessingSource.completed_pieces`仍受旧表约束，S2没有借入库抬高它。S3接入新写路径时必须处理这项既有约束，不能直接复用旧手工完成入口；主系统迁移及旧功能停用仍按S7/S8执行。此次仅交付数量基础与报工保护，不把三个新发出入口或一次回货声明为已完成。
