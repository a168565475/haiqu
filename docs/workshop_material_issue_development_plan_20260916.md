# 生产领料开发方案 V1

日期：2026-09-16。执行方式：连续开发。新增入口：**生产车间 → 生产领料**。

本轮交付开发方案及验收清单；尚未开发正式业务代码，未迁移数据库、写入库存或执行正式页面验收。用户已明确连续开发方式，执行阶段不再逐页重复询问是否继续。

## 1. 交付目标与范围

实现“选择生产订单及产品 → 按 BOM 分类申请原料或已回库半成品 → 提交仓库审核 → 整单确认出库 → 查询订单采购与领用”的真实业务链路。

必须同时交付前端页面、真实 API、权限、数据模型与前向迁移、库存事务、订单额度校验、专项测试和1920×1080视觉验收。构建成功、静态截图相似或 Mock 页面通过，都不能代替完整完成。

本期保留已确认的11个原型场景。新增和修改使用页面；“退回修改”使用统一弹窗。库存详情复用“仓库管理 → 材料库存”的真实入口，增加订单采购与订单领用查询，不平行创建另一套材料仓库。

本期不包含每日报工、工价工资、自动开工、成品入库、超领审批、退料、领料冲销、已出库删除、采购批次分配、成本核算。它们不能作为领料已完成的替代品或顺带开发。

## 5. 业务规则和状态

### 5.1 订单需求与公共库存

原材料按生产订单汇总需求，保留所选产品/BOM归属用于追溯。切换产品、车间、领料人或另开单都不能重置整单材料额度。不能因为选择了某一产品，擅自增加一个更小的产品独立上限。

原材料：

`订单剩余可领 = 已确定订单材料需求 - 厂内已确认领料 - 委外已确认发料`

`本次可领上限 = min(订单剩余可领, 合格公共可用库存)`

`确认后订单剩余可领 = 确认前订单剩余可领 - 本次确认量`

采购归属不限定领用订单；不选择采购单、入库批次或出库来源，不偷偷增加FIFO或采购专料预留。不同材料ID、颜色规格、单位、品质不能仅因名称相同合并。

BOM用量必须按分区解释：单位用量乘产品订单数量一次，整单用量不再乘；管材根数、米数、千克及损耗采购量不能相互替代。数量映射未确定的材料阻止提交/审核并说明原因，不把空值、公式文本或解析失败转换为0。

半成品：按“任务产品＋稳定部件标识＋完成工艺＋颜色＋套单位＋合格状态”匹配当前产品需求。保留原型当前订单产品的可领范围；是否允许跨生产订单半成品互领，此前未明确，本期不静默扩展。领取半成品只扣半成品余额及对应半成品需求，不再次扣原材料和原材料额度。BOM裁片记录本身不是库存。

### 5.2 状态转换

| 当前状态 | 允许操作 | 结果与库存 |
|---|---|---|
| DRAFT 草稿 | 修改、保存、提交 | 保存不扣库存；提交成功转PENDING_REVIEW |
| PENDING_REVIEW 待仓库审核 | 查看、刷新校验、退回、审核出库 | 退回原因必填；审核成功整单转ISSUED并扣一次 |
| RETURNED 已退回 | 查看、修改、重新提交 | 原因和历次审核记录保留；修改/重提均不扣库存 |
| ISSUED 已出库 | 查看历史及关联查询 | 不开放改数量、换订单、删除、撤销 |

库存不足和超额度是待审核单的校验结果，不新增长期业务状态。草稿和待审不预占库存/额度；仓库确认必须重新读取并校验。失败不自动缩小申请量，也不出库其他正常行。

同一订单允许多张领料单，一张单本期整单确认一次。计划分批与领料分次是不同概念。本方案按已确认状态图落实整单审核，不新增部分审核操作。

领料时间与系统审核时间分开存储；原型填写的业务时间不能自动冒充数据库写入时间。实际领料人与登录制单/审核者分开记录。保存草稿可缺业务必填项；提交时字段完整、至少一项且数量合法。

## 7. 后端职责与数据结构建议

业务单据建议新增`apps/material_issues/`，沿用Model、Serializer、Service、Selector、ViewSet分层。公共库存与流水属于`apps/inventory/`，领料单不得私有化库存余额；订单额度服务供领料和委外共同调用。

以下为拟定模型，不是已创建表，也不是可直接执行的迁移：

| 对象 | 关键字段与约束 |
|---|---|
| MaterialIssue | UUID、唯一单号、production_task、product_line、recipient_workshop_employee、workshop、issue_at、remark、status、version、created/updated/submitted/issued人员和时间、client_request_id；产品必须属于任务单 |
| MaterialIssueLine | 单据、行号、类型RAW/SEMI、稳定库存物料ID、需求ID、BOM版本/行/部件关联、名称规格颜色单位快照、申请量；同单同需求/库存身份合并或拒绝重复，不允许重复行绕额度 |
| MaterialIssueAuditEvent | 动作、单据版本、操作者、时间、原因、变更快照；追加历史，重提不覆盖退回事件 |
| OrderMaterialRequirement | 任务单＋标准物料身份＋库存单位唯一，需求量、已确认厂内/委外量或其可验证汇总、需求版本；不得把BOM版本加入额度唯一键以重置额度 |
| RequirementContribution | 需求对应产品/BOM来源及换算依据；同订单多产品同料合并时仍保留追溯 |
| StockItem/物料映射 | 稳定原料主数据引用、颜色规格及标准单位；从真实主数据ID映射，老快照文字只用于人工核对，不自动同名归并 |
| StockBalance | 库存身份/物理范围/品质的唯一余额，精确Decimal、版本、非负约束；首次无余额并发通过唯一键和确定父锁处理 |
| StockMovement | 不可变入/出流水、正数量和方向、来源业务单/行、物料与单位、前后余额、操作者时间；来源＋动作唯一，防重复记账 |
| 半成品需求与库存身份 | 复用委外设计中的稳定部件/工艺身份；合格余额独立于原料；若尚未实现，作为本次接入前置补齐，不直接复用成品仓模型 |

金额与计件工价不进入领料单。原材料使用Decimal(18,4)或库存既有精度，接口传十进制字符串；计数单位按单位配置校验，半成品套数为正整数。不能先四舍五入超领数量再放行。

关联采用PROTECT及归属校验；申请行的RAW/SEMI引用必须恰好一种。已出库单头、行、数量快照及出库事件不能再改写。数据库兜底包括唯一单号、幂等键、事件唯一、状态枚举、非负余额和正数量；跨表规则必须由统一事务入口保护，必要时增加数据库约束触发器，不能只靠前端校验。

## 8. 公共库存与旧数据衔接

1. 建立物料身份映射报告：采购入库、手工入库、BOM需求、委外用料分别能否关联同一个稳定库存ID；名称相同不能作为匹配成功依据。
2. 为可核实的已品质确认入库生成一次性入账映射/期初流水，源行唯一；支持dry-run和对账。不得把已存在出库再忽略一次，也不得重复导入旧入库。
3. 品质确认、手工入库、领料出库、委外发料统一更新余额/流水。采购退货若已从accepted_quantity排除，不能再扣第二次。已确认入库事实保留不变。
4. 旧材料列表改为净余额查询；订单采购统计仍来自采购明细及真实入库，不能按每次收货重复累加采购数量。
5. 委外材料发出也调用同一订单材料额度服务；旧委外方案“只检查批次库存”的规则已被用户后续共同额度/公共使用要求覆盖。
6. 委外分批回货只有确认合格后增加相应半成品余额；不能因外发单写成完成、填写回货草稿或BOM存在裁片就生成库存。
7. 原料库存不得静默汇总不同单位或不良品；半成品不得把不同部件、颜色、已完成工艺合成一项。

**物理库区边界必须在执行预检核实**：公共使用取消的是采购订单/批次专属关系，不等于实物没有仓库位置。若部署只有一个可发库区，可从真实仓库配置取得；若存在多个可发库区，须核对既有仓库操作范围/出库规则能否唯一确定实发库区。无法确定时只阻断相关确认，不擅自FIFO，也不在原型塞入未经确认的来源分配界面。不得一边仅扣全局余额，一边继续把各库区累计入库量标为可用库存。

对缺失原料ID、单位换算、历史期初或仓库归属的记录，输出具体异常清单；保持未解析状态，不编造ID、不默认0库存、不自动改主数据。执行代码可继续完成已明确部分，真实数据修复必须按项目授权规则处理。

## 9. 事务、并发和重试

建议所有入库、委外、领料使用同一锁顺序协议，编码前与既有采购/仓库锁链核对。领料确认参考顺序：业务幂等键 → 生产任务/产品 → 本单及需求 → 按稳定ID排序的库区/库存余额 → 事件写入。跨模块不得反向取锁；首次余额/需求行不存在时先锁稳定父对象再创建，不能仅锁空查询。

单个`transaction.atomic`完成：

1. 验证登录、有效员工、审核权限和业务数据范围；检查幂等请求是否已有同内容结果。
2. 锁单据并检查PENDING_REVIEW、If-Match和申请版本。相同请求不同内容返回冲突。
3. 锁后重新检查任务/BOM有效性、所属产品、稳定物料、数量和单位、整单相同材料汇总。
4. 同时核验订单剩余额度与合格净库存。厂内/委外使用同一需求锁；跨订单领取同一材料使用同一库存锁。
5. 所有行通过后一次写出库事实、库存流水、余额、订单累计和审核记录，并将单据改为ISSUED、version递增。
6. 任意一行失败整笔回滚，返回行级原因和最新库存/额度；不可返回成功后再异步扣库存。

已处理请求重试返回原出库结果，不受已经变化的旧ETag影响而再次处理；新的不同请求对已出库单返回已处理状态，不新增流水。审核与退回并发只有一种动作成功；等待中的另一方收到状态/版本冲突。

BOM修订不能使需求低于已确认用量，也不能通过新版本创建一套空额度。待审单来源版本变化时明确要求刷新/重新提交，保留旧申请及历史版本；禁止静默换BOM。

## 10. API契约建议

沿用`/api/v1/`、项目DataResponse/Pagination、Session＋CSRF、If-Match。下列是新增接口建议，开发前纳入OpenAPI，不冒充已有接口。

| 方法与路径 | 职责 |
|---|---|
| GET `/material-issues/` | 后端搜索、状态/车间/人员筛选、排序、分页 |
| GET `/material-issues/options/` | 有权限的生产订单、车间和领料人候选，不返回无关全量主数据 |
| GET `/material-issues/eligible-products/?production_task_id=` | 当前订单内产品行 |
| GET `/material-issues/requirements/?production_task_id=&product_line_id=` | 分区、需求、已领、委外已发、库存、可领及来源版本 |
| POST `/material-issues/` | 创建草稿，client_request_id防重复 |
| GET/PATCH `/material-issues/{id}/` | 查询含审核历史；更新草稿/退回单，If-Match |
| POST `/material-issues/{id}/submit/` | 完整校验并提交，不预占 |
| POST `/material-issues/{id}/return/` | 原因必填，版本校验、记录审核事件 |
| POST `/material-issues/{id}/preview-issue/` | 可选复核接口，不写库存；若使用GET需保证只读 |
| POST `/material-issues/{id}/confirm-issue/` | 幂等整单出库；前端不得直接传扣库结果 |
| GET `/material-inventory/{stock_item_id}/summary/` | 当前、可用、累计采购/入库/已发 |
| GET `/material-inventory/{stock_item_id}/order-purchases/` | 按采购归属订单汇总及分页 |
| GET `/material-inventory/{stock_item_id}/order-issues/` | 按领用订单汇总及确认发料明细 |

复用现有物料详情接口时优先扩展而非重复命名。查询需求返回`requirement_id/stock_item_id/line_type/section_code/unit/required_quantity/internal_issued_quantity/outsourcing_issued_quantity/order_remaining/available_stock/max_issue_quantity/bom_version/validation_errors`。

前端只提交真实关联ID、申请数量、业务时间及备注；需求、库存、累计数、单据状态、审核者都由后端计算。相同物料跨分类重复选择先合并后校验。错误返回稳定code、中文说明、line_id、最新可用量和可重试指示。

主要错误：REQUIREMENT_UNRESOLVED、UNIT_MISMATCH、STOCK_INSUFFICIENT、ORDER_ALLOWANCE_EXCEEDED、SOURCE_CHANGED、INVALID_STATE、VERSION_CONFLICT、PERMISSION_DENIED。缺关联或换算不是“库存为0”。
