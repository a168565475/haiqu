## 4. 字段契约

### 4.1 产品表单

| 界面字段 | API 字段 | 规则 |
| --- | --- | --- |
| 品号 | `product_number` | 必填，最长 100，唯一；新增和编辑均可输入 |
| 类型 | `product_type` | 固定 FINISHED/成品，后端只读；不让用户选择材料 |
| 产品编码 | `product_code` | 可空，最长 100，去首尾空格；非空时唯一 |
| 品名 | `product_name` | 必填，最长 200 |
| 类别 | `category` | 必填 UUID，只能选有效成品类别 |
| 货号 | `product_item` | 必填 UUID，按类别过滤；显示 `item_number` |
| 规格 | `specification` | 必填，最长 300；不把规格强制解析为尺寸数字 |
| 单位 | `unit` | 必填 UUID，来自有效生产单位 |
| 仓库号 | `warehouse_number` | 可空，最长 100；普通文本输入 |
| 仓库名称 | `warehouse_name` | 可空，最长 150；普通文本输入 |
| 规模 | `scale` | CUSTOM/定制、REGULAR/常规；沿用当前默认 CUSTOM |
| 状态 | `status` | ACTIVE/正常、INACTIVE/废弃；沿用当前默认 ACTIVE |

分组顺序固定：基本识别 → 产品归类 → 存放与属性。产品编码提示、货号联动说明以及编辑规格焦点样式对应原型保留。

类别与货号的历史不匹配：编辑加载时不触发清空；两个关联都没变时允许保留原有关系。用户修改类别或货号后必须重新满足所属关系。已停用的原关联可只读回显，不能变成新记录可选项。其他字段验证遵守当前 Serializer，不扩大规则。

## 5. 列表、查询与排序契约

### 5.1 列与操作

产品列顺序：品号、产品编码、类别、品名、规格、单位、货号、仓库、规模、状态、操作。没有勾选列。仓库按原型同一行组合显示；空值使用统一占位。

原料列顺序：勾选、品号、类型、类别、品名、规格、单位、颜色、仓库、包材辅料、箱子形状、操作。仓库上下两行，类型和类别均为实心标签。非包材的两个包装列显示“—”。勾选只管理当前页选择和已选数量，不暗示存在批量业务；筛选、翻页、刷新导致数据替换时清空选择。

列表必须从登录后的真实侧栏入口进入，菜单激活正确。新增按钮是页面级操作，刷新在工具栏右侧。产品状态仍用淡色状态标签，不套用原料类型的实心蓝色。

### 5.2 查询 API

| 模块 | 地址 | 查询参数 |
| --- | --- | --- |
| 产品 | `GET /api/v1/products/` | `page,page_size,q,category_id,scale,status,ordering` |
| 原料 | `GET /api/v1/raw-materials/` | `page,page_size,q,item_type,category_id,warehouse_number,ordering` |

默认 page=1、page_size=50；总数、页数与是否有下一页从服务端结果计算，不能写死 126、368 或 3/8 页。搜索回车、筛选变化、排序变化都重置 page=1；重置清空全部筛选并恢复默认品号升序。刷新保留当前有效筛选和排序。分页变更只调整分页请求。

保留请求序号/取消机制，后发请求先返回时不能被旧结果覆盖。加载中保持布局；首次加载无总数显示占位，刷新时可保留上次已知总数；失败提示不能伪装“无数据”。列表获取成功但选项失败时，分别管理状态，避免屏蔽可用列表。

## 6. 保存、权限与异常

接口继续使用现有 GET 详情、GET options、POST 创建、PATCH 更新，不新增虚假的“保存成功”接口。表单成功返回之前不关闭抽屉。

编辑打开流程：点击真实行 → GET `{id}/` → 暂停联动 → 装载资料及 ETag → 恢复联动 → 展示可编辑表单。读取失败显示可重试状态，不能沿用上一条记录。连续快速点击两条记录时只展示最后一次请求。

保存流程：验证 → 构造白名单 payload → saving 防重 → POST/PATCH → 成功消息 → 关闭 → 按当前筛选刷新。保存成功而刷新失败要明确区分“已保存，列表刷新失败”，不能再次 POST。

| 情况 | 行为 |
| --- | --- |
| 必填、超长、无效枚举、重复编号/编码 | 对应字段提示，保留输入，聚焦首个错误；长错误允许内容区滚动 |
| 无创建权限 | 隐藏新增；服务端拒绝 POST |
| 无修改权限 | 隐藏编辑；服务端拒绝 PATCH |
| 无查看权限、未登录、员工失效 | 沿用现有路由和页面权限保护，不能请求后再泄露数据 |
| 412 版本冲突 | 明确本次未保存；保留输入，允许用户主动重新读取最新数据；不得自动覆盖重试 |
| 428 缺版本 | 保留输入，重新取得版本后由用户再次确认保存 |
| 网络失败、服务端错误 | 保留输入，退出 saving，可重试；不得关闭、清空或弹成功 |

| 未修改而取消/关闭 | 直接返回列表，保留列表状态 |
| 已修改而取消/关闭/Esc/切换模块 | 放弃确认；继续编辑保持输入；确认放弃后关闭并归还焦点 |
| 保存中关闭 | 防止重复提交和中途丢失；明确禁用对应操作，错误后恢复 |

权限代码：`products.view_productinformation`、`products.add_productinformation`、`products.change_productinformation`；原料对应 `view_rawmaterialinformation/add_rawmaterialinformation/change_rawmaterialinformation`。继续保留 IsAuthenticated、HasActiveEmployee、BusinessActionPermission，以及 options 的现有权限组合。

412 重新读取前应在内存中保留本地草稿用于对照；不要把真实业务内容写入 localStorage、日志或文档。若用户主动选“重新读取”，以最新服务器版本重新初始化，但不偷偷自动再次保存。
