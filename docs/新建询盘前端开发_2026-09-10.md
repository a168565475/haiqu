# 新建询盘页面开发与验收

用户确认后按 Figma 文件 `czPqlJ7fXYn5cq4cbQyTFm` 的 `1597:14182`（INQ-V3-03 新建询盘 / 1920）开发。采用现有 Vue 3、Element Plus 和 CRM 设计变量，不新增依赖，不改模型或执行迁移。

## 实现

- 新建与继续编辑草稿共用 `InquiryEditorView.vue`，接入 230px 侧栏、64px 顶栏及暖色主题。左侧客户与来源、产品明细、备注；右侧贸易与预算、附件和实时提交检查。
- 页面自身按可用视口高度滚动；产品表格和附件列表支持内部滚动，长内容不会被公共布局截断。
- 客户使用服务端搜索，当前选择和来自客户详情的预选客户单独加载，避免受前 100 条限制。联系人按客户加载所有分页；切换客户即清除旧联系人，并丢弃过期请求结果。邮箱按接口脱敏显示。
- 询盘来源、语言、币种、贸易条款读取已有配置接口。接收时间使用日期对象转 ISO 时间，避免把本地时间错误标成 UTC。
- 产品支持新增与删除，最多 200 行。行号不会因删除后新增而与旧记录冲突；产品数量、目标价用字符串和整数缩放计算，保留 4 位输入小数及乘积的 8 位精度。不同币种、不同数量单位分别合计。
- 预估金额按目标单价乘数量实时计算，缺价显示“待补齐”；客户预算单独填写并保留零值。目标价不自动创建报价。
- 完全空白的初始产品行可不随草稿保存；部分填写的行必须补齐必要字段。正式提交必须有客户、有效联系人、来源、有效产品及接收时间。当前登录员工自动负责；已提交询盘进入编辑地址时只读。
- 需求备注保留换行；已有富文本在未修改时原样保存，修改后的纯文本进行 HTML 转义，避免误删尖括号内容。
- 附件选择后排队，保存或提交时先保存草稿，再顺序上传和扫描。支持 PDF、XLSX、JPG、JPEG、PNG，单文件 10 MB，每询盘最多 100 个附件。未上传的文件可移除；已保存附件显示服务端状态。
- 保存、上传、提交使用单一操作锁，避免重复点击。保存结果不明确时锁定表单，以相同内容和请求标识重试；附件失败保留草稿和队列，不重复创建询盘。版本冲突保留填写内容；未保存离开和关闭窗口会提示。
- 新增仅用于草稿附件的上传接口，沿用权限、客户数据范围、ETag、事务和审计。检查文件签名及 XLSX 容器，复用真实 ClamAV 扫描；失败不关联文件，数据库回滚时清理本次文件。重复上传标识校验内容哈希。

## 手工使用

进入 `http://localhost:8080/inquiries`，点击“新建询盘”。选择客户，填写产品，可先保存草稿；补齐联系人和来源后正式提交。附件在保存时上传，失败可再次保存重试。提交会产生真实业务记录，请按实际业务需要操作。继续使用项目现有 Docker 和 Node 环境，无需安装额外依赖。
