### 3.3 D-01：BOM 归属决策，已选择 B

已向用户提出的问题：同款产品深灰 2,400 件、米白 1,600 件，是否按确认原型共用一份 4,000 件 BOM？当前代码按两个产品颜色明细分别建版。这涉及模型、采购引用和历史数据，不只是页面排版。

**有效决策 B：保持每色独立 BOM。**
- 后端版本主键及范围继续为产品明细；创建一张任务时仍可有多个颜色明细。
- 两份 BOM 分别计算 2,400 和 1,600；详情必须展示两份最新 BOM，开工检查两份都已确认。
- 采购来源按所选颜色 BOM 独立生成；不能把另一颜色的物料或数量合入当前采购来源。
- 当前模型、版本键和采购快照已经按 product_line 工作，因此不新增 BOM 分组模型，也不生成无业务价值的迁移。
- 该选择会改变当前确认稿的 BOM 选择、数量摘要与版本展示；代码必须明确显示颜色与单色数量，不能继续展示合计一份 BOM 的示例语义。

决策记录：用户于 2026-09-11 明确回复“B”。原 A 分组方案不再实施；不得新增范围 ID、不得自动合并历史 BOM。

## 4. 视觉冻结与逐页实施规格

### 4.1 统一验收规则

- 正式视口 1920×1080，浏览器缩放 100%，DPR=1，字体加载完成后截图。
- 顶栏 64、侧栏 230；页面内容及各区实际坐标取当前节点。左右边距约 28，不给整个界面套 transform:scale。
- Noto Sans SC、Noto Serif SC、Inter、HiTree 使用的 Instrument Serif，以节点实际绑定为准。先确认项目字体文件及授权来源，不能悄悄降级字体造成布局改变。
- 本原型存在 41.34 高按钮、52.82 高统计条等实测值；DESIGN 的通用默认不能强行覆盖明确节点数值。
- 提取页面 token（颜色、边框、字号、阴影、间距、列宽）与字段配置到本模块；复用 crm tokens/mixins。页面样式用 scoped SCSS，禁止为两模块重写全局 main.css。
- 以 Figma 当前截图和 recheck/after_*.png 为对比输入。refined 中较早的 1672×941 图片仅追溯，不作为二次缩放后的编码坐标。
- 原型图标用现有 IconPark 对应资源；产品图从真实受权限控制的文件地址读取，缺图采用现有缺图状态。
- 页面无横向溢出；宽表在表格容器内横滚。长文字、0、空值、长编号和图片失败都不能破坏布局。
- 只在测试数据库放可重复的基准样本；不将 128、86、4,000、17 或类别行数硬编码进业务页面。
- 在测试中量测主要区块的 x/y/宽/高、表头和行高。建议初始几何容差 2px，字体抗锯齿单独观察；这是验收方法建议，不是允许主观放宽明显差异。
- 每页都输出同视口“Figma 基准 / 实现截图 / 叠图或差异图”和核对结论；差异未修复不能标通过。动态业务字段只在必要时屏蔽具体文本，不能屏蔽整个卡片和按钮。

2. 扩展 POST /production-tasks/create-from-sales-order/：
   - 新入口接收同一个销售订单交付批次下的多行选择，计划契约为 delivery_batch_id + lines[]；每行明确 delivery_batch_line_id、product_color_id（有来源时锁定）、quantity 及本任务要求。
   - 兼容原有单 delivery_batch_line_id + quantity 调用；新旧参数不能同时使用。
   - 锁定实际来源行，逐行核对订单状态、批次状态、产品/颜色/规格/单位、已分配与容差，再一次事务创建任务和全部子行；不能用多次单行接口拼成多个任务。
   - 任务归属一个销售订单，不自动混单；子行保留来源外键。若当前来源只能确定到批次行，则存真实可证明的关系，不补造颜色来源。
   - 新建草稿计划日期可空；如传入两日期仍须合法。提交时只检查业务输入，PMC 确认时检查计划完整性。
   - 前端防重复点击；后端在行锁下重新计量。若需要在网络中断后安全重试创建，增加一次性请求标识并返回同一结果，不用自动重发 POST。
3. 保留 PATCH /production-tasks/{id}/，扩展 serializer 支持精确字段更新，避免旧综合表单清空 followers、图片、批次和隐藏字段。
4. 来源、客户、销售产品及数量容差由上游锁定。PMC 专用入口只允许修改计划字段，服务端拒绝额外业务字段。
5. 更新涉及 BOM 时，先返回 BOM_SYNC_CONFIRMATION_REQUIRED 和具体影响，再按用户选择提交 bom_sync_mode、bom_sync_token、最新 If-Match。令牌有效期沿用 15 分钟；过期重新取影响，不能跳过确认。
6. SYNC 对已确认 BOM 建新草稿版，旧版保留；KEEP 保留旧版本和数量，详情展示差异，最终确认必须处理差异原因。保存任务不等于提交 PMC，不自动完成重审。

### 6.3 BOM 创建、计算与版本

- 保留 GET /boms/、/{id}/、/stats/、/options/ 和物料/维护选项接口。
- D-01 确认后冻结 create/preview/sync/verify 接口中的产品范围标识。A 增加范围 ID 并兼容历史 production_task_product_id；B 保留原参数。范围校验必须在后端完成。
- 扩展 POST /boms/preview-import/：返回原文件/工作表、各分区 line_count、白名单规范化预览行、产品身份校验、来源数量与差异。预览不创建正式 BOM；临时文件正常清理，不回传服务器路径。
- 保留 POST /boms/，creation_method=IMPORT/COPY/BLANK。上传错误、工作表缺失、身份不符、停用物料、无效单位分别返回可定位字段/行号；创建事务中重新解析并复核，不信任客户端预览结果。
- COPY 生成当前任务新版本，保留来源 BOM 及原因；已确认旧版不可被覆盖。空白方式保存草稿，不能缺必要物料信息直接确认。
- 保留 PATCH /boms/{id}/、POST /{id}/sync-order-quantity/、/{id}/verify/、/{id}/archive/。确认要求生产任务已确认、数量来源说明完整、物料合法；版本校验用服务端权威数值。
- 图片沿用现有受控上传、扫描与读取流程；失败可重选、不显示假上传成功，草稿临时图片与正式行绑定关系保持一致。
- 明确字段：BOM 当前生产数量、订单/任务最新数量、Excel 来源数量、生产批次数量及差额，均属于当前 BOM 范围。不得拿整张任务所有产品合计与单个产品的 BOM 对比。
- 界面使用“BOM 毛需求量”；不把它称为实际采购量，不引入库存、在途、MOQ 等净需求计算。

型材计算沿用当前服务中的 Decimal 规则并做回归：
- 总用量 = 该 BOM 生产数量 × 单件用量。
- 支数 = 四舍五入(总用量 ÷ 每支切件数 × 1.01)，不是擅自向上取整。
- 下料长度(米) = (长度毫米 × 每支切件数 + 50) ÷ 1000。
- 当前重量系数 0.464 及其他精度沿用代码，不凭原型重新定义。
- 长度/切件数缺失或切件数非正时按现有规则展示不可计算并提示，不能出现 Infinity/NaN。
- 包装样例“每箱4件、共4000件”对应1000箱、单耗0.25；生产数据由实际物料参数计算，不能为了匹配旧错误示例写成4000箱。

### 6.4 筛选、统计、导出与打印

- 所有列表查询都从 accessible selector 开始。搜索、日期、状态、类别、业务员参数白名单验证，非法日期/倒置范围返回 400。
- 日期选“截至某日”按 Asia/Shanghai 当日结束语义转换为次日零点的排他上界，避免漏掉当天晚间数据。
- 推荐统计定义：遵循当前非状态筛选和数据权限，分别返回各状态数量；点击状态条仅改变列表状态筛选。记录为实现契约并给用户可观察的一致结果，不从当前页推算。
- 导出新增只读接口或扩展现有能力：勾选记录优先，否则导出当前筛选全部；按钮/反馈明确数量和范围。支持当前页选中项，不暗中跨页全选。导出列固定白名单、敏感列遵循权限、CSV 防公式执行、中文编码正确，大量记录不能无提示截断。
- 未明确允许的敏感字段不导出，前端隐藏列不能替代后端字段权限。
- 打印沿用浏览器原生打印。打印纸型/方向以确认对话框为准；不额外采购 PDF 服务。打印成功反馈最多说“已打开打印窗口”，不能声称已物理打印。
- 实现 print 样式、页边距、重复表头、合理分页、备注和页码；屏幕 1920 画布不等于打印纸张。至少覆盖单页、多页、长中文和空分区。

## 7. 状态与权限矩阵

### 7.1 状态迁移

| 当前状态/触发 | 允许行为 | 结果与限制 |
|---|---|---|
| DRAFT 草稿 | 修改、保存、提交 PMC；可准备 BOM 草稿 | submit → PENDING_VALIDATION；不能确认 BOM 或开工 |
| PENDING_VALIDATION 待 PMC | PMC 计划确认或填写原因退回；可准备 BOM 草稿 | CONFIRM → READY；RETURN → DRAFT；PMC 不改业务来源及数量 |
| READY 已确认 | 确认适用 BOM；满足门禁接单开工 | start → IN_PRODUCTION；BOM 草稿/数量冲突未处理则不允许开工 |
| 待确认或已确认任务修改 | 保存、明确 SYNC/KEEP 影响 | 当前服务回到 DRAFT，之后再提交 PMC；不能跳过重审 |
| BOM 已确认后变更 | 新草稿版、重确认 | 旧版只读保留；不能以旧已确认版掩盖最新草稿版的开工门禁 |
| IN_PRODUCTION / PAUSED | 沿用已实现的生产事实与合法动作 | 不在本次新造停产/重排规则；保存不得抹去实际开工记录 |
| COMPLETED / CANCELLED | 查看、历史追溯和允许的打印 | 当前服务禁止修改；取消不删除上游需求或历史生产事实 |

必须验收原型的“修改后草稿→重新提交PMC→PMC重审→BOM重确认→待开工”全链路，状态不能仅靠前端切换文案。
