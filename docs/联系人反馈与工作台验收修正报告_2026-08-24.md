## 1. 联系人反馈完成情况

| 反馈项 | 原因与处理 | 验收结果 |
| --- | --- | --- |
| 勾选框、姓名列不固定 | 移除两列的 Element Plus 左固定配置；仅操作列右固定 | 通过，桌面、1440、窄屏均为 `leftFixedWidth = 0` |
| 联系方式全部显示 | 取消前端只截取两条联系方式的逻辑，按后端已脱敏值纵向展示全部方式 | 通过，邮箱、手机、电话均展示；未读取或显示原始联系方式 |
| 操作统一进入“更多” | 移除行内“查看”“编辑”，保留一个“更多”下拉；下拉含查看、编辑、任职历史、标记离职 | 通过；编辑和离职仍受真实权限、在职状态控制 |
| 表格响应式 | 允许表格内部横向滚动，页面容器不产生横向滚动 | 通过，1920、1440、768 宽度均验证 |

Figma 原始联系人表头高度为 44px，联系人行基础高度为 48px。联系人行的联系方式按内容自然增高，这是“全部显示”要求带来的有意差异；不再以截断信息换取固定行高。原型原有多个操作按钮，已按本轮明确反馈改为单一“更多”入口。

## 2. 工作台一致性矩阵

| 项目 | 原型 / 业务需求 | 真实数据库与接口 | 本轮验收与处理 | 状态 |
| --- | --- | --- | --- | --- |
| 当前用户、员工、角色权限 | 业务员、主管、无权限三种状态 | `auth_user`、Employee、角色及权限；`/api/auth/me/` | 实际账号进入三种状态，401 清空状态后回到登录页 | 通过 |
| 业务员工作台 | 指标卡、任务、风险客户、快捷操作 | `GET /api/v1/dashboard/me/`、任务、客户、沟通、询盘接口 | 保留真实接口；销售漏斗等无统计口径区域集中使用演示数据并标识 | 通过 |
| 主管工作台 | 团队指标、负载、绩效 | `GET /api/v1/dashboard/manager/` 及现有权限 | 主管真实权限进入主管视图 | 通过 |
| 任务流转 | 开始、完成和并发提示 | Task API、ETag、`If-Match` | 真实浏览器完成“开始 → 完成”流转；补齐 412/428 等错误文案 | 通过 |
| 沟通、询盘快捷新建 | 新建后真实留痕 | CustomerCommunication、Inquiry 及相应创建接口 | 真实浏览器创建成功，不使用前端假成功 | 通过 |
| 演示内容 | 销售漏斗、订单里程碑、团队绩效、SLA | 暂无对应真实统计口径 | 保留在 `workbenchDemoData.ts` 集中维护，并明确标识“演示数据” | 通过 |
| 导出日报、询盘分配、审批 | 尚未接入 | 无可用真实流程 | 保持不可用提示，不显示虚假完成 | 通过 |

## 6. 保留的验收数据与限制

- 依照“保留审计数据”的要求，真实浏览器验收留存：2 个 QA 用户、2 个 QA 员工、1 个 QA 客户、2 个 ETag 任务、2 条沟通记录、2 条询盘记录；均带 `WB-QA` 标识。
- 400、403、409、412、428、500、网络错误已由前端单元测试覆盖统一提示；401 已在真实浏览器中验证跳转登录。后端本轮未变更，因此不通过人为破坏生产接口来制造每一种错误码。
- 销售漏斗、订单里程碑、团队绩效、团队负载及 SLA 尚无真实统计 API，继续显示集中维护的演示数据并带醒目标识；这不是实际业务统计。
- 联系人联系方式仅渲染后端返回的脱敏字段，前端不持有原始联系方式。
