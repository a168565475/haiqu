# 询盘处理时限

用户确认：北京时间，08:30—12:00、13:30—17:30，每个工作日7.5小时；大小周交替，星期日固定休息，2026-09-05是休息星期六基准。首次回复4个工作小时，记录首次回复后，需求确认再计2个工作小时。

## 接入范围

- 正式提交询盘后启动首次回复计时；草稿不计时。
- 记录首次回复时结束前阶段，启动需求确认阶段；确认需求结束该阶段。
- 午休、下班、周日和双休周的周六均不累计。详情进度和列表剩余时长也扣除非工作时间。
- 新记录保存日历、目标分钟数和提醒阈值快照；规则更改不重算旧记录，负责人转交不重置截止时间。
- 原连续时间记录继续按原规则显示；不为历史询盘自动补建计时。
- 超时但尚未结束的阶段仍可正常完成并保留“超时完成”，或终止并保留历史。
- 列表、筛选和汇总按工作时间计算30分钟预警，并显示过期但尚未落库更新状态的记录。
- 询盘列表“处理时限”、详情“处理时限与进度”，以及“查看规则与记录”均使用中文说明。规则通过真实接口返回。

本次实现用户最终确认的计时规则。节假日及临时调休尚未提供，当前只按大小周常规排班，不能自动识别法定假期。等待客户暂停、通知发送、规则维护页面未在本次加入。

## 数据与部署

迁移 `inquiries.0008_inquiry_worktime_policy` 只新增 `INQUIRY_WORKTIME_202609` 启用策略，不修改询盘记录或其他模块。执行前已只读确认本地库没有询盘策略、没有当前计时记录。目标迁移计划只包含该项，不运行其他模块待执行迁移。

```powershell
docker compose exec -T backend python manage.py migrate inquiries 0008
```

若其他环境已有多个启用的询盘规则，需先明确选择优先级：现有服务按策略编码选择首项。本地当前是单规则。迁移逆向不删除可能已被计时记录引用的策略；如需停用须按业务配置停用并保留历史。
